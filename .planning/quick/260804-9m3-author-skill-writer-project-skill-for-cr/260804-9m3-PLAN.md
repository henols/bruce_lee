# Quick Task 260804-9m3 — `skill-writer` project skill

## Goal

A project skill that makes the next skill in this repo cheap to write correctly:
the frontmatter contract, the directory layout, progressive disclosure, the house
style the four existing skills already share, the project hard rules a new skill
must not break, and how registration actually happens.

## Why it is needed

Four skills exist and share a discoverable house style, but nothing writes that
style down. The registry has no credible skill-creation skill to install — the
only `skill-creator` match carries 10 installs — so authoring one locally is the
route.

Two facts discovered while scoping, both of which the skill must encode because
they are the easy things to get wrong:

1. The Project Skills table in `.claude/CLAUDE.md` sits inside
   `<!-- GSD:skills-start source:skills/ -->` / `<!-- GSD:skills-end -->` and is
   **generated** from the skills directories by `gsd-tools generate-claude-md`.
   Hand-editing it is wrong — the next regeneration silently discards the edit.
2. The table is currently stale: `find-skills` was installed into
   `.claude/skills/` but never made it into the table. Running the generator is
   therefore both the registration step for `skill-writer` and the fix for that
   drift.

## Tasks

### Task 1 — Author `.claude/skills/skill-writer/SKILL.md`

**files:** `.claude/skills/skill-writer/SKILL.md`

**action:** Write the skill in the repo's existing house style — terse and
imperative, concrete commands in fenced blocks, tables for contracts and
troubleshooting, worked examples over prose. Cover, in this order: the
frontmatter contract; where files go; how a skill earns its trigger; progressive
disclosure; house style; the project hard rules; registration via the generator;
and a validation checklist ending in a runnable check.

**verify:** `node -e` parse of the frontmatter confirms `name: skill-writer` and
that it equals the directory name; the file names all three hard rules and the
`generate-claude-md` registration route.

**done:** SKILL.md exists, frontmatter is valid, and every claim it makes about
this repo's layout is true of the four existing skills.

### Task 2 — Register the skill by regenerating the table

**files:** `.claude/CLAUDE.md`

**action:** Run `node .claude/gsd-core/bin/gsd-tools.cjs generate-claude-md`.
Confirm the diff touches only the region between the skills markers, and that it
adds both `skill-writer` and the previously-missing `find-skills`.

**verify:** `grep -c 'skill-writer' .claude/CLAUDE.md` is non-zero; the diff for
`.claude/CLAUDE.md` is confined to the `GSD:skills-*` block.

**done:** The table lists all six skills, and no other GSD-managed block moved.

## Out of scope

- Any change to the four existing skills. Their style is the reference, not the
  subject.
- A global `~/.claude/skills/` copy. Placement was decided as project-local so
  the skill can carry this repo's hard rules and its GSD registration step.
- Scripts under `.claude/skills/skill-writer/scripts/`. The skill is guidance
  plus one runnable check; it needs no module of its own.
