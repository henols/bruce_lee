## Emulator-safety rules for THIS task — read before running anything

The host VICE instance holds the developer's live work. It was verified `ECONNREFUSED`
at planning time and has died six times in one session (STATE.md, HOST INSTABILITY), so
treat reachability as a coin flip, never as a precondition.

- NEVER call `vice_disk_list`. Not to test the deny-list against a live server, not
  "just to check". The deny-list is proven by unit test, offline, before the network.
- The ONLY live `vice_*` call permitted anywhere in this task is `vice_ping`. Every
  other state-reading call — including `vice_registers_get` — PAUSES the emulator and
  does not resume it (STATE.md, pause-on-read finding), which would stall the
  developer's running machine. `vice_ping` was measured non-pausing (986,693 cycles/s
  while ping-polling); it is the one safe probe.
- `tools/list` is an MCP protocol call, not a `vice_*` tool. It does not touch the
  emulated machine and is safe.
- Nothing in this task may attach a disk, reset, step, resume, write memory, save a
  snapshot, or add a checkpoint.
- A dead endpoint costs ~50 s of reconnect backoff per command. Export
  `VICE_MCP_TIMEOUT_MS=5000` before any live probe so a refusal surfaces in seconds
  rather than looking like a hang.

## Coding idiom

`tools/*.mjs` in this repo carry heavy explanatory comments that say WHY, including
what went wrong before. Match that register — see `vice-pool.mjs`'s header block and
its "WHAT THIS DELIBERATELY DOES NOT DO" note for the target density. New code without
that commentary is not finished code here.

No new runtime dependencies, no new test framework. `node:test` and stdlib only.

  - Cross-process survival (THE load-bearing test, D-1): spawn `node tools/vice.mjs
    session acquire` as ONE child process; after it exits, spawn `node tools/vice.mjs
    session status` as a SECOND child process. The two children share only
    `VICE_POOL_DIR` and `VICE_SESSION_FILE` in env — nothing an `export` inside the
    first child could carry. `status` must report the same port and session id the
    first child leased. This proves a session cannot live in shell state.
  - Session lease survives its creator's exit: after the `session acquire` child has
    exited, the lease file for that port still exists on disk and its record decodes
    with `kind` equal to `"session"` and a parseable `expires_at`.
  - A second `acquire()` cannot take the leased port: with a 1-port registry already
    held by a live session lease, `acquire({dir, timeoutMs: 0})` rejects, and the error
    names that port. Session leases and programmatic leases share one lease namespace.
  - Session lease is NOT pid-reclaimable (D-2): write a session lease whose
    `holder_pid` is a confirmably-dead pid ON THIS HOST and whose `expires_at` is in
    the future, then `acquire({dir, timeoutMs: 0})` must still reject. Same fixture but
    with `kind` omitted (a process lease) must succeed — the two schemes differ, and
    this test is the proof.
  - Session lease outlives `maxLeaseAgeMs`: a session lease with `acquired_at` two
    hours ago and `expires_at` ten minutes in the future is NOT reclaimed by
    `acquire({dir, timeoutMs: 0, maxLeaseAgeMs: 1000})`. The session branch must be
    evaluated before the age branch or a long-refreshed session gets stolen.
  - Expired session lease IS reclaimed: same fixture with `expires_at` in the past →
    `acquire({dir, timeoutMs: 0})` succeeds on that port.
  - Malformed session lease (`kind` session, `expires_at` unparseable) is reclaimed with
    a stderr warning rather than wedging the port forever — same posture as the existing
    malformed-lease test.
  - No session file at all = today's behaviour (D-1, hard requirement): with
    `VICE_SESSION_FILE` pointing at a path that does not exist, `activeInstance()` after
    session resolution reports port 6510 and the default endpoint, and no lease file is
    written anywhere.
  - `session release` frees the port: after a release child exits, the lease file is
    gone and the session file is gone.
  - Untrusted session file (T-nh5-01): a session file whose `port` is a string, or
    negative, or whose `epoch_file` is `"../../etc/passwd"`, must not crash and must not
    open the attacker-supplied path — resolution reports the file unusable and refuses,
    and the epoch path actually used is derived from the validated integer port.

does NOT persist between Bash invocations, so a session cannot live in an exported

retargeting from a leased port back to 6510 without telling anyone is precisely the
"quiet wrong answer" failure class this codebase keeps rejecting. Refuse the command and
name the two recovery verbs.

In `tools/vice-pool.mjs`: extend `acquire()` with `kind` (default `"process"`, today's
meaning) and `ttlMs`. When `kind` is `"session"`, write `kind` and `expires_at` into the
lease record and DO NOT add the lease to `pendingLeases` or register the exit handlers —
a session deliberately outlives the process that created it, which is the entire
distinction from a process lease, and auto-releasing at exit would destroy every session
the instant `session acquire` returned. Comment that trap explicitly at the skip site.

Rewrite `isReclaimable()` so a session lease is decided FIRST, before the age branch and
before the pid branch: a session lease is reclaimable only when `expires_at` has passed,
or when `expires_at` is missing or unparseable (malformed, reclaim with a warning). It is
never reclaimed by `maxLeaseAgeMs` and never pid-probed. Add the comment D-2 requires
here: pid liveness is deliberately not used for sessions because the holder is a
short-lived Node process that exits between commands — its pid is gone immediately, so
pid-liveness would reclaim a live session out from under itself. A process lease keeps
today's rules verbatim.

Export `releaseLeaseByToken(leasePath, token)` and `refreshLease(leasePath, token, ttlMs)`
from `tools/vice-pool.mjs`, both token-checked so a lease that was reclaimed and
reacquired by someone else is never stolen (T-nh5-04), and refactor the existing
`release()` closure to delegate to `releaseLeaseByToken` so there is one implementation
and no drift. `refreshLease` writes via temp file plus rename.

`session release`, `session status`. Import `vice-session.mjs` with a dynamic

imports `vice.mjs`, so a static import would create a module cycle, and more importantly
the library surface of `vice.mjs` must stay free of any pool/session dependency so
programmatic callers keep working untouched (D-6). Call `resolveInstance()` once at the
top of the CLI's `main()` so `ping` and `call` transparently honour the active session,
and make `ping`'s output line print the resolved port and session id alongside the URL it
already prints.

In `tools/recover.mjs`, leave the lease behaviour completely alone and add to the existing
`main()` lease comment the other half of D-2's distinction: this is deliberately a
`kind:"process"` lease with pid-based reclaim, because its holder is one long-running
process that lives for the whole verb — unlike an interactive session, whose holder exits
between commands. Cross-reference `isReclaimable()`.
