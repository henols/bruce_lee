<objective>
Close `.planning/todos/pending/2026-08-02-vice-broker-has-no-detached-run-mode.md` (severity
`major`): the VICE broker runs in the foreground only, so a stray Ctrl-C, a closed terminal or a
SIGHUP from an ending SSH/VS Code session reaps every instance it is tracking — including
instances leased to other agents' live sessions. Observed live on 2026-08-02: `^C` produced
`reap saw 4 recorded instance(s), terminated 4`, and a live session's `vice_ping` immediately
returned ECONNREFUSED against its cached grant. This has already halted plan 01-04 once.

Two halves, both required:

1. A `--detach` flag on `start` that re-execs the broker under `setsid`, leaving the terminal's
   session and process group entirely, appending its output to a log, and returning promptly
   with the child's pid.
2. A loud warning on the foreground `start` path naming exactly what a Ctrl-C in that terminal
   destroys — the half that helps the person who chooses not to detach.

Purpose: the blast radius is what makes this `major`. One signal to a foreground process
destroys every live session's emulator at once, and a session that loses its instance loses its
accumulated context.

Output: a `--detach` flag and a `VICE_BROKER_LOG` knob on the tracked broker script, a foreground
warning, and regression tests in the existing harness proving detachment by session id rather
than by the parent merely having returned.

**The fix changes which signals can REACH the broker. It never changes what the broker does when
one arrives.** See `<constraints>`.

Tracer note: this is a deployment-shape change to an already-proven daemon, not a new
architecture, so there is no separate tracer slice. Task 2's first test IS the end-to-end slice —
it spawns the real script, captures the real detached pid, and compares real session ids from
`ps`; Tasks 1 and 3 are the parse surface below it and the contract proof above it.
</objective>
