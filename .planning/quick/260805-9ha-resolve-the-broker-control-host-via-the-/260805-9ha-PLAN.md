<objective>
Stop the container-side broker client from dialing the address `broker.json` records in
`control_host` -- that field is the broker's BIND address (`0.0.0.0`) and is structurally
unreachable from inside this container -- and stop a connect failure from being reported as a
stale-heartbeat verdict.

Purpose: every forwarded `mcp__vice__*` call currently fails while a healthy broker with three warm
spares sits idle, and the error names a cause that had already been satisfied. The address bug costs
total emulator access; the mis-attributing message cost the previous session roughly a dozen tool
calls chasing a threshold that was never exceeded. Both are first-class deliverables.

Output: a dial-target resolver plus a structural-unreachability guard in
`vice-broker-client.ts`, a control-plane-unreachable diagnosis in `vice-proxy.ts` that names the
address and port, in-container test seams for every control-plane test, one appended
`RE-FINDINGS.md` entry, and the todo moved to `completed/` with a dated resolution note.

Root cause is ESTABLISHED and must not be re-derived. `vice-broker.mts:782` writes the bind address
into `control_host`; `vice-broker-client.ts:219` and `:701` read it verbatim and connect to it;
`broker-control.mts:16-20` documents the exact rule being broken; `vice.ts:32` shows the data plane
already getting this right. The trap: `control_host` has two consumers with two different correct
answers (host-side tooling runs on the host, where the recorded bind address is fine), so the fix
belongs on the consumer side, never in the record.
</objective>
