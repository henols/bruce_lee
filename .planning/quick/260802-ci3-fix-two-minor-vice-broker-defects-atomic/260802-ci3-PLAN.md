<objective>
Fix the two `minor` VICE-broker defects filed on 2026-08-02, each with a regression test that
would have caught it:

1. `write_json_atomic()` strands a `.broker.XXXXXX` temp file in the pool dir when the process
   dies mid-write, and nothing ever sweeps it. Replaced with a deterministic per-target
   `"$final_path.tmp"`, bounded by construction.
2. `maintain_spares()` integer-divides nanoseconds to whole seconds, so every sub-second boot
   logs as `(0s)`. Replaced with a millisecond figure carrying the poll-quantisation caveat.

Purpose: the second defect is why an ~8x-wrong ~8s boot assumption reached a design note, a todo
and a spike unchallenged — the real measurement existed and displayed as nothing. The first is
unbounded accumulation plus a misleading artifact for anyone inspecting the pool dir mid-outage.

Output: two corrected sites in the tracked broker script (one of them with its now-false header
comment rewritten), two new regression tests in the existing harness, and both todos archived
with their stale `files:` path corrected.

Tracer note: this is a two-site bug fix in an already-proven system, not a new architecture, so
there is no separate tracer slice. Task 1's regression test IS an end-to-end slice — it spawns
the real script as a subprocess against a real temp pool dir and asserts on the resulting
on-disk state — and Task 2 expands the same harness shape to the second site.
</objective>
