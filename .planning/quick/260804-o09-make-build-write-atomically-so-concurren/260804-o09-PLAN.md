<objective>
Make `build()` in `.claude/mcp/vice/build.ts` stage its output in a private temp directory and
atomically `rename()` each finished file into `outDir`, so the 15 test-suite call sites that build
concurrently into the shared, committed `resources/` can no longer expose a torn file to a reader.

Purpose: the full suite fails intermittently with a *different* victim each run
(`resources-sync.test.ts` reporting the committed tree STALE; `vice-broker-launch.test.ts:333`
getting exit 1 instead of 2 from the emitted artifact). Both are false alarms -- the committed tree
is correct -- and both are reads of a file another test's `build()` was mid-write on. An
intermittent false failure in the gate that polices generated output is worse than no gate: it
trains a maintainer to re-run until green, which is exactly how a genuinely stale `resources/` would
get waved through.

Output: an atomic `build()`, a regression test demonstrated RED against the current implementation
first, a `resources/` tree proven byte-unchanged, and three consecutive green full-suite runs.
</objective>

Facts established during planning -- do not re-derive:

- **`tsc` emits exactly the seven `.mjs` files and nothing else** into an out-dir. Verified by
  running `node build.ts --out-dir <scratch>` and a recursive `find` (no `.d.mts`, no `.map`, no
  `.tsbuildinfo`; `tsconfig.json` sets `declaration: false`, `sourceMap: false`, no `incremental`).
  So `HOST_BOUND_ARTIFACTS` is a complete description of what has to be moved.
- **One build takes ~0.6 s wall** (node startup included). Concurrency rounds are cheap.
- **`resources/` also holds `vice-launcher.sh`, hand-authored and NOT generated.** It is not in the
  temp dir and must not be touched by the rename loop -- iterating `HOST_BOUND_ARTIFACTS` (not a
  walk of `outDir`) is what keeps it safe, same as today.
- **Every torn read has a wide, always-present window in the current implementation:** `tsc` writes
  each artifact WITHOUT the banner, and build.ts prepends the banner in a second pass afterwards.
  So a banner-less artifact exists on disk on *every* build, concurrent or not. That is the state
  the concurrency test is most likely to catch.
- **`writeFileSync` / `tsc`'s emit both open with `O_TRUNC`, preserving the inode.** That is what
  makes the held-open-fd test in task 1 deterministic rather than a timing lottery.
</planning_notes>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-time filesystem -> committed `resources/` | Bytes crossing here become the artifacts `install-resources.ts` deploys to the host and the host runs under bare `node`. A wrong byte here reaches the host verbatim. |
| concurrent processes -> shared out-dir | Multiple builds and multiple readers share one directory with no lock; ordering is the only protection. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-o09-01 | Tampering | `build()` staging dir | medium | mitigate | `mkdtempSync` creates the directory with mode 0700 and an unpredictable suffix, so no other user can pre-create or symlink-hijack the staging path between the name being chosen and the files being written. Do not hand-roll a predictable `pid`-only name. |
| T-o09-02 | Tampering | `resources/` during a concurrent build | high | mitigate | This is the defect itself: a reader can currently observe a half-written artifact and, worse, `vice-broker-launch.test.ts` *executes* one. Per-file `renameSync` of fully-bannered files closes it; task 1 test 2 is the standing proof. |
| T-o09-03 | Denial of Service | staging dir accumulation | low | mitigate | `finally { rmSync(...) }` on every path, plus task 1 test 3's success- and failure-path leftover assertions and task 3's tree-wide `find`. |
| T-o09-04 | Tampering | silent artifact loss | medium | mitigate | Post-rename "staging dir must be empty" assertion: a compiler that starts emitting an eighth file fails the build loudly instead of quietly dropping a file that used to reach `outDir`. |
| T-o09-05 | Repudiation | a green suite read as proof | high | mitigate | A race that is only ever observed green is indistinguishable from a fix. Countered by demonstrating the test RED first and pasting that output into SUMMARY.md, plus three consecutive green runs rather than one. |
