**`build()` in `.claude/mcp/vice/build.ts` now stages every compiled, fully-bannered artifact in a private same-filesystem sibling temp dir and atomically `rename()`s each into `resources/`, closing an intermittent torn-read race that made concurrent test-suite `build()` calls flip a random victim test red on a correct committed tree.**

## Decisions Made

- **No lock, per-file atomic rename only.** Every concurrent `build()` caller in this repo compiles the same unmutated `.mts` sources, so every concurrent build emits byte-identical output — there is no "which generation wins" question, only "never expose a half-written file", and `rename()` onto a fully-finished path already guarantees that. Documented in `build()`'s doc comment per the plan's instruction.
- **Staging dir is a sibling of `outDir`, not inside it, and not `os.tmpdir()`.** Inside `outDir` would be visible to `resources-sync.test.ts`'s recursive walk; `os.tmpdir()` risks a different filesystem and an `EXDEV` on the final rename. `dirname(outDirAbs)` is guaranteed to exist because `mkdirSync(outDirAbs, { recursive: true })` runs first.
- **Staging dir name (`.build-tmp-<pid>-<random>`) has exactly one leading dot and no dot in the tail**, per the plan's key link, keeping it invisible to every shallow `/\.[cm]?[jt]s$/`-filtered directory gate in this test directory (verified by grep against all 6 files using that pattern before writing the fix).
