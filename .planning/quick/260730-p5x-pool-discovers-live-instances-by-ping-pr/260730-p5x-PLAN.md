<objective>
Close the gap where `acquire()` hands out an instance based only on what `vice-pool.sh start` CLAIMED to launch, with no check that anything is alive on that port. Today the host supervisor died, its epoch froze, and nothing container-side knew until a call burned ~50s of reconnect backoff.

Purpose: turn "the registry says this port exists" into "this port answered a ping just now", and make the four questions — launched, alive, free, supervised — separately answerable and separately reported.

Output: a new deliberately-fragile probe module, a probing `acquire()` that never returns a dead instance and explains every rejection, a `pool status` report covering all four questions, and offline tests including the timing proof that the probe is not the reconnect ladder in disguise.
</objective>

Create `.claude/skills/vice-session/vice-probe.mjs`, a new module in the vice-session skill, exporting `PROBE_TOOL`, `DEFAULT_PROBE_TIMEOUT_MS`, `probeInstance()` and `probeAll()`.

`PROBE_TOOL` is the frozen constant `"vice_ping"`. It is hardcoded and no export accepts a tool name from a caller — that is the structural reason no probe can ever reach a forbidden tool (T-p5x-03, D-7). `DEFAULT_PROBE_TIMEOUT_MS` reads `VICE_PROBE_TIMEOUT_MS` and defaults to 1500 (D-3's "~1-2s, configurable").

`probeInstance({ url, port, timeoutMs = DEFAULT_PROBE_TIMEOUT_MS })` performs ONE MCP round trip sequence against `url` — the `initialize` handshake followed by a `tools/call` of `PROBE_TOOL` — with a SINGLE `AbortSignal.timeout(timeoutMs)` created once and shared by both requests, so total wall time is bounded by `timeoutMs` no matter how many round trips the handshake costs. No retry, no backoff, no second attempt at anything. Returns `{ port, url, alive, ms, reason, ping }` and NEVER throws: a rejected fetch becomes `alive:false` with a reason built from the error's `cause.code` when present (so ECONNREFUSED surfaces as itself) and the message otherwise; an abort becomes a timeout reason naming `timeoutMs`; a non-2xx becomes an HTTP-status reason; a JSON-RPC `error` member becomes an RPC reason. Parse the response body the same two ways the seam does (an SSE-framed body's last `data:` line, or a plain JSON body) using a small parser local to this module — the duplication is deliberate and must be commented as such: this module shares no mutable state with the seam because it probes several ports at once, none of which the seam is pointed at. Treat a 200 that does not decode to a ping result (no `version` field) as `alive:false` with a reason saying something else is listening on that port (T-p5x-04).

`probeAll(instances, { timeoutMs })` maps `probeInstance` over the given instance objects and awaits them all together, so N candidates cost one timeout and not N (D-3). Return both the array and a `byPort` Map so callers can look a verdict up without re-scanning. It takes instance objects — never raw registry entries — because the caller is responsible for having derived the URL from a validated port (T-p5x-01).

This module must NOT take a static dependency on the transport seam. That is not stylistic: importing it is how the resilient retry path would leak in, and D-3 exists because probing four ports through a ~50s backoff ladder takes minutes to report an empty pool. Keep the header comment heavy and explanatory in this codebase's established idiom, and make it say, in this order: (1) that this is the deliberately-FRAGILE counterpart to the resilient path and the two must never be merged; (2) what went wrong before — the host supervisor died, its epoch froze, and the first thing to notice was a call burning ~50s of backoff; (3) why the probe is `vice_ping` and nothing else — it is the one call measured NON-pausing, 986,693 cycles/s while ping-polling versus 991,569 fully quiet, whereas every other state-reading call pauses the emulator and does not resume it, which would make probing destructive (cite `.planning/STATE.md`'s pause-on-read finding so a later reader can check the measurement rather than trust the comment).

For the live-endpoint test, probe the default endpoint and assert ONLY on elapsed time, never on the verdict — the endpoint's liveness is not under this repo's control, but the bound on how long a verdict takes is exactly what this task delivers.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host-written `registry.json` -> container Node | Untrusted input already; this task makes it drive OUTBOUND HTTP requests for the first time. |
| container -> arbitrary TCP endpoint | The probe opens connections. What decides the target is now security-relevant. |
| anything listening on a pool port -> container | A responder is trusted to be VICE unless its reply says otherwise. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-p5x-01 | Tampering / Information disclosure (SSRF) | `probeAll` target derivation in `poolHealth`/`acquire` | high | mitigate | Probe targets come only from `instanceFor(validatedPort)`; registry string fields (`url`, `epoch_file`) are never read for this or any other purpose. Test: a registry entry carrying a foreign `url` is probed at the port-derived address instead. |
| T-p5x-02 | Denial of service | probe fan-out | medium | mitigate | Registry-driven only — no scanning, no range sweep, no adoption of unregistered ports (D-6). One single-shot request sequence per candidate per poll pass, bounded by a ~1.5s shared abort signal, candidate count bounded by the registry (pool size caps at 16). |
| T-p5x-03 | Elevation of privilege (deny-list bypass) | `vice-probe.mjs` | high | mitigate | The probe hardcodes `PROBE_TOOL` and exposes no parameter that accepts a tool name, so no caller can steer it at a forbidden tool. `call()`'s deny-list check is untouched and its existing test still passes. |
| T-p5x-04 | Spoofing | liveness verdict | low | mitigate | A verdict of alive requires a decodable ping result carrying a `version` field, not merely a TCP accept or an HTTP 200; anything else answering the port is reported as such rather than as VICE. |
| T-p5x-SC | Tampering (supply chain) | dependencies | low | accept | No package installs in this task — `node:http`, `node:test` and `fetch` are stdlib. No `package.json` change; nothing to audit. |
