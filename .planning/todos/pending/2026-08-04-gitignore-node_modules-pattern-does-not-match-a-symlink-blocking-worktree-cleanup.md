# `.gitignore`'s `node_modules/` pattern does not match a *symlinked* node_modules, which blocks GSD worktree cleanup

## What happened

A worktree executor in Phase 01.6.2.1 wave 2 created

```
.claude/mcp/vice/node_modules -> /workspaces/bruce_lee/.claude/mcp/vice/node_modules
```

inside its isolated worktree — a sensible move, reusing the main checkout's installed
dependencies instead of paying for a fresh `npm install` per worktree.

`gsd-tools query worktree.cleanup-wave` then **refused to merge the worktree**:

```
"status": "blocked",
"reason": "worktree_dirty",
"stderr": "?? .claude/mcp/vice/node_modules"
```

## Why

`.gitignore:137` is `node_modules/` — with a trailing slash, so it matches **directories only**.
A symlink is a *file* as far as git is concerned, so the pattern does not match it and the link
shows up as untracked. `worktree.cleanup-wave` treats any dirty worktree as unsafe to merge.

The work itself was fine — the merge succeeded immediately once the symlink was removed
(`rm` on the link, never `rm -rf` through it into the shared target).

## Why this is worth fixing rather than remembering

It will recur for **every** future worktree executor that reuses deps this way, and the failure
surface is a *blocked merge at the end of a completed plan* — the most expensive moment to
discover it. The orchestrator worked around it three more times in the same phase only because it
had learned the trap and pre-warned each subsequent executor in its dispatch prompt. That
workaround does not survive into other sessions.

## Candidate fixes

1. Drop the trailing slash: `node_modules` instead of `node_modules/` — matches both the directory
   and a symlink of that name, at any depth. Smallest change; check nothing legitimately tracked
   is named `node_modules`.
2. Add an explicit second pattern rather than editing the existing one, if the directory-only
   semantics are deliberate somewhere.
3. Have `worktree.cleanup-wave` ignore untracked *symlinks pointing outside the worktree* when
   deciding "dirty". Broader blast radius; less obviously correct.

Option 1 is the cheap one. Note `.gitignore:127-137` carries a deliberate comment about this
being the first `node_modules` the repository has ever had and about the leading-slash choice
being intentional — read that comment before changing the pattern, since the directory-only form
may itself have been deliberate.

## Evidence

Observed live during Phase 01.6.2.1 wave 2 cleanup: the exact `worktree_dirty` /
`?? .claude/mcp/vice/node_modules` refusal above, then a clean `merged_removed` on retry after
removing only the symlink. Cause confirmed by reading `.gitignore:137` and by `ls -la` showing the
path was a symlink, not a directory.

Confidence: HIGH (reproduced and resolved in-session; cause read directly out of `.gitignore`).
