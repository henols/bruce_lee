<objective>
Make it structurally impossible to recycle an emulator without leaving behind the trail that could
root-cause why it needed recycling.

Purpose: the four existing stall todos all end with "worth investigating host-side" and no host-side
data, because recovery was never possible and the session simply ended. A recycle that discards the
only evidence trades a recurring blocker for a permanent mystery. D-17 puts the capture inside the
tool rather than in instructions an agent under pressure can skip — the alternative arrangement is
precisely the one that already produced four evidence-free todos.

Output: a shared evidence gatherer composed from the plan 02 primitives, the full incident-record
format, a best-effort pre-kill snapshot, and a filesystem-ordering test that is criterion 4's
automated form.
</objective>

## Planning notes carried into execution

**Spec-less probe fallback: SKIPPED, visibly** — no requirement IDs and no phase SPEC, so no probe
predicates were generated. Truths derive from the eleven ROADMAP criteria and D-01..D-22.

**Discretion resolved: the screenshot is committed beside the record.** A C64 framebuffer PNG is a few
kilobytes and it is the single most legible piece of evidence about what the machine was showing when
it stopped. The four evidence-free todos this phase replaces are the argument for keeping it, not
against.

**A distinction that must be stated in the code, not assumed.** This project's no-wall-clock rule
governs **synchronisation with the emulated machine** — never sleep to wait for the game to reach a
state; synchronise on checkpoint hits and cycle counts. It does not forbid a **transport deadline** on
a forwarded call, which already exists and which is what stops a capture step hanging forever against
a wedged instance. Write that distinction into the comment above the capture-step wrapper so a later
reader does not mistake one for the other and either remove a needed deadline or add a forbidden
delay.

**Capture runs exactly one bracket, not two.** The two-bracket rule belongs to the verdict
(criterion 2, plan 02). By the time `vice_recycle` is called the caller has already decided; the
bracket here is evidence for the record, and D-04's reasoning about the resume being this project's
leading crash suspect argues for one rather than two.

**Known pre-existing flake:** the `vice-pool.test.mjs` two-port acquire test reds roughly 1 run in 5,
recorded OPEN in `01.1-deferred-items.md`. Re-run and record both outcomes rather than treating it as
damage from this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP tool surface → repo working tree | The recycle tool writes a git-tracked markdown record and a git-tracked screenshot at paths it computes |
| proxy-local tool → host filesystem | The screenshot capability writes a file host-side at a path the proxy supplies and must translate itself |
| wedged machine → capture steps | Evidence is gathered from an instance that is, by hypothesis, not answering reliably |
