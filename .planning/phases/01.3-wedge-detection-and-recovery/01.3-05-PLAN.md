<objective>
Answer the question the roadmap refuses to assume away: is a specific call or ordering causing the
freeze? Answer it within a fixed number of attempts, entirely from inside the container, and record
the answer either way.

Purpose: there is already one proven instance of a single tool call killing the host —
`vice_disk_list`, deny-listed at four layers for exactly that reason — so "a call does this" is an
established shape in this codebase, not a hypothesis. Two independent sessions froze at an identical
program counter shortly after a stopping checkpoint parked the machine and execution was resumed, and
a third froze after a hard reset issued while a checkpoint was armed on an IRQ handler entry. D-09
retargeted the hunt from that address to the family all three share. A confirmed trigger changes the
deliverable: prevention beats recovery.

Output: a bounded, fully recorded investigation; the findings appended to the project's findings log
as they are found; and, if a trigger is confirmed, one seam-hazard table entry closing it in this
phase rather than a follow-on.
</objective>

## Planning notes carried into execution

**Spec-less probe fallback: SKIPPED, visibly** — no requirement IDs and no phase SPEC, so no probe
predicates were generated. Truths derive from the eleven ROADMAP criteria and D-01..D-22.

**The budget is six, and it is a count.** D-10 requires the number to be named in the plan, not what
it is. Six, split three and three across the two recorded variants, sized from RESEARCH's
reconstruction of what one attempt costs — roughly eight to twelve tool calls plus a boot sequence,
affordable in one session only because `vice_recycle` now restores an instance in place instead of
forcing a fresh session per attempt. Time-boxing was rejected in D-10 because wall-clock is never part
of this project's loop, and making an exception here would be the wrong place to start.

**The boundary is a checkable line, not an aspiration.** D-11: anything answerable through
`mcp__vice__*` is in scope — which call, which ordering, what the machine state looks like at the
freeze. The moment a question needs host process internals — a stack trace, thread state, GTK or
OpenGL introspection, a debugger on the emulator process — the hunt stops and records it as an open
question. No script, module or driver may open its own connection to the host, and reimplementing that
route cleanly would be the same violation as importing it.

**Do not derail into fixing what you find.** A VICE MCP quirk observed while driving the emulator gets
filed as a pending todo, per the project's own triage rule. The exception is a confirmed trigger, which
D-06 says is closed at the seam inside this phase.

**If the emulator cannot be reached at all**, the broker-absent path names which of three states it is
in and what to do. Record that as the outcome, name it in the document, and stop. Criterion 9's answer
then becomes "could not be attempted, here is why", which is still a real result and which plan 01.3-06
records. Do not fabricate attempts.

**Known pre-existing flake:** the `vice-pool.test.mjs` two-port acquire test reds roughly 1 run in 5,
recorded OPEN in `01.1-deferred-items.md`.
