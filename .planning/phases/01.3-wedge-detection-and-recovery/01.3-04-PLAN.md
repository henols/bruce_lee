<objective>
Put the phase's own hypothesis in front of the agent at the moment it is about to act on it: arming a
stopping exec checkpoint is the shape common to all three recorded freezes, and the call that arms one
comes back carrying that fact.

Purpose: D-06 says a confirmed trigger is blocked at the seam within this phase rather than deferred,
and D-16 fixes the shape of that block. `vice_disk_list` is deny-listed because it has no legitimate
use. A stopping checkpoint on an IRQ handler is core RE technique that Phase 2's exhaustive trace
depends on — refusing it, even behind an opt-in override, would obstruct the exact work this project
runs on. Same seam, different remedy: the call goes through and the result carries the warning.

Output: a post-forward annotation mechanism that is structurally the opposite of the deny list, a
hazard table that makes adding the next confirmed trigger a one-line change, and the guard-removal
tests that keep both honest.
</objective>

## Planning notes carried into execution

**Spec-less probe fallback: SKIPPED, visibly** — no requirement IDs and no phase SPEC, so no probe
predicates were generated. Truths derive from the eleven ROADMAP criteria and D-01..D-22.

**A planner decision that narrows the guard on purpose, recorded rather than buried.** RESEARCH Key
Finding 5 suggested detecting "a stopping exec checkpoint whose address resolves to the currently-live
IRQ handler target", which needs the same live vector lookup `vice_diagnose` performs. **This plan
deliberately does not do that at the seam.** Three reasons, and the third is the decisive one:

1. D-09 already retargeted the hunt's subject from the `$DD00` address to **the armed-stopping-exec-
   checkpoint family**, because cross-reading all three incidents showed the family, not any address,
   is the common factor. The seam guard should target the same family the evidence names.
2. RESEARCH Pitfall 3 forbids caching the resolved handler, so a seam-level address match would have
   to re-resolve on every checkpoint-arming call.
3. Most state reads pause the emulator. Adding three reads to every checkpoint arm — at the scale
   Phase 2's exhaustive trace will arm them — would make this guard a source of exactly the class of
   disturbance it exists to warn about. That is D-04's reasoning about the detector causing the
   failure it catches, applied one layer down.

**Stated residual, in the honest style this project already uses elsewhere.** Only a call whose own
arguments carry the exec operation and the stop flag is detectable from the call alone. Re-enabling a
previously-armed stopping checkpoint through the toggle capability, or through a checkpoint group,
carries no stop flag in its own arguments and is therefore **not annotated**. That gap is covered by
the two tool descriptions and by `vice_diagnose`'s trap check, and it is written into the annotation
text rather than left for a reader to discover.

**Known pre-existing flake:** the `vice-pool.test.mjs` two-port acquire test reds roughly 1 run in 5,
recorded OPEN in `01.1-deferred-items.md`. Re-run and record both outcomes.
