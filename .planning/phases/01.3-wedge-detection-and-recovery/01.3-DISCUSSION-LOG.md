## The checkpoint-trap fourth state (user-raised)

The user interrupted the todo-folding question to propose a mechanism: *"if it's possible, check if there is a checkpoint set inside the IRQ routine so it looks like it's frozen but it gets stuck in the IRQ vector."*

Checked against all three incidents before folding it in. It held up better than the roadmap's own leading candidate — the common factor across all three is an armed stopping checkpoint plus a resume, not an address. The `$1103` incident's `hit_count: 0` on an IRQ-driven screen is the strongest single piece of evidence. Logged to `.planning/RE-FINDINGS.md` at MEDIUM confidence.

**Notes:** User then clarified mid-turn: *"it shall report back what the problem is but not solve it"* — the tool diagnoses and stops; the agent deletes/disables/steps past using existing tools. Confirmed again at the close: *"just to confirm if the IRQ trap is found, there is no need of restarting the emulator and it's reporting back the issue so the LLM can solve it by itself and understand what happened."*
