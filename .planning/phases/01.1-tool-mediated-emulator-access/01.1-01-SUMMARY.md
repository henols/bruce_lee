## Decisions Made

- **Reachability verdict is `host-not-running`.** DNS resolved (`172.17.0.1`), all three pool ports refused immediately rather than timing out, and `.vice-supervisor/` doesn't exist yet in this container instance — this is an availability fact about the host, not a design defect, so Task 2 proceeded on the `node:http` stand-in server plan `01.1-RESEARCH.md` specified for exactly this case.
- **Corrected, not inherited, the "non-functional" framing.** The diagnosis names RECOVER-01/02/03 as evidence the current path works and states the real justification is the hazard/enforcement gap.
- **`vice-proxy.mjs` imports only `call` and `activeInstance`** from `vice.mjs`, not the full four-symbol list named in the plan's action text (`call`, `serverInfo`, `DENY_LIST`, `activeInstance`). `serverInfo`/`DENY_LIST` were left out because their only legitimate use in this tracer's scope would either touch the host (violating the zero-HTTP-request property of `initialize`/`tools/list`) or duplicate a guard `call()` already enforces (the plan's action text explicitly says "no hazard guards beyond what the reused `call()` already enforces"). This does not affect any acceptance criterion — none of them names a specific import beyond "imports from `../../vice-session/scripts/vice.mjs` and that import resolves," which it does.
- **`tools/list`'s tracer-scope manifest source is a `VICE_TOOLS_MANIFEST` env-var file path, read synchronously, never a live call** — matches the plan's explicit instruction and keeps the zero-host-request property of `initialize`+`tools/list` true by construction, verified directly by the test's request-count assertion.
