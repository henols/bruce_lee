## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Claude Code → proxy stdin | Untrusted-shaped JSON-RPC lines. A dead stdio server is never reconnected, so a crash here costs the session its emulator access permanently. | JSON-RPC request frames, arbitrary/malformed bytes |
| Claude Code → forwarded tool arguments | The agent chooses tool names and argument values, including filesystem paths. The proxy is the only place that can know whether a path is host-correct. | Tool names, addresses, absolute container paths |
| host-written files → proxy | `.vice-supervisor/epoch.json` and `tools-manifest.json` are written by host-side processes the container does not control. | Epoch/pid records, tool metadata |
| proxy → host VICE MCP server (HTTP) | The only route out of the container. Every emulator action passes here, which is what makes the proxy an access-control point rather than a pass-through. | Serialised tool calls, memory/screen payloads |
| proxy stdout → Claude Code's line parser | One non-JSON-RPC byte corrupts framing for the rest of the session. | JSON-RPC response frames only |
| `/proc/self/mountinfo` → `hostPath()` | Read lazily to derive the host mount; failure must degrade to a refusal with a reason, never a silently wrong path. | Mount table |
| documentation → agent behaviour | The remaining agent-facing route. A surviving instruction to reach the emulator from a shell bypasses every guard installed here. | Instructions read by agents |
| tracked `resources/` → deployed `tools/` copies | One-way copy. Deleting the source orphans the deployed host scripts with nothing to diff against. | Shell scripts |

## Notes for later phases

Not threats in this phase, but the two things a future audit should re-check rather than assume:

- **The path-translation residual is deliberate and documented.** A *relative* path string is left
  byte-identical, because it is indistinguishable from a non-path argument (a tool name, a hex
  address like `$0400`, a label) without guessing, and rewriting a non-path argument would be a
  worse failure than leaving a relative path unresolved. `SKILL.md` tells callers to pass absolute
  container paths for exactly this reason. If a later phase starts passing relative paths to
  emulator tools, this becomes a live concern.
- **The workspace boundary is the only access-control property available at the proxy seam.** It
  bounds what the MCP surface can address on the host to the mounted workspace. It does not, and
  cannot, bound what the *emulator* does once it has a valid path.
