### `.claude/skills/vice-mcp-selector/scripts/vice-proxy.mjs` (new — server+client hybrid)

**No stdio-MCP-server analog exists anywhere in this repo.** Every existing "server" in this project is either a shell daemon (`vice-supervisor.sh`) or a plain CLI (`vice.mjs`'s own `if (process.argv[1] === SELF)` block) — none speaks JSON-RPC framed over its own stdin/stdout to an MCP client. State this as a genuine gap rather than force a weak match; RESEARCH.md's own "Don't Hand-Roll" table agrees this ~150-line piece is the one truly new artifact.

**Client-half analog: `vice.mjs`** (`.claude/skills/vice-session/scripts/vice.mjs`, moves unchanged to `vice-mcp-selector/scripts/vice.mjs`). Import surface the proxy is expected to consume, verified by direct read (lines cited against the pre-move path):

The deny-list check the proxy must reuse verbatim (vice.mjs:103-106):
```js

```

The call-then-refuse ordering vice.mjs already enforces at the top of `call()` (vice.mjs:476-482) — the proxy's `tools/call` handler should mirror this shape exactly, refusing *before* any network request:
```js
export async function call(toolName, args = {}, opts = {}) {
  if (DENY_LIST.includes(toolName)) {
    throw new ViceError(
      `${toolName} is permanently forbidden -- it is known to crash the shared host VICE MCP server ` +
        `(see CLAUDE.md's hazard note). Refusing to serialise this request.`
    );
  }
  ...
```

Discovery-time filtering the proxy's `tools/list` handler should reuse directly, not reimplement (vice.mjs:536-541):
```js
export async function serverInfo() {
  await ensureInitialized();
  const payload = await rpc("tools/list", {});
  if (!Array.isArray(payload?.tools)) return payload;
  return { ...payload, tools: payload.tools.filter((t) => !DENY_LIST.includes(t?.name)) };
}
```

Epoch re-check primitive to call on every forwarded `tools/call` (vice.mjs:327-351, `readEpoch()`) — synchronous, never throws, treats the file as untrusted input:
```js
export function readEpoch(path = activeEpochFile) {
  const absent = { present: false, epoch: null, spawned_at: null, pid: null, path };
  let raw;
  try { raw = readFileSync(path, "utf8"); }
  catch { return { ...absent, reason: "epoch file absent" }; }
  let parsed;
  try { parsed = JSON.parse(raw); }
  catch { return { ...absent, reason: "epoch file present but not valid JSON" }; }
  if (parsed === null || typeof parsed !== "object" || !Number.isInteger(parsed.epoch)) {
    return { ...absent, reason: "epoch file present but its \"epoch\" field is not a finite integer" };
  }
  return { present: true, epoch: parsed.epoch, spawned_at: ..., pid: ..., path };
}
```

**Error handling pattern to copy at the proxy's outermost boundary** (vice.mjs's own `withReconnect()`, lines 249-281): every transport failure is caught and turned into a thrown `ViceError` with an actionable, host-side-fix message — never an uncaught exception. The proxy's job (per RESEARCH.md Pattern 2 and Pitfall 3) is to catch *this* thrown error one layer further out and turn it into an MCP `{content, isError:true}` result, never a JSON-RPC protocol error and never an uncaught throw:
```js
// RESEARCH.md's own illustrative sketch (01.1-RESEARCH.md:167-183), to be
// checked against call()'s actual return/throw shape during implementation:
async function handleToolsCall(name, args) {
  if (DENY_LIST.includes(name)) {
    return { content: [{ type: "text", text: `${name} is permanently forbidden — see CLAUDE.md's hazard note.` }], isError: true };
  }
  try {
    const result = await call(name, args);
    return { content: [{ type: "text", text: JSON.stringify(result) }], isError: false };
  } catch (e) {
    return { content: [{ type: "text", text: e.message }], isError: true }; // NEVER rethrow
  }
}
```

**Process-lifetime/signal-handling analog: `resources/vice-supervisor.sh`** (lines 323-350). Not a Node file, so the pattern to copy is the *discipline*, not the code: a long-lived loop with a `trap cleanup INT TERM` that terminates the tracked child cleanly, never leaving something orphaned, and that never exits on the failure condition it exists to survive:
```bash
# vice-supervisor.sh:328-339 — copy the SHAPE (trap + guarded cleanup + one
# exit point), not the shell syntax, into vice-proxy.mjs's
# process.on('SIGTERM')/uncaughtException handlers.
child_pid=""
cleanup() {
  if [ -n "$child_pid" ] && kill -0 "$child_pid" 2>/dev/null; then
    echo "vice-supervisor: caught signal, terminating child pid $child_pid" >&2
    kill -TERM "$child_pid" 2>/dev/null || true
    wait "$child_pid" 2>/dev/null || true
  fi
  echo "vice-supervisor: clean shutdown" >&2
  exit 0
}
trap cleanup INT TERM
```
The proxy's own equivalent is `process.on('uncaughtException', ...)` / `process.on('unhandledRejection', ...)` / an `'error'` listener on `process.stdout` for EPIPE — log-and-continue, never `process.exit()`, per RESEARCH.md Pitfall 3 (citing the real, filed `modelcontextprotocol/typescript-sdk#1564` defect for this exact failure class).

**Host path translation (success criterion 9) — see `hostpath.mjs` mapping below**, since the proxy is now a *new* consumer of it, not one of the existing ones.

## Shared Patterns

### Never-throw / always-answer-in-MCP-frames
**Source:** `vice.mjs`'s own `withReconnect()` (catches every transport failure, throws a typed `ViceError` with an actionable host-side-fix message) and `vice-probe.mjs`'s explicit "NEVER THROWS" contract (lines 86-91, every failure mode becomes `{ alive: false, reason }`).
**Apply to:** `vice-proxy.mjs`'s entire `tools/call` handler, per-line JSON parsing, and its stdin read loop — this is the single structural property success criteria 5, 6 and 7 all rest on.

### Deny-list enforced at two layers (discovery + call)
**Source:** `vice.mjs:103-106` (`DENY_LIST`), `vice.mjs:536-541` (`serverInfo()` filters `tools/list`), `vice.mjs:476-482` (`call()` refuses before any network request).
**Apply to:** `vice-proxy.mjs`'s `tools/list` and `tools/call` handlers both — hide AND refuse, never one without the other (RESEARCH.md's Known Threat Patterns table is explicit that regressing to refusal-only would be a real regression).

### Directory-enumeration completeness checks, never a one-shot grep
**Source:** `skill-docs.test.mjs` (both copies, `vice-session` and `c64-ram-capture`) — `readdirSync(SCRIPTS_DIR)` walked fresh every test run, never a hardcoded module-name list.
**Apply to:** both new test files that check "nothing leaked" (`vice-mcp-selector-docs.test.mjs` for criterion 8's retirement, and any equivalent SKILL.md-name-leak check for the new skill itself).

### Fire-once resource deployment, `resources/` (tracked) → `tools/` (deployed), never the reverse
**Source:** `install-resources.mjs`'s `installResources()`/`resourcesStatus()`, triggered from `repo-root.mjs`'s bottom-of-module `ensureResourcesInstalled()`.
**Apply to:** the relocated `resources/` directory (`vice-pool.sh`, `vice-supervisor.sh`, `lib/container-guard.sh`, `lib/repo-root.sh`) must move as a unit with `install-resources.mjs`, preserving this exact copy direction — do not invert it, and do not delete `tools/`'s deployed copies without also either keeping `resources/` as their source or accepting they become permanently orphaned.
