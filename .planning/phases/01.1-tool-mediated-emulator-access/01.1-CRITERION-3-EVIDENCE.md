## 5. Address read and bytes returned

Call made to the `mcp__vice__memory_read` tool (full session-listed name
`mcp__vice__vice_memory_read`, per the naming pattern in § 4 above):

```
mcp__vice__vice_memory_read { "address": "$FFFC", "size": 2 }
```

Result, verbatim:

```json
{ "address": 65532, "size": 2, "encoding": "array", "data": ["E2", "FC"] }
```

Interpretation: `$FFFC = $E2`, `$FFFD = $FC`. Little-endian, that is the reset
vector **`$FCE2`** — the stock C64 KERNAL reset entry point, which is exactly
what the C64 memory map specifies for a machine with KERNAL ROM banked in at the
top of memory. The bytes are correct, so a real `mcp__vice__*` call reached the
real host emulator and returned real data.

## 6. Observed `protocolVersion` — NOT CAPTURED, deliberately, with cause

**This is a deliberate, user-approved deviation from the letter of Task 1's
acceptance criteria.** The `protocolVersion` string Claude Code sent during
`initialize` is **not recoverable retroactively** and is recorded here as a gap,
not a value.

`handleInitialize()` (`.claude/skills/vice-mcp-selector/scripts/vice-proxy.mjs:114-123`)
reads `params.protocolVersion`, echoes it back when it is one of the proxy's
supported versions, and otherwise falls back to the newest version the proxy
itself supports — but it never persists the requested value anywhere. The proxy
keeps no log file and no debug hook; its only environment inputs are
`VICE_MAX_RESULT_CHARS` and `VICE_TOOLS_MANIFEST`. Nothing on disk carries the
string, so it cannot be recovered after the handshake completed.

What *is* known and is recorded here instead:

- `SUPPORTED_PROTOCOL_VERSIONS = ["2025-06-18", "2024-11-05"]` (`vice-proxy.mjs:110`)
- Negotiation rule: echo the client's requested version when it is in that list,
  else respond with `"2025-06-18"`.
- The handshake succeeded and tools were listed, so the version Claude Code sent
  was either one of those two supported values, or was absent/unsupported and
  silently negotiated down to `"2025-06-18"` — the three cases are
  indistinguishable from outside the process with the proxy as it stands today.

The one-line fix that would close this gap for future sessions — persisting
`requested` at the point `handleInitialize()` reads it — is **not** made in this
plan; it is out of scope for 01.1-04 and is left as a note for whoever next
touches the initialize handshake (relevant to `01.1-RESEARCH.md` § Open Questions
item 1, the pending lifecycle spike). No value was guessed.
