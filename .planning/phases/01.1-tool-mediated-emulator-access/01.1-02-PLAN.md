<objective>
Give `tools/list` a real source that needs no emulator, and convert the three known hazards from
rules that had to be remembered into code with tests that fail when the guard is removed.

Purpose: this is where the phase earns its justification. The diagnosis in plan `01.1-01`
established that the Bash-mediated path was working code — what it could not do was *enforce*
anything. `vice_disk_list` crashes the host and needs a manual host-side restart; a mid-session
host restart silently returns blank-machine reads; a 64K RAM read overruns the output limit. All
three become structural here.

Output: a committed `tools-manifest.json` snapshot plus the `refresh-manifest.mjs` that regenerates
it; deny-list enforcement at both discovery and call time; a per-call epoch re-check; and a
no-silent-truncation output path.
</objective>

<decisions_resolved_here>
Three decisions land in this plan. None is `one-way`, so none earns a `checkpoint:decision`.

**D-C — Where `tools/list`'s schemas come from.**
Resolution: a **committed schema snapshot plus a refresh script**. `tools/list` is a pure read of
`tools-manifest.json`; `refresh-manifest.mjs` is the only writer and fetches from a live host on
demand. Rejected: a **hand-written manifest**, because 63 tool schemas maintained by hand drift the
week they are written. Rejected: a **lazy first-fetch with cached fallback**, because on the very
first run of a fresh clone there is no cache, so the fetch is not a fallback but the primary path —
and finding 6 (spawn is eager, at session start) means that fetch lands inside session startup
against a host that this phase has already measured as frequently down. A snapshot read cannot
hang, cannot fail open, and cannot make session startup depend on the emulator.
Consequence to plan around, stated plainly: the snapshot **cannot be generated until the host is
up**, so the committed initial state is an empty `tools` array and the criterion-3 human checkpoint
(plan `01.1-04`) must run the refresh *before* the fresh session, or no `mcp__vice__*` tool will
appear. Reversibility: **reversible** — a fetch path can be added later behind the same read.

**D-D — What the epoch check is for now.**
Resolution: **mid-session host-restart detection only, via `readEpoch()` alone.** The proxy does
not call `assertSameMachine()` and never runs its checkpoint-fallback probe. Three reasons, all
concrete: the probe costs an MCP round-trip; `vice_checkpoint_list` is a state-reading call, which
pauses the emulated CPU and does not resume it (a measured project finding); and the proxy arms no
checkpoints of its own, so it has nothing legitimate to probe with — `assertSameMachine()`'s
"reconnect happened, nothing to probe, therefore void" branch would fire on every reconnect and
turn a recoverable blip into a hard error. The narrowed contract: compare a baseline epoch against
the current epoch on every forwarded call, report a change loudly, then adopt the new value so the
session stays usable. Absent→present is not a restart (a supervisor merely started); this matches
`vice.mjs`'s existing "only compare when both are present" rule. Reversibility: **reversible.**

**D-E — Chunking versus the `_meta` output-size override.**
Resolution: **both, in that order.** `tools/list` declares
`_meta["anthropic/maxResultSizeChars"]` at the documented 500,000-character ceiling on every tool
(not a curated per-tool list, which would drift as the host's tool set changes), which raises the
real limit far above the 25,000-token default and covers a 64K RAM read in any plausible encoding.
Behind that, a proxy-side cap catches whatever still overruns: an oversized result is split and
returned across an explicit continuation sequence via one synthetic tool, so the caller can always
reassemble the whole payload. Silent truncation is never a branch. Rejected: **truncation with a
warning**, because criterion 5 exists precisely to prevent a caller believing it holds a full RAM
image. Rejected: **`_meta` alone**, because it moves the cliff without removing it. Reversibility:
**reversible** — the cap is a single configurable number.
</decisions_resolved_here>

Two hazards, both already implemented as library code, both now enforced at the proxy seam with
regression tests that fail when the guard is removed.

**Deny-list, two independent layers.** Discovery: task 1's `tools/list` read already filters
`DENY_LIST` names out of the snapshot. Call time: before any forwarding logic runs, check the
requested `params.name` against `DENY_LIST` and return an `isError: true` result whose text names
the tool, states that it crashes the host VICE MCP server, that recovery needs a manual host-side
restart, and that the refusal is permanent. Do this in the proxy explicitly rather than relying on
`call()`'s own refusal, for one concrete reason: the proxy's refusal must be observable without any
network attempt and must produce a well-formed MCP frame, whereas `call()` throws a `ViceError` —
correct behaviour for a library, but one more layer of catch between the hazard and the answer.
Keep both; they are independent layers, exactly as `serverInfo()`/`call()` already are.

**Epoch re-check on every forwarded call.** Call `beginSession()` from `vice.mjs` lazily,
immediately before the first forwarded call, and keep the returned session. Then, per decision D-D,
on every forwarded `tools/call`:

- **Before forwarding**, `readEpoch()` and compare against the recorded baseline. If both are
  `present` and the values differ, do **not** forward: return an `isError: true` result naming the
  baseline epoch, the current epoch, the recorded `pid` and `spawned_at` when available, and stating
  that any work done since the previous call may have hit a different, freshly-booted machine and
  should be redone. Then **adopt the current epoch as the new baseline** so the session remains
  usable — never caching a negative result is criterion 6, and a proxy that reports the same restart
  forever is exactly that cache.
- **After the call returns**, `readEpoch()` again and apply the same comparison, so a restart that
  happened *during* the call is caught too. On a change, return the restart frame rather than the
  call's result: a payload read from a machine whose identity changed mid-call is not trustworthy
  and must not be handed back as if it were.
- If the baseline is not `present` and the current read now is, adopt it silently as the baseline —
  a supervisor merely started, which is not a restart. This mirrors `vice.mjs`'s existing
  "only compare when both are present" rule; do not invent an error for it.
- Catch `MachineRestartedError` thrown from inside `call()` (its own post-reconnect fast path) and
  convert it to the same `isError: true` frame shape, then re-baseline identically. Two layers, one
  observable behaviour.

Do not call `assertSameMachine()` and do not add a `vice_checkpoint_list` probe — decision D-D
records the three reasons, and a state-reading probe would additionally pause the emulated CPU
without resuming it.

Close the last hazard: an oversized result must remain fully recoverable.

Introduce a module constant for the cap — default `500000`, overridable via
`VICE_MAX_RESULT_CHARS` — and export it so task 1's `tools/list` handler declares the *same* number
in each tool's `_meta["anthropic/maxResultSizeChars"]`. One number, one definition: declaring one
ceiling and enforcing a different one would tell the caller a limit it does not have.

After a forwarded call succeeds and its payload has been serialised to text, measure the text's
length. Under the cap, behave exactly as now. Over the cap, split the text into cap-sized chunks
(leaving headroom for the envelope), keep chunks 2..N in an in-memory map keyed by a fresh
continuation token, and return chunk 1 with `isError: false` plus an unmistakable trailing marker
line stating: that this is chunk 1 of N, the total character count, the continuation token, and the
exact tool call to make next. Expose exactly one synthetic tool for that call — name it
`vice_result_continue`, add it to every `tools/list` response with an `inputSchema` requiring a
string `token`, and handle it in `tools/call` by returning the next stored chunk with the same
marker shape, deleting each chunk as it is handed out and dropping the token entirely once the last
chunk is served. Because it is synthetic, `vice_result_continue` is served entirely inside the
proxy: it must never be forwarded to the host, and an unknown or exhausted token returns an
`isError: true` result explaining that the continuation expired and the original call should be
re-issued with a narrower range.

Bound the store so a long session cannot grow it without limit: keep at most a small number of
outstanding continuations (a handful), evicting the oldest, and say in the eviction message that
the original call should be narrowed rather than resumed.

Nothing on this path may silently shorten a payload. There is no truncation branch to write.

  `vice_result_continue` calls until the marker reports the last chunk. Assert the concatenation of
  every chunk's payload portion equals the stand-in server's original payload exactly, and assert

  served from the proxy and never re-forwarded.

- `"tools/list declares the same cap it enforces"` — read the `_meta` value from a `tools/list`
  response and assert it equals the value the child was started with in `VICE_MAX_RESULT_CHARS`.
