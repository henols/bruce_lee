# Phase 01.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Seeded from `01.1-RESEARCH.md` § Validation Architecture.

**Standing environmental fact:** the host VICE emulator was **not running** when this phase was
researched (`ECONNREFUSED` on 6510/6511/6512; supervisor state files absent). The whole point of the
strategy below is that it does **not** depend on that changing: the proxy is a Node process whose
entire observable surface is stdin/stdout frames, so ~90% of this phase is testable with zero network
activity by stubbing the host client. Only criterion 3 needs a live host, and it is a human
checkpoint by construction (see Manual-Only Verifications).

## Sampling Rate

- **After every task commit:** Run `node --test .claude/skills/vice-mcp-selector/scripts/vice-proxy.test.mjs`
- **After every plan wave:** Run the full suite, **plus** confirm the relocated transport modules
  (`vice.mjs`, `vice-sync.mjs`, `vice-pool.mjs`) still pass their own existing test files unchanged
  at their new location — a relocation that breaks a test it did not author is the failure mode here.
- **Before `/gsd-verify-work`:** Full suite green, and the criterion-3 human checkpoint passed
- **Max feedback latency:** ~20 seconds

## Wave 0 Requirements

- [ ] `.claude/skills/vice-mcp-selector/scripts/vice-proxy.test.mjs` — covers criteria 4, 5, 6, 7, 9
      via a spawned-child-process harness (write frames to stdin, assert on stdout). Matches this
      project's convention of testing real process behaviour rather than mocking the module boundary.
- [ ] A stand-in for the host MCP server, so criteria 4–7 and 9 run with no dependency on a live
      emulator. **This is the load-bearing Wave 0 item** — it is what makes the phase verifiable
      despite the host being down. Resolved by the plans (`01.1-01/T2`) as an **in-process
      `node:http` server on an ephemeral loopback port**, with the child proxy pointed at it via
      `VICE_MCP_URL`, rather than a module-boundary mock — `vice-pool.test.mjs` already imports
      `createServer` for exactly this, `vice.mjs` already honours the env override, and this keeps
      the real transport (retry ladder, SSE-body parsing) inside the test path instead of stubbing
      it out. The server records every request it receives, which is what makes the
      "zero outbound requests" and "continuations served in-proxy" assertions provable rather than
      inferred.
- [ ] `vice-mcp-selector-docs.test.mjs` — durable, directory-enumerating completeness check for
      criteria 2, 8 and 9's caller-side half. Modelled on the existing `skill-docs.test.mjs` pattern
      (already used twice in this repo). Must enumerate rather than grep once: a one-shot grep passes
      the day it is written and rots silently.
- [ ] Framework install: **none needed** — `node:test` ships with the installed Node and is already
      used project-wide.
