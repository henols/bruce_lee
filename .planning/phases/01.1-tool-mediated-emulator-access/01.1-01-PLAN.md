**D-A — Which fixed port, and who launches the emulator on it during 1.1.**
Resolution: **port 6510, launched on the host by `tools/vice-supervisor.sh`** (single instance,
crash-supervised). The proxy's default endpoint is whatever `vice.mjs`'s `DEFAULT_ENDPOINT`
already resolves to (`http://host.docker.internal:6510/mcp`), and `VICE_MCP_URL` remains the

a crash then stays dead and its evidence is lost. The proxy takes **no** pool lease: leasing is
1.2's scope. `tools/README.md` § "don't run both a bare supervisor and a pool on 6510" applies.

`vice-proxy.mjs` — the one genuinely new piece of protocol code in this phase. Import `call`,
`serverInfo`, `DENY_LIST` and `activeInstance` from `../../vice-session/scripts/vice.mjs`. That
cross-skill relative import is deliberate and temporary: it is the same shape

Implement the stdio server half spec-literally: read `process.stdin` as UTF-8, buffer, split on
`\n`, and `JSON.parse` one message per line. Answer three methods and nothing else:

- `initialize` — respond with `protocolVersion` echoing the client's requested version when the
  proxy supports it, otherwise the newest the proxy supports; accept at least `2024-11-05` and
  `2025-06-18`; `capabilities: { tools: { listChanged: false } }`; `serverInfo: { name: "vice", version }`.
  Make **zero** HTTP requests here.
- `notifications/initialized` — a notification: consume it and write no response at all.
- `tools/list` — for this tracer only, return the host's list via `serverInfo()` if a
  `VICE_TOOLS_MANIFEST` file path is set and readable, else an empty `tools` array. Task 1 of plan
  `01.1-02` replaces this with the committed snapshot; the tracer needs only enough to prove the
  method is answered without touching the host.
- `tools/call` — extract `params.name` and `params.arguments`, delegate to `call(name, args)`, and
  wrap the outcome in a JSON-RPC **result** whose value is
  `{ content: [{ type: "text", text: <JSON.stringify of the payload, or the payload verbatim when it is already a string> }], isError: false }`.
  Catch every throw from `call()` and return the same result shape with `isError: true` and the
  error's `message` as the text. Per RESEARCH.md Pattern 2, a tool-execution failure is an
  `isError: true` **result**, never a JSON-RPC `error` object; reserve JSON-RPC `error` (code
  `-32601` / `-32602`) for genuine protocol problems — an unknown method or missing `params.name`.

Never-throw discipline, from the first commit rather than retrofitted (this is what finding 7
makes unrecoverable if it is added late): register `process.on('uncaughtException', ...)` and
`process.on('unhandledRejection', ...)` that log to `stderr` and return, never re-throw and never
call `process.exit()`; attach an `'error'` listener to `process.stdout` so an `EPIPE` on write
cannot throw synchronously (this is the exact class of the filed defect
`modelcontextprotocol/typescript-sdk#1564`); wrap each per-line `JSON.parse` so a malformed line
yields a JSON-RPC parse-error response (code `-32700`) instead of a crash. The one exit that IS
correct: stdin `end`/`close` is normal session shutdown — exit cleanly there. "Never exits" means
never on an error, not never at all.

Write only complete JSON-RPC messages to stdout, one per line, newline-terminated, with no
embedded newlines — the spec forbids anything on stdout that is not a valid MCP message. All
logging goes to `stderr`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code → proxy stdin | Untrusted-shaped JSON-RPC lines: a malformed or oversized line must not be able to kill the process, because a dead stdio server is never reconnected (finding 7) and the session loses emulator access for good. |
| host-written files → proxy | `.vice-supervisor/epoch.json` and (later) `tools-manifest.json` are written by a host-side process the container does not control. Contents are untrusted input. |
| proxy → host VICE MCP server over HTTP | The only route out of the container. Everything the agent can make the emulator do passes through here, which is what makes the proxy an access-control point rather than a pass-through. |
| proxy stdout → Claude Code's line parser | A single non-JSON-RPC byte on this channel corrupts framing for the rest of the session. |
