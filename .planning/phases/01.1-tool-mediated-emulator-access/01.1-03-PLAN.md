<objective>
Harden the proxy so nothing can kill it, make an unreachable emulator produce a diagnosis instead
of a timeout, and move container→host path translation from every caller's discipline into the one
seam that sees every call.

Purpose: these three are the criteria that make the proxy trustworthy rather than merely
functional. Finding 7 says a stdio server that dies mid-session is never reconnected, so an
uncaught throw costs the session its emulator access silently and permanently. A generic
"unavailable" message sends the reader to the wrong fix two times out of three. And a container
path handed to a host-side VICE fails *silently* today — the exact failure class this project keeps
rejecting.

Output: a never-throw proxy with tests that prove it; three-state diagnostics that fail fast and
quote a host path; proxy-owned path translation with a loud refusal for the out-of-workspace case.
</objective>

<decisions_resolved_here>
Two decisions land in this plan. Neither is `one-way`, so neither earns a `checkpoint:decision`.

**D-F — Whether the proxy absorbs the pause-on-state-read polling discipline.**
Resolution: **it does not. The discipline stays documented, in `SKILL.md`.** Three concrete
reasons. (1) Absorbing it means the proxy injects a `vice_execution_run` after every state-reading
call — and `vice_execution_run` is this project's leading crash suspect: `STATE.md` records that
host outages 4, 5 and 6 *all* died on it. Multiplying the dominant crash trigger by the number of
state reads is a worse trade than documenting a rule. (2) The discipline is a property of a
*poll loop* — read → run → poll with `ping` → read — spanning several calls; a proxy seeing one
forwarded call in isolation cannot tell a deliberate pause from a poll step without guessing the
caller's intent. (3) Injected, invisible extra tool calls are precisely the "quiet wrong answer"
failure class this codebase keeps rejecting elsewhere. Instead, `SKILL.md` carries the rule forward
in the agent-facing surface's own vocabulary (`mcp__vice__execution_run`, `mcp__vice__ping`).
Reversibility: **reversible** — the injection point would be one place in the `tools/call` handler.

**D-G — How the proxy recognises a path argument, and what happens to an out-of-workspace path.**
Resolution: the **structural rule**, with a loud refusal for the out-of-workspace case. Any string
argument value beginning with `/` is treated as an absolute filesystem path; if it resolves inside
the container workspace root it is rewritten to its host equivalent, and if it does not, the whole
call is refused with an actionable message. Everything else is forwarded byte-identical. Chosen
over a **per-tool argument allow-list** because the host's tool set is not this repo's to enumerate
(`tools-manifest.json` is a snapshot of somebody else's schemas, refreshed on demand), so an
allow-list would silently stop covering a tool the moment the host adds one — and every path a VICE
tool takes is host-side by definition, which makes the structural rule high-precision here in a way
it would not be for a general-purpose proxy. Refusal chosen over **forwarding untouched** because
forwarding is the silent failure criterion 9 exists to eliminate; a container path is never correct
on the host, so passing it along can only produce a wrong answer with no error.
**Stated residual, deliberately not papered over:** a *relative* path string (for example
`recovery/danish/dump.bin`) is left untouched, because a relative-looking string cannot be
distinguished from a non-path argument without guessing, and rewriting a non-path argument would be
a worse failure than not rewriting a path. `SKILL.md` therefore instructs callers to pass absolute
container paths to `mcp__vice__*` tools. Reversibility: **reversible** — the predicate is one
function.
</decisions_resolved_here>
