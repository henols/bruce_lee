## Decisions Made

- **No special-casing for the generic-surface meta-tools.** `tools_call`/`tools_list`/`initialize`/`notifications_initialized` are registered exactly like every other manifest tool — excluding them would itself have been the kind of per-tool branch this plan's own must_have explicitly forbids. This is a deliberate choice to keep the registration mechanism genuinely generic, accepting the pre-existing generic-surface risk as a known, tracked, out-of-scope-for-this-plan cost rather than quietly working around it with a special case that would undermine the "one generic loop, no per-tool block" property this plan exists to prove.
- **The generic-surface deny-list gap is disclosed, not fixed.** See the "Deviations" / "Threat Flags" sections below for the full reasoning. In short: `call()`'s own internal guard (the deepest, un-touched-by-either-plan layer) checks only the outer tool name, so a request to the manifest's own `tools_call` meta-tool carrying `{name: "vice_disk_list", ...}` as a nested argument is not refused by this proxy at any layer — proven identical before and after this swap, not newly introduced by it.
- **`COVERAGE.md`'s `tools/call routing skeleton` row needed a correction, not a rewording.** The original row's claim ("the deny-list, path rewriting and broker leasing wrapped around it stay hand-rolled") was written against the plan-time INTENDED shape (MCPServer routes, hand-rolled logic wraps it) rather than what actually shipped (MCPServer's own dispatch is bypassed entirely for this method). Per this plan's own must_have ("verified against real code, not left as a planning-time artifact nobody re-checked"), the row now states this plainly.

## Carried-forward cost of D-01 (per the coordinator's explicit instruction)

**`tsconfig.json`'s `skipLibCheck: true` (added in Plan 02, unchanged by this plan) is a genuine, permanent reduction in this directory's own type-checking strictness, caused directly by adopting `@mastra/mcp`/`@mastra/core` — not a cosmetic build tweak.** `@mastra/core@1.55.0` bundles internal, vendored `ai-sdk-provider`/`zod-v4` declaration files under `dist/_types/` with real, independently-verified cross-version inconsistencies (missing exports the files themselves reference; `ZodObject`/`ZodArray` generic-arity mismatches). These files are third-party, upstream-owned, and outside this project's control — `skipLibCheck: true` silences TypeScript's default walk of every transitively-imported `.d.ts`, which is the ONLY way to make `tsc --noEmit` pass at all once anything imports from either package. This project's own source was independently confirmed to typecheck clean with or without the flag (a direct `tsc --skipLibCheck` A/B comparison produced zero diagnostics for our files either way), so the flag masks nothing OF OURS — but it does mean this directory's `tsc --noEmit` step can no longer catch a REAL type error inside any future third-party dependency's own bundled declaration files, a protection every other file in this repo (before this phase) implicitly had by virtue of never importing anything with this problem. This is exactly the shape `01.6-RESEARCH.md` §B's HIGH-confidence mismatch rating predicted — a real, measurable, disclosed cost of the D-01 decision, not a hypothetical one — and belongs on the record for whoever eventually revisits whether D-01 should stand, be narrowed further, or be reversed.
