The genuine, disclosed cost: this directory's `tsc --noEmit` step can no longer catch a real type error inside any FUTURE third-party dependency's own bundled declaration files -- a protection every other file in this repo had by default before this phase. This is exactly the shape `01.6-RESEARCH.md` §B's HIGH-confidence mismatch rating predicted. Now recorded in THREE places so a future D-01 reversal decision finds it regardless of which document it opens first: `01.6.3-02-SUMMARY.md` (where it was discovered), `01.6.3-03-SUMMARY.md`'s "Carried-forward cost of D-01" section, and this plan's `vice-proxy.ts` header comment (point (c)) plus this section.

**2. The pre-existing, unwidened generic-surface deny-list gap -- carried to Phase 01.4 criterion 3, not left to a todo nobody reads.** `tools_call` (the manifest's own generic-surface meta-tool, registered like every other tool per Plan 03's deliberate "no special-casing" decision) can carry `{name: "vice_disk_list", ...}` as a nested argument, which is refused by no layer -- neither this file's `CallToolRequestSchema` override (an outer-name-only check) nor `call()`'s own internal guard in `vice.ts` (also outer-name-only, unchanged by either plan). Plan 03 proved this byte-for-byte identical before and after the `@mastra/mcp` swap: the retired pre-swap `handleToolsCall()` had the exact same outer-name-only blind spot, so full-manifest registration made the gap *reachable* (the meta-tool itself was previously unregistered) without *widening* it. `vice_disk_list` crashes the host MCP server; recovery is a manual host restart. Filed at `.planning/todos/pending/2026-08-05-generic-surface-deny-list-gap-tools-call-nested-vice-disk-list.md` and flagged in Plan 03's own "Threat Flags" table. This close-out states explicitly: **this belongs to Phase 01.4 criterion 3's already-recorded open breach concern**, not to this phase's own scope -- closing it for real requires a decision (refuse the meta-tools outright, or teach the deny-list check to parse nested argument shapes) that this registration-loop-scoped adoption phase does not make.

## D-01 Standing: Honest Close-Out Assessment

Per the autonomy contract, an honest account of whether the adoption was worth it, not a formality:

**What the adoption delivered cleanly:** `tools/list`'s schema-conversion dispatch is now genuinely `MCPServer`'s own code (the SDK's `ListToolsRequestSchema` handler, unmodified), proven byte-for-byte identical to the pre-swap wire output across the full manifest (Plan 03). The hand-rolled JSON-RPC framing/protocol-negotiation layer (~140-300 lines, 6-12% of the pre-swap file, matching RESEARCH.md §B4's own measurement) is gone, replaced by `StdioServerTransport`/`Protocol`. This is real, working, adopted library value.

**What did not resolve as the ROADMAP criterion's headline implied:** `tools/call` -- the method this proxy's own hazard discipline (the deny-list, the exact refusal wording, the `{content,isError}` contract) depends on most -- is **not** handled by `MCPServer`'s own dispatch at all (Plan 02's finding, re-confirmed unchanged by Plans 03 and 04). It required a hand-built `CallToolRequestSchema` override because the SDK's own success path forces `isError:false` and collapses chunked results, and its failure path prepends `"Error: "` to messages -- both of which would have broken this proxy's own pinned contract. So "adopt `@mastra/mcp`" resolved, concretely, to "adopt its `tools/list` conversion dispatch and its stdio transport, while re-implementing the one JSON-RPC method that matters most to this proxy's threat model by hand" -- a narrower, more qualified outcome than the phase's own headline criterion suggests, though not a failure: it is a working, fully-tested, disclosed compromise.

**Net assessment:** `01.6-RESEARCH.md` §B rated this fit a mismatch at HIGH confidence, and this close-out does not overturn that rating. The adoption is real but narrow (one wire-transport method genuinely adopted, one method re-implemented by hand to preserve an existing contract), it cost a permanent reduction in type-checking strictness (`skipLibCheck: true`) that has nothing to do with this project's own code quality, and it added a first-ever runtime dependency (69 MB unpacked, 35 direct dependencies) to a project whose CLAUDE.md otherwise holds a strict "no host-side helpers, headless-only, scriptable" bar. Weighed against that: the swap did not regress anything (434/429/0/5 held at every checkpoint across four plans), the ten agent-facing failure strings survived verbatim, the deny-list held, and the rollback (this plan's own deliverable) is now cheap enough that trying this and reverting it would cost roughly one more plan's worth of work, not a redesign. **This reads as a legitimate, working outcome that a reasonable future session could still choose to reverse without regret, not as a mistake that must be undone now** -- which is precisely the "reversible but costly, not one-way" rating the ROADMAP already assigned it, now backed by an actually-written rollback path rather than an assertion that one could be written.
