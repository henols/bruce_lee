## Not covered by this approval — needs a decision before install

**`@mastra/core` ships `posthog-node` as a direct dependency: an analytics/telemetry client.** This
was found *after* the approval was given and the approval therefore cannot be read as covering it.
It is not a legitimacy problem — the package is authentic — it is a design problem for this project
specifically:

- The container's MCP server currently has **zero runtime dependencies** and makes no outbound
  network calls of its own. A telemetry client in the dependency tree ends that property, which is
  the same property criterion D (D-06) exists to protect.
- Mastra's telemetry is normally opt-out via configuration or an environment variable. **Which
  mechanism, and whether it is verifiable from this repository, is unestablished** — it must be
  established in 01.6.3 and not assumed.

**Disposition:** carried into 01.6.3's planning as a required sub-decision of D-06, with three
candidate answers to price — disable by configuration and assert it in a test; bundle in a way that
excludes the telemetry path; or treat it as a reason to reverse D-01 and keep the hand-rolled seam.
None is chosen here.

**This also changes D-06's economics.** "Bundle to preserve the container's zero-dependency-clone
property" was scoped against a small transport seam. The real figure is **~69 MB unpacked across 35
direct dependencies**, including a triple-vendored `@ai-sdk/provider-v5`/`v6`/`v7` set. Bundling that
is a materially different proposition from what the criterion was written against, and D-06 must be
decided against the real number.
