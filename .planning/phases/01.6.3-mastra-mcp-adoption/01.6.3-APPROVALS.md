## The telemetry dependency — disclosed and accepted

> **approved, i have no objections** — developer, 2026-08-04, *after* being shown the
> `posthog-node` finding below in full.

The finding was surfaced before any install and the developer accepted it knowingly. Recorded as a
second, separate approval rather than folded into the first, because the first one was given without
this information and the record should show which facts each answer was given against.

**What is accepted:** installing `@mastra/core@1.55.0` with `posthog-node` in its dependency tree.

**What is still 01.6.3's technical work, not a developer question:** whether the telemetry is
*disabled at runtime* and how that is asserted. The developer's acceptance clears the dependency; it
is not an instruction to leave a telemetry client phoning home from a project whose container MCP
server has never made an outbound call of its own.

### ESTABLISHED 2026-08-04 — the telemetry is not reachable from this project's import graph

This was recorded as "unestablished, must be verified from Mastra's own source, never assumed from
the usual `TELEMETRY_DISABLED` convention." It has now been verified from the published bytes, and
the answer changes the required work.

**Method:** `npm pack @mastra/core@1.55.0 @mastra/mcp@1.15.0` into a scratch directory and read the
published `dist/` trees. **No install, nothing added to this repository, no lifecycle script run**
(both packages have `postinstall: none`, independently confirmed). `npm pack` fetches published
tarballs only.

**Findings:**

1. **`@mastra/mcp@1.15.0` contains zero `posthog`/`PostHog` references anywhere in its package.**
2. **Within `@mastra/core@1.55.0`, `posthog` appears only under `dist/telemetry/`** — `index.js`,
   `index.cjs` and their sourcemaps, plus `package.json` and `CHANGELOG.md`. **No shared/common chunk
   carries it**, which is what closes the transitive question rather than leaving it to inference.
3. **`./telemetry` is a separate export subpath.** `@mastra/core`'s main entry (`dist/index.js`) has
   **zero** telemetry references.
4. **`@mastra/mcp` imports nine `@mastra/core` subpaths and `./telemetry` is not among them:**
   `/agent`, `/auth/ee`, `/base`, `/error`, `/mcp`, `/request-context`, `/schema`, `/tools`,
   `/utils`. Each subpath's resolved entry file was grepped individually for
   `posthog|usage-telemetry|/telemetry` — **all nine returned 0**.

**Conclusion:** the PostHog client is reachable only by explicitly importing
`@mastra/core/telemetry`, which is what Mastra's CLI and playground do. That matches upstream issue
[#3729](https://github.com/mastra-ai/mastra/issues/3729), which reports the leak *"in playground"*.
Nothing in this project's import graph reaches it.

**Evidence:** direct read of published `dist/` trees for both pinned versions, in-container,
2026-08-04. **Confidence: HIGH** for "not reachable via the nine imported subpaths"; the method is a
text grep over published (minified) bundles, so a *computed or dynamic* specifier would evade it —
none was found, and finding 2 makes one unlikely, since a dynamic import would still need the
`posthog` string to appear outside `dist/telemetry/`.

**Consequence for the required work — the default is revised, and it gets stronger, not weaker:**

- **Do NOT rely on `MASTRA_TELEMETRY_DISABLED`.** The variable exists, but
  [#7813](https://github.com/mastra-ai/mastra/issues/7813) (open, assigned) reports telemetry sent
  anyway with `MASTRA_TELEMETRY_DISABLED=1`, and [#6551](https://github.com/mastra-ai/mastra/issues/6551)
  asks for a separate `MASTRA_DISABLE_POSTHOG` because of it. An env var whose own upstream bug
  tracker says it does not work is not a control.
- **Implement instead a structural test asserting `@mastra/core/telemetry` is never imported**, in
  the idiom this repository already uses for exactly this class of guarantee — the skills'
  import-purity test, `HOSTPATH_ALLOW_LIST`'s traced consumer set, and 01.6's statement-anchored
  load-order regex. That is enforced-by-construction rather than observed-once, and unlike the env
  var it cannot silently regress.
- Setting the env var additionally is harmless belt-and-braces, but it must not be the primary
  mechanism and must not be presented as one.

**`@mastra/core` ships `posthog-node` as a direct dependency: an analytics/telemetry client.**
It is not a legitimacy problem — the package is authentic — it is a design problem for this project
specifically:

- The container's MCP server currently has **zero runtime dependencies** and makes no outbound
  network calls of its own. A telemetry client in the dependency tree ends that property, which is
  the same property criterion D (D-06) exists to protect.
- Mastra's telemetry is normally opt-out via configuration or an environment variable. **Which
  mechanism, and whether it is verifiable from this repository, is unestablished** — it must be
  established in 01.6.3 and not assumed.

**Disposition:** the *dependency* is accepted (above). The *runtime disablement* is carried into
01.6.3's planning as implementation work with a stated default, not as an open question for the
developer. Reversing D-01 over telemetry alone is explicitly **off** the table now — that option was
priced against a developer who might object, and they did not.

## D-06 — still undecided, and not covered by either approval

Neither "approved" nor "no objections" addressed D-06 (bundle, or wire `npm install` into
provisioning). It stays a decision this phase must take deliberately, per criterion D's own wording:
*"Either is defensible; leaving it undecided is not."*

**What the approvals did change is D-06's arithmetic.** "Bundle to preserve the container's
zero-dependency-clone property" was scoped against a small transport seam. The real figure is
**~69 MB unpacked across 35 direct dependencies**, including a triple-vendored
`@ai-sdk/provider-v5`/`v6`/`v7` set. Bundling that is a materially different proposition from what the
criterion was written against, and D-06 must be decided against the real number rather than the
imagined one. If planning concludes the decision turns on a developer preference rather than on
measurable cost, it goes to Phase 01.8 as an HV row rather than being taken quietly.
