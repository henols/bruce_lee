## Decisions Made

- **Extend DENY_LIST, don't parse nested arguments.** 01.4-RESEARCH.md's own Pattern 1 ("one array, no new mechanism") and primary recommendation both pointed the same direction; Option B from the originating todo (teach the guard to understand `tools_call`'s own argument semantics) was rejected as unnecessary complexity for a hazard the existing array-based mechanism already closes cleanly.
- **One shared refusal-message function, keyed by hazard shape.** vice_disk_list crashes the host directly; every other DENY_LIST entry is a bypass vector that does not itself crash anything. Reusing one wording for both would tell an agent an inaccurate reason for a permanent refusal (T-01.4-02) — `denyListRefusalMessage()` renders the correct wording per entry, consumed by both call sites (`vice.ts`'s `call()` and `vice-proxy.ts`'s override) rather than duplicated inline text.
- **Close all four generic-surface meta-tools in task 2, not just `tools_call`.** The grep the task itself calls for found zero sanctioned callers for any of the four as tools (only narrative documents and the one test fixture this plan repoints), so partial closure would have left an equally-unused surface open for no benefit — 01.4-RESEARCH.md's primary recommendation was explicit that a partial fix should not be the resting state.
- **Defer the live "after" confirmation rather than fabricate or silently skip it.** The plan's own `<live_confirmation_is_NOT_yours>` instruction anticipated this; empirically confirming it (a third live `tools_list` call after both fix commits landed still returned the pre-fix inventory byte-for-byte) turned a plan-author assumption into a recorded, evidenced fact for the next session, rather than leaving it as an untested claim in the plan's `<done>` criteria.
