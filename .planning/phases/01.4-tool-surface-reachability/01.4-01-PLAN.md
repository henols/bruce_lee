Close Phase 01.4 criterion 3's generic-dispatch hole: `vice_disk_list` is unreachable on the named
tool-call path already, but the manifest's own generic meta-tools (`tools_call`, `tools_list`) can
still carry it as a nested argument, unrefused, per
`.planning/todos/pending/2026-08-05-generic-surface-deny-list-gap-tools-call-nested-vice-disk-list.md`

slice first (`tools_list` alone), then expands to the rest of the generic surface using the exact
same proven mechanism, per Pattern 1 in `01.4-RESEARCH.md` ("one array, no new mechanism").

plan.** The one safe generic-path probe is `mcp__vice__tools_list`; use only that to observe the
current (pre-fix) and post-fix behaviour live.

hazard this project has already paid for once (crashes the shared host MCP server; recovery is a
manual host restart).

Output: `DENY_LIST` extended to close the generic-dispatch surface; matching tests; two live,
in-session before/after observations recorded for Plan 02 to cite when it writes up criterion 2's
"re-established now" requirement.

|----------|--------------|
| agent session -> proxy (stdio MCP) | The agent names any tool by string; the proxy is the only seam that inspects it before the host does. |
| proxy -> host VICE MCP server (HTTP) | Once forwarded, a request is entirely the host's own dispatch — the proxy cannot un-forward it. |
