# Phase 01.4 Plan 03: De-architect agent-visible vice-proxy messages Summary

**Every agent-visible vice-proxy.ts message now uses the `vice:` identity and leads with the required action instead of naming a proxy/broker/host topology the agent cannot see or reach, backed by a permanent regression test.**

## Performance

- **Duration:** ~35 min (base commit 15:12:01Z, final task commit 15:46:56Z)
- **Tasks:** 2
- **Files modified:** 2 (`.claude/mcp/vice/vice-proxy.ts`, `.claude/mcp/vice/vice-proxy.test.ts`)

## Accomplishments

- Re-derived the live set of message-rendering functions directly against the CURRENT `vice-proxy.ts` (13 named functions plus the RESULT_CONTINUE_TOOL description, resolutionNote, chunkMarkerText, the checkpoint-arming hazard renderer, and the internal-error-shape branch) rather than trusting PLAN.md's stale line numbers or its incomplete "swap these three, catch-all the rest" list.
- Swapped every agent-visible `vice-proxy:` prefix to `vice:` across the unreachable-shaped family (broker never-started/dead-or-hung/launch-failed/warming/control-unreachable, host never-started/dead-or-hung/alive-but-rejected, session-must-restart), the path-refusal branches, the chunking messages, and the internal-error branch. Each unreachable-shaped message already preserved its state distinction, an absolute host path, and ended with the shared `ONLY_ROUTE_NOTE` (added by a prior plan) instructing the agent to surface the failure to the user and stop -- no restructuring needed there beyond the prefix.
- Restructured the epoch-drift and replaced-machine family (`epochDriftMessage`, the inline mid-call epoch-drift branch, `machineReplacedMessage`, `replacementFailedMessage`) to lead with the required action (void and redo the work / make the call again / retry once fixed) before the supporting epoch/port evidence.
- Found and fixed one instance PLAN.md's own task list didn't name: `renderCheckpointArmingHazard`'s two production strings contained the bare word "proxy" ("vice-proxy hazard" / "vice-proxy hazard (repeat)") outside any `console.error` call -- in scope under the todo's literal "no string returned as content contains proxy" bar. Reworded to "vice hazard" / "vice hazard (repeat)", with the ~10 test assertions that pinned the old wording co-updated deliberately (same substrings asserted -- presence, repeat-suppression, absence-on-failure -- only the prefix moved).
- Added the permanent structural regression test the plan calls for: a proximity-based grep in `vice-proxy.test.ts` that flags any backtick-opened template literal beginning with `vice-proxy:` that is not immediately preceded by `console.error(`. Verified live: temporarily reintroduced a `vice-proxy:` prefix, confirmed the new test went red, restored the file, confirmed it went green again.
- Full suite: 442 tests / 437 pass / 0 fail / 5 todo (stated baseline was 441/436/0/5; the delta is exactly the one new structural test, and it passes). No `broker-kill.test.ts` flake observed in either full-suite run.
- `npm run typecheck` (`tsc --noEmit`) clean. No diff in `.claude/mcp/vice/resources/` -- expected, since `vice-proxy.ts` is container-side and not part of the host-side `tsc` build tracked by `resources-sync.test.ts` (which is itself part of the passing full suite).

## Issues Encountered

- One test (`vice-proxy.test.ts:2765`, in the containerize-epoch-drift test) pinned `/epoch drift/i` on `epochDriftMessage`'s output. My first rewrite (leading with the void-and-redo action, dropping the phrase "epoch drift" entirely) broke this. Resolved by keeping the phrase "epoch drift" as part of the supporting evidence clause while still leading with the action -- satisfies both the pinned test and criterion 5's ordering requirement. No test or behavior was weakened; this is exactly the "update test and message together, deliberately" guidance the plan calls for, applied by keeping the message (not the test) as the thing that bends.
- The plan's own `<done>` grep for Task 1 (`grep -n '\`vice-proxy:' vice-proxy.ts | grep -v console.error`) returns 5 lines even after this plan's changes, because it is line-oriented and the file's `console.error(\n  \`vice-proxy: ...\`)` call sites split the `console.error(` and the backtick across two lines. The frontmatter truth ("no string ... contains proxy, except inside console.error ... lines") is satisfied; the plan's own convenience grep just can't see across the line break. The new structural test in `vice-proxy.test.ts` uses a 40-character look-behind that correctly spans the line break and reports zero violations.
