for one. The other two are honestly unproven rather than assumed from presence — and the *reasons*
differ (destructive vs. needs a precondition), which a plan can act on.

## Criterion 3 — `vice_disk_list` on the generic path

- **Named path: HOLDING.** `vice_disk_list` is **absent** from this session's tool surface. The
  four-layer deny-list works where it was verified.
- **Generic path: NOT YET PROBED.** `mcp__vice__tools_call` and `mcp__vice__tools_list` **are** present
  in this session — the "four host JSON-RPC meta-methods sitting in the manifest as forwardable tools"
  that `01.4-RESEARCH.md` named. So the generic surface criterion 3 calls out still exists.

**The only safe probe is `tools_list`** (enumeration). `tools_call` with that name must NEVER be used
as a probe — that *is* the hazard: it crashes the host MCP server and recovery is a manual host
restart. Deferred to a 01.4 plan rather than run ad hoc, since the payload is large and the result is
only durable once the phase can act on it.
