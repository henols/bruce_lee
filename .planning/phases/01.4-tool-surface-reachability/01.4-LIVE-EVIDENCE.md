**Verdict (2026-08-05, plan 01.4-02 task 2): criterion 4 is SATISFIED directly.** `mcp__vice__*` was
present in this dispatch's tool surface (task 1's finding above), so the "present" branch of this

**What "satisfied" means precisely, so a later plan does not over-read it:** presence is in the
**deferred** tier, not the directly-callable one. A `gsd-executor` dispatched under
`/gsd-execute-phase` — the shape 01.4-04 and 01.4-05 will both be — can rely on every `mcp__vice__*`
name being reachable, but the first use in a given session needs one `ToolSearch(select:...)` call to
load the specific tool's schema before it is directly callable; skipping straight to calling
`mcp__vice__vice_recycle` (say) without first searching for it would fail with `InputValidationError`,
not with an absence. This is an operational note for 01.4-04/01.4-05 to plan around (budget one
`ToolSearch` call before the first live emulator call of a plan), not a limitation that reopens this
criterion.

**Against the harsher concern this criterion was written for:** the "five tools, zero `mcp__vice__*`

**Phase 01, plan 04** — an earlier phase, a different `gsd-executor.md` frontmatter revision (fixed

independent Phase 01.4 dispatches (`01.4-01`, this plan's own task 1) have now both landed on the
milder "present-but-deferred" shape and neither has reproduced the harsher one. That is enough
