### Gaps Summary

One BLOCKER: the concurrency race the code review filed as CR-01 is real, independently
re-confirmed by direct code reading rather than accepted from the review's narrative alone, and it
sits in the exact code this phase's own Task 1/Defect-5/Defect-3 work introduced and is supposed to
have closed. `selectWarmInstance()`'s post-probe recheck only inspects `record.state`, and the
drop path (a failed grant-time probe) deletes the record from `state.instances` without ever
setting `record.state` to anything other than `"ready"` — so a sibling concurrent
`selectWarmInstance()` walk holding a stale reference to the same record can still return it as a
winner after it has been dropped and is being killed. The resulting orphaned grant's later
`release()` resolves its kill target by current port occupant (`state.instances.get(grant.port)`),
which can by then be an unrelated live instance belonging to a different session — a genuine
cross-session availability/data-loss risk, not a theoretical one, and precisely the "a grant is
proven live before it is honoured and cannot outlive its process" property that Defect 3's
disposition in `01.6.2-VALIDATION.md` (line 474) currently claims, unqualified, is "DISCHARGED
here." No test anywhere in the phase (unit, e2e, or structural) exercises two overlapping
`selectWarmInstance()` calls against a shared candidate with differing probe outcomes, so the gap
was never caught by the phase's own extensive test suite.

This is a BLOCKER because it falsifies one of this phase's own core deliverables (Defect 3's fix,
Defect 5's fix, and the T-01.6.2.1-03 threat-model disposition all rest on the false premise), it
was introduced by this phase's own new code (no shared-pool grant path existed before P-01), and
the fix is well-scoped (the review already supplies the exact patch and a description of the
missing regression test) — this is not a pre-existing, out-of-scope defect being inherited, and no
override has been recorded for it anywhere in this phase's CONTEXT or plans. Recommend routing
back through `/gsd-plan-phase --gaps` for a small closure plan (one map-membership recheck, one
regression test, one review of `handleRelease()`'s kill-target resolution, and a corrected
Defect-3 disposition row in `01.6.2-VALIDATION.md`) before proceeding to Phase 01.4, since Phase
01.4 is exactly where a real concurrent-acquire session would first exercise this path against a
real host.

Everything else in the phase — the five-labelled-tasks/five-tests/separate-commits clause, the
seven-criteria disposition (criterion M), the 35-row carry-forward list naming Phase 01.4 as owner
(criterion E), the D-07 prerequisite gate check, the honest non-live-verification labelling, the
