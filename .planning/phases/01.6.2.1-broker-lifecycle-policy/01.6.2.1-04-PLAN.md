<objective>
Raise the connection-level acquire deadline's default from 25000 ms to ~120000 ms per **P-08**,
disposition Phase 01.5 **criterion 6** as ADOPTED, and close its standalone todo as
done-on-the-successor per **P-09**.

Purpose: this is criterion **L**'s deadline change and one of criterion **M**'s two

the session, so a deadline that fires is expensive in a way it was not when the original todo was
written.

Output: one behaviour commit, a preserved ordering invariant, a re-anchored fail-fast assertion, a

## Plan-time finding: raising this default breaks a landed invariant unless a second file moves

**This appears in no source artifact and CONTEXT does not record it.** Found by grepping the
constant's consumers at plan time.

`vice-proxy.test.ts` carries a passing test named *"ordering: the proxy's own acquire deadline is
strictly less than .mcp.json's timeout"*. It reads the vice server's `timeout` field out of the
repository's own `.mcp.json` and asserts the acquire deadline is **strictly less** than it. That
field is currently **60000**. So a bare raise to 120000 turns a green test red.

The invariant is not incidental and must not be relaxed — the test states its own reason: *"so the
proxy's own warming-and-retry message is always what a waiting caller sees rather than the client's
own timeout."* That is precisely the agent-facing-failure-message concern Phase 01.4 criterion 5
owns.

**Resolution: raise the vice server's timeout field to 150000 in the same commit**, keeping the
invariant true with its reason intact (120000 is strictly less than 150000). The number is
evidence-backed rather than picked: spike-003 measured a 150 s tool call returning a real result and
recorded the default tool-call budget as at least 150 s, so 150000 sits inside proven territory
rather than beyond it. This is why this plan touches a file outside `.claude/mcp/vice/` — a necessary
consequence of a locked decision, not an expansion of scope.

**Second-order finding, same grep.** The same test file asserts that a never-started diagnosis is
fail-fast, with a bound expressed as half the acquire deadline. Anchored to a fraction of the
deadline, that bound moves from 12500 ms to 60000 ms on its own — and the surrounding message-read
deadline is 10000 ms, so the assertion would become unfalsifiable. **P-08 says never loosened.**
Task 1 re-anchors it to an absolute bound.
