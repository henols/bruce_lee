# Phase 01.6.2.1 Plan 04: P-08/P-09 — Acquire Deadline Raised to ~120s, Timeout Todo Closed Summary

**The connection-level acquire deadline's default rises from 25000 to 120000 ms with `.mcp.json`'s own timeout raised in lockstep to keep a landed ordering invariant true unedited, the never-started fail-fast bound is re-anchored from a self-loosening fraction to a fixed absolute value, and Phase 01.5's criterion 6 is closed as adopted-on-the-successor rather than dissolved.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3
- **Files modified:** 5 (2 source/test files, 1 config file, 1 renamed+appended todo, 1 findings log)

## Accomplishments

- Raised `CONTROL_ACQUIRE_TIMEOUT_MS`'s default from 25000 to 120000 in `vice-broker-client.ts` (the `VICE_BROKER_ACQUIRE_TIMEOUT_MS` knob is untouched -- an explicitly configured value still works exactly as before). Recorded the counter-evidence and decision ID (P-08) directly at the constant's own declaration: at the measured sub-second cold-launch boot (spike-003), the old value already implied a cliff far past the instance ceiling, so this raise is robustness headroom for a slow or contended host, not an unblocking of any wave-width constraint.
- Raised `.mcp.json`'s vice server `timeout` field from 60000 to 150000 in the **same commit** -- a plan-time finding (documented in the plan's own objective section, not present in any prior source artifact) that raising the acquire deadline alone would have turned a landed passing test red (`vice-proxy.test.ts`'s "ordering: the proxy's own acquire deadline is strictly less than .mcp.json's timeout"). Chose 150000 because it is spike-003's own measured floor (>=150s tool-call budget), sitting inside proven territory. **Did not edit the ordering-invariant test** -- it passes with its body byte-unchanged, which is the proof the invariant was preserved by moving the *other* side of the inequality, not relaxed.
- Re-anchored the never-started fail-fast assertion. The old expression (`elapsedMs < ACQUIRE_TIMEOUT_MS / 2`) would have silently carried its bound from 12500ms to 60000ms with no change to its own text -- past the test's own separate, hardcoded 10000ms message-read deadline, making the assertion practically unfalsifiable (a real regression would hit that read's own timeout first). Declared a named constant, `NEVER_STARTED_FAILFAST_BOUND_MS = 5000`, satisfying both "at least as strict as the old 12500ms effective value" and "comfortably below the 10000ms read deadline," with a comment stating why a fraction-of-the-deadline bound is a loosening even when the assertion's own text never changes.
- Swept every consumer of the deadline constant across tracked TypeScript (not merely grepping for the literal `25000`): only `vice-broker-client.ts`'s own three call sites (`acquire`, `status`, `hostState`, all via the shared `ACQUIRE_TIMEOUT_MS` alias) and `vice-broker-client.test.ts`'s export-surface test (which checks names only, not values, and stays green unedited). Confirmed `vice-sync.ts`'s `POLL_WINDOWS_MS` array and `vice-proxy.ts`'s `REQUIRED_MAX_MCP_OUTPUT_TOKENS` both contain the literal `25000` but are genuinely unrelated (a poll-window schedule and an output-token budget, not this deadline) -- read both directly rather than pattern-matching the number, and left them alone.
- Closed the standalone grant-poll-timeout todo (`git mv` from `pending/` to `completed/`, one rename in history) with an appended closing note naming both constants: the retired `GRANT_POLL_TIMEOUT_MS` (gone with `pollGrant()` and the whole file-messaging protocol under D-01/D-12) and the surviving `CONTROL_ACQUIRE_TIMEOUT_MS`/`ACQUIRE_TIMEOUT_MS` (a connection-level acquire deadline, a different mechanism). Explicitly overruled `ROADMAP.md`'s own proposed "dissolved" wording in writing, with the reasoning: the value question was not separable from the constant's own deletion, so "dissolved" would read as "we decided not to," the opposite of what happened. Referenced task 1's commit as satisfying the todo's literal ask, and answered the todo's own "what to check while doing it" question (the cross-file coupling task 1's sweep found).
- Logged one dated, graded finding to `RE-FINDINGS.md` (hazard): the cross-file timeout coupling between this deadline and `.mcp.json`, plus the self-loosening fraction-bound assertion, naming the reusable search technique (grep consumers of a constant, not only its literal) and stating honest plan-time provenance.
