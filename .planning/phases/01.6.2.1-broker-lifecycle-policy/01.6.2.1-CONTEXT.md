### Defect 5 — the warm floor nothing reads

- **P-01: Defect 5 is fixed in this phase, as a SIXTH explicitly-labelled task with its own test and
  its own commit.** `vice-broker.mts`'s `handleAcquire()` never consults the warm pool — every
  acquire is a fresh cold launch regardless of how many instances sit ready. Logged into this
  phase's own four-defect list on **2026-08-04**, found while building 01.6.2's test ledger,
  declared outside that plan's scope, and pointed here by name.
  **Criterion L therefore reads "five policy changes + one wiring defect", and criterion M's
  mapping goes from four defects to FIVE.** D-02's four-defect enumeration is superseded by a
  five-row table (see Folded Todos below).
  *Why not carried:* D-06's floor of 1 is justified entirely as *"a spare is only ever a latency
  optimisation"* — with the pool unread that optimisation is provably zero, and 01.5 criterion 4's
  dissolution (P-10) would rest on a predicate no acquire path consults.

- **P-02: the grant path re-probes the instance it is about to hand out.** The floor pass having
  probed live is not carried into the grant — *read-a-record-is-bookkeeping, a
  probe-that-answers-now is evidence*. A failed grant-time probe **drops the record and
  identity-verified-kills the pid**, the same discipline as D-05.
  *Why:* trusting the floor pass reintroduces the Defect 3 window at a shorter timescale — a
  wedged `x64sc` between the pass and the grant gets handed to a session.

- **P-03: a failed grant-time probe walks the remaining ready records, then falls through to a cold
  launch.** Every failure drops + identity-verified-kills as in P-02. Bounded by the acquire
  deadline (P-08). At D-06's floor of 1 there is at most one ready record, so this is identical to
  "try one" in the normal case and differs only on a host deliberately configured to N>1 — where
  walking is what the operator asked for.

- **P-04: Defect 5 is proved by a unit test AND an e2e test against the real spawned broker.**
  Unit: seed one ready instance, stubbed spawn, assert zero spawns and that the grant names the
  pre-warmed port — **red against today's `handleAcquire()`**. E2e: an acquire over the real control
  plane against the real spawned broker is served from the warm floor.
  *Why both:* Defect 5 **is** the failure shape 01.6.2's first verification caught — `maintainWarmFloor()`
  was correctly built and unit-tested while orphaned from the entry point, exactly as
  `withCrashSupervision()` was. A unit test cannot see an orphaned module; the e2e half is what
  01.6.2's gap closure had to add.

### D-05 — the probe

- **P-05: D-05's "in-process TCP connect" wording is AMENDED. The `vice_ping` POST body stays; the
  other two branches retire.** Exactly one in-process mechanism remains, which is D-05's actual
  intent (one check, no external command, no *"pair of indistinguishable states"*), but the body
  proves the emulator **answers** rather than that a port is bound.
  *Why:* the landed code argues against D-05 in its own comment — *"a bare TCP accept is explicitly
  not sufficient (a C64 can accept a connection before it has finished booting)"*. A booting `x64sc`
  that accepts before its MCP server answers would be promoted to ready and handed out.
  **This is a locked-decision amendment and must be recorded as one in writing** — the project's own
  rule: *"A locked decision reversed without a record is the failure mode this project already names
  for confidence grades."*
  — **Reversibility:** reversible.

- **P-06: the collapse deletes the `ProbeMechanism` union and the `no_mechanism` branch outright**,
  together with `maintainWarmFloor()`'s *"warm ZERO speculative spares when no mechanism exists"*
  conditional and `resolveProbeMechanism()`. `VICE_BROKER_PROBE_CMD` retires. This is D-05's
  indistinguishable-states dissolution taken to completion: a deliberate zero floor and a broken
  host can no longer look alike because there is no broken-host branch left.
  **Every landed test that retires must be named in the plan with its reason** — silently deleting
  tests is not permitted, and `broker-launch.test.ts`'s *"warming ZERO speculative spares"* group is
  the known set.
  — **Reversibility:** costly — the union and the branch are deleted, and their tests with them.

- **P-07: the probe timeout default shortens from 5 s to ~1 s; `VICE_BROKER_PROBE_TIMEOUT_S` still
  honours any value.** Measured boot is **~0.65 s** and a live instance answers in milliseconds, so
  5 s is time only ever spent discovering that an instance is wedged — the case D-05 hunts, and the
  case that now sits between a session and its emulator on the grant path (P-02/P-03). Safe because
  `probeReady()` has no retry loop: a slow host is re-probed on the next floor pass, not starved.

### The acquire deadline and the two unsettled 01.5 items

- **P-08: 01.5 criterion 6 is dispositioned as "the constant ceased to exist; its successor is a
  connection-level acquire deadline" — ADOPTED — and the default is raised from 25 s to ~120 s.**
  `VICE_BROKER_ACQUIRE_TIMEOUT_MS` still honours any value.
  *Why raise:* it leaves headroom under spike-003's **≥150 s** tool-call budget rather than racing
  it, and the acquire path can now spend probe timeouts walking stale records (P-03) before it even
  starts a boot. After D-14 broker death is fatal to the session, so a deadline that fires is
  expensive in a way it was not when the todo was written.
  *Counter-evidence recorded, not hidden:* at ~0.65 s boot the 25 s value already implied a cliff
  past `VICE_BROKER_MAX=16`, so this constant bound nothing that MAX would allow. The raise is
  robustness headroom, as the todo itself says — not an unblocking.
  **Any test pinned to 25000 is updated in the same commit, never loosened.**

- **P-09: the standalone todo closes as DONE ON THE SUCCESSOR, not as dissolved.**
  `2026-08-01-raise-grant-poll-timeout-to-match-measured-tool-call-budget.md` moves to
  `completed/` with a note naming **both** constants and why the name changed. Its literal ask
  (25000 → ~120000) is satisfied; recording it as "dissolved" would read as *we decided not to*.
  This **overrides** the ROADMAP's proposed wording, which was written assuming the value question
  was separate from the constant's deletion.

- **P-10: 01.5 criterion 4 (R1/R2 replenish-cap semantics) is ADOPTED as dissolved-by-D-06**, with
  the reasoning recorded. At floor=1 with kill-never-recycle, R1 (*"launch a replacement only if
  zero ready remain"*) and R2 (*"only if total < N"*) collapse into the single predicate the floor
  evaluation already computes — **probe-live ready < floor** — so the `N + outstanding_leases`
  overshoot is structurally impossible. The cap is `floor + outstanding_grants`, bounded by
  `VICE_BROKER_MAX` (untouched).
  **P-01 is what makes this real rather than nominal:** the predicate is now consulted by the acquire
  path, not only by a pass nothing reads.

### D-10 / D-11 — the rename

- **P-11: the rename reaches `broker.json`'s on-disk `spares_target` field.** `broker.json`
  is rewritten by the broker at every start and `readBrokerLiveness()` parses only `pid` and
  `heartbeat_at`, so no consumer breaks — the field is a config echo for a human reading the file,
  which is the audience D-10's rename exists for. Leaving one `spares` on disk while every log line
  says `warm floor` recreates the two-vocabularies confusion that misled a live outage.
  — **Reversibility:** costly — operator-facing, and the break is the point (D-10).

- **P-12: the rename is the LAST commit of the phase**, after all six behaviour tasks. D-11's
  ordering (D-06's behaviour ships while the identifier still reads `VICE_BROKER_SPARES`, rename its
  own commit) extended to the whole phase.
  *Deciding reason:* D-10 is the only decision here rated costly-to-reverse — it breaks
  `VICE_BROKER_SPARES` with no shim. Landing it last means backing it out is one revert; landing it
  mid-phase means backing it out drags four later tasks with it.

- **P-13: the rename commit adds a startup warning naming the retired variable — and no shim.**
  `VICE_BROKER_SPARES` must not affect behaviour (D-10, unweakened: no alias, no fallback, no
  deprecation path). But D-25's **mandatory start-time banner** names it when it is set, e.g.
  *"`VICE_BROKER_SPARES` is set and ignored; use `VICE_BROKER_WARM_FLOOR`."* This closes the one
  failure mode the developer was shown when choosing the clean break — an operator with it in a
  shell profile silently getting the default — without weakening the break.

- **Generated `resources/` is rebuilt and diff-checked** — `node build.ts` then
