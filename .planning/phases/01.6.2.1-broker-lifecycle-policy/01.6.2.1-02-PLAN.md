<objective>
Collapse the readiness probe to exactly one in-process mechanism, per **D-05** as amended by
**P-05**, **P-06** and **P-07**. The ping-shaped request body stays — it proves the emulator
*answers*, not merely that a port is bound. The external-command branch and the
no-mechanism branch retire outright, together with the mechanism union, the mechanism resolver, the
environment variable that selected the external command, and the warm-floor pass's warm-zero
conditional. The probe timeout default shortens from 5 s to ~1 s.

Purpose: this is criterion **L**'s second labelled task and Phase 01.5 criterion 3 / **Defect 3**'s
disposition — *read-a-record-is-bookkeeping, a probe-that-answers-now is evidence*. Plan 01 put the
probe on the acquire hot path, which is what makes the shortened timeout matter: a 5 s timeout is
time only ever spent discovering that an instance is wedged, and it now sits between a session and
its emulator.

Output: one probe, one answer, four named test retirements, a probe-answering stub emulator fixture,
and the P-05 amendment on the record.

## P-05 is an amendment to a locked decision, and this is the record

**D-05 (locked, `01.6.2-CONTEXT.md`) specified the probe as an in-process TCP connect** to the
instance's monitor port with a short timeout. **P-05 amends that: the ping-shaped request body
stays; only the other two branches retire.**

**Why the amendment.** The code that landed in 01.6.2 argues against D-05's own wording, in its own
comment: *"a bare TCP accept is explicitly not sufficient (a C64 can accept a connection before it
has finished booting)."* A booting emulator that accepts before its own MCP server answers would be
promoted to ready and handed to a session — which is Defect 3's failure shape reappearing at a
shorter timescale, on the hot path plan 01 just created.

**What is unchanged.** D-05's actual intent is fully honoured and is what P-06 completes: exactly
one check, no external command, and no *"pair of indistinguishable states"* — because after P-06
there is no broken-host branch left for a deliberate zero floor to be confused with.

**Why this paragraph exists.** The project's own rule: *"A locked decision reversed without a record
is the failure mode this project already names for confidence grades."* This record is duplicated
into the source at the probe itself (task 1) and consolidated into `01.6.2-VALIDATION.md` by plan 06,
so a code reader, a plan reader and an artifact reader each meet it.
</objective>
