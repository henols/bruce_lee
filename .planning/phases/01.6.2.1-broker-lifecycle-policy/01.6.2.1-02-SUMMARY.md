# Phase 01.6.2.1 Plan 02: D-05/P-05/P-06/P-07 — Probe Collapse Summary

**The broker's readiness probe collapses from a three-way branch to exactly one in-process HTTP mechanism, with the ping-shaped both-substrings requirement preserved, the timeout default cut from 5s to 1s, four named test retirements, and the e2e suite migrated onto a probe-answering stub emulator.**

## Performance

- **Duration:** ~55 min
- **Tasks:** 3
- **Files modified:** 9 (7 source/test files, 2 generated resources, 1 findings log)

## Accomplishments

- Collapsed `broker-launch.mts`'s `probeReady()` from a three-branch function (`ProbeMechanism`/`ProbeOutcome`, an external-command branch, an HTTP branch, and a report-ready-unconditionally branch) to a single function returning a bare `Promise<boolean>`. The ping-shaped request body and its both-substrings requirement (`"version"` and `"machine"`) survive unchanged -- this is exactly what P-05 preserves from D-05's original intent.
- Deleted, in full: the `ProbeMechanism` union, the `ProbeOutcome` wrapper, `resolveProbeMechanism()`, `defaultRunProbeCmd()`, the `probeCmdEnv`/`runProbeCmd` seams, the `VICE_BROKER_PROBE_CMD` environment variable (every read, in `broker-launch.mts` and in `vice-broker.mts`'s pass re-entrancy comment), and `maintainWarmFloor()`'s step-2 warm-zero conditional -- step 3's in-flight check is now the first gate after promotion.
- Shortened the probe timeout default from 5s to 1s (P-07), keeping `VICE_BROKER_PROBE_TIMEOUT_S`'s exact coercion behaviour so an operator on a slow host can still raise it. Added a test asserting both halves (default value, knob override) -- none existed before this task.
- Recorded the P-05 amendment to locked decision D-05 directly in `probeReady()`'s own header comment, replacing the old three-branch enumeration: states what D-05 specified, why the landed code's own comment argued against that wording, what P-05 amends, and that D-05's underlying intent (exactly one check, no external command, no indistinguishable states) is fully honoured rather than reversed.
- Reworded `vice-broker-launch.test.ts`'s `JUSTIFIED_NETWORK_CALLERS` entry for `broker-launch.mts` to name P-05 and stop describing the probe as one branch among several; its structural network-caller test still passes.
- Updated both real production read sites of the probe's return value (`maintainWarmFloor()`'s promotion step and `vice-broker.mts`'s `selectWarmInstance()`) from `outcome.ready` to a plain boolean, and updated `MaintainWarmFloorDeps.probe`/`HandleAcquireDeps.probe`/`selectWarmInstance()`'s own deps type to `Promise<boolean>`.
- Migrated both end-to-end tests that used to reach `ready` through the retiring external-command probe (the landed "wired supervision: a warm-floor stub child..." test and plan 01's "wired warm floor: an acquire over the real control plane..." test) onto a new shared fixture, `writeProbeAnsweringStub()`: a small Node-shebang script that reads its own allocated port out of the `-mcpserverport` flag `buildViceArgs()` constructs, binds a loopback HTTP listener on it, and answers every request with both substrings the probe requires -- staying alive indefinitely like `/bin/sleep` did for the fixture it replaces. Every existing assertion in both tests (epoch-advance-by-one, same-port respawn, instance-directory counts, broker-still-running) is unchanged.
- Logged two dated, separately-graded findings to `RE-FINDINGS.md`: a hazard (a liveness check that only proves a port is bound is not a readiness check, MEDIUM -- doc-and-code-derived, confirmable on a real host in minutes) and a dead end / negative finding (the no-mechanism fallback branch was itself the defect, not the mitigation, HIGH -- observed directly in the retired code).

## Retired Tests (P-06's no-silent-deletion rule)

All four were in `broker-launch.test.ts`, immediately below the `probeReady` section header:

1. **"probeReady: prefers the external command when named, passing the port as its own argv element"** -- deleted. Exercised the external-command branch, which no longer exists.
2. **"probeReady: external command failure (non-zero exit) reports not ready"** -- deleted. Same branch, same reason.
3. **"probeReady: with neither mechanism available, reports success unconditionally and logs the reason"** -- deleted. Asserted the report-ready-without-evidence behaviour P-06 removes; this is the test that encoded the "pair of indistinguishable states" D-05 set out to dissolve.
4. **"maintainWarmFloor: a pass with no readiness mechanism at all warms zero instances and logs exactly one line naming why"** -- deleted, together with its environment save/delete/restore dance for the retiring variable.

**Surviving, renamed:** "probeReady: with no external command named, issues an HTTP readiness request and succeeds only when BOTH substrings are present" is now "probeReady: issues an HTTP readiness request and succeeds only when BOTH substrings are present" -- its substance (the both-substrings assertion) is untouched.

Every other `maintainWarmFloor` test in the file injects its floor explicitly through the options bag rather than depending on the default; each was read while making this change and confirmed unaffected beyond the `{ ready, mechanism }` -> plain-boolean stub-return-shape update every stubbed `probe` callback in the file needed regardless (a mechanical, non-semantic change).

- **Removed the `| null` option from `ProbeDeps.httpProbe`'s type**, not merely the `no_mechanism` branch that read it. That escape hatch existed solely to simulate "neither mechanism available"; with the branch gone, keeping the type option would advertise a case the code no longer handles, and the one test that exercised it is one of the four named retirements.
- **Applied the Rule 3 (blocking) fix to `vice-broker-acquire.test.ts`** (see Deviations below) even though it is outside this task's own `<files>` list.
- **Wrote the e2e stub as `.cjs`, not `.js`** -- the package's own `"type": "module"` would force a same-named `.js` file into ESM, breaking its plain `require("node:http")`.
