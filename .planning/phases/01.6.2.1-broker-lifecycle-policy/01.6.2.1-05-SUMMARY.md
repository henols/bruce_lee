## Decisions Made

- **The `reason` field's literal value `"spare"` is out of scope for this rename.** It is an internal discriminator between a request-driven launch (`"acquire"`) and a warm-floor launch (`"spare"`), used identically to how the plan already protects `resolveWarmFloor`/`warmFloor` as "already-correct internal identifiers." Renaming it would touch `broker-control.mts`'s status wire shape (explicitly out of this plan's `files_modified`) and would break an already-landed, unedited test (`broker-launch.test.ts`'s D-07 priority test) that regexes the literal word `/spare/` to confirm the waiting reason is named.
- **The structural gate excludes `*.test.ts` by construction.** A test file legitimately sets/deletes/matches the retired variable's literal name to exercise the banner's own two branches (and the gate's own source must be able to search for the retired field name at all) -- neither is the "a consumer reads the retired variable" risk the gate exists to catch. The plan's own non-test acceptance criteria (comment-stripped grep for a value-read in `broker-launch.mts`/`vice-broker.mts`) already cover the production read sites directly.
- **The gate's retired-field-name literal is built via string concatenation**, not spelled as one token, because the `spares_target` acceptance criterion grants no banner-style exception at all (unlike `VICE_BROKER_SPARES`) -- verified live: the first draft (spelled literally) tripped the plan's own mechanical grep against the gate's own source, requiring this fix.
- **Direct quotations of the retiring bash original are preserved verbatim.** `grant_from_spare()`, `drop_dead_instance_records()`, and the quoted `broker_once()` comment text all name or quote actual bash source; rewording them would misrepresent history rather than retire current vocabulary.
