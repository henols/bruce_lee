## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Node's built-in `node:test`. No third-party runner; none introduced by this phase. |
| **Config file** | None — `node --test` globs `.test.ts` and `.test.mjs` identically (verified live, RESEARCH § Validation Architecture). |
| **Quick run command** | `node --test <path>/<file>.test.ts` — the single new or converted file for the slice in flight (per-slice commands in RESEARCH §E). |
| **Full suite command** | `node --test '.claude/mcp/vice/'*.test.*` — matches both `.planning/config.json`'s `workflow.test_command` and `package.json`'s `test` script (both confirmed live, already correct). |
| **Estimated runtime** | ~54 s for 275 tests. |

> **Baseline for this phase: 275 tests, 270 pass, 0 fail, 5 todo, ~54 s.** Measured live, twice,
> 2026-08-03, `git status --porcelain` clean before and after (RESEARCH §A4). The 5 todo are
> pre-existing checkpoint-dependent stubs, unrelated to this phase's scope. **This supersedes
> `01.6.1-RESEARCH.md §6`'s 247/247 figure**, which was recorded before 01.6.1's plans 05–08 landed
> (`vice-broker-client`, `vice`, `refresh-manifest`, `vice-sync`, `vice-proxy`, `vice-proxy.test`).
> A slice that deletes or redesigns tests must state its new expected total; the arithmetic is
> reconciled at every wave boundary, not assumed.

> **This phase's baseline moves by design.** `vice-broker.test.mjs` (2,685 lines / 61 tests) is
> *redesigned, not ported* (criterion A). Roughly a third of its 61 tests survive as black-box
> protocol tests, a third need a new in-memory observation point, and a third have no port at all
> (RESEARCH §F). A shrinking total is therefore expected — but every deleted test needs a named
> disposition in the plan, not a silent drop.

## Sampling Rate

- **After every task commit:** that slice's own per-file command from RESEARCH §E's wave breakdown
  (e.g. `node --test vice-broker.test.ts`).
- **After every plan wave:** `node --test '.claude/mcp/vice/'*.test.*` — full suite, with the
  test-count arithmetic reconciled against the 275 baseline and the slice's own declared delta.
- **Before `/gsd-verify-work`:** full suite green.
- **Phase gate (beyond a green suite):** the explicit written statement criterion E requires —
  restated under *Manual-Only Verifications* below. A green suite here proves **language and
  structural equivalence only**.
- **Max feedback latency:** ~54 s (full suite); < 5 s (per-slice).

## Wave 0 Requirements

- [ ] **The typed `GrantRecord`/`SpareRecord` state shape and its pure helper functions**
      (RESEARCH §E Wave 0) — none exist yet. Everything else in the phase reads or writes this.
- [ ] **The `launchInFlight` concurrency guard and its required race test** (RESEARCH §C,
      criterion C) — none exists yet. Two concurrent launch requests against a **stubbed** spawn,
      asserting exactly one spawn.
- [ ] **The corrected-identity `verifiedKill()`/`shutdown()` wiring** (RESEARCH §D3) — the *sketch*
      exists (`01.6-RESEARCH.md §D1`); the identity-check correction and its application to this
      broker's new spawn topology do not.
- [ ] **The epoch-file writer (D-04) plus a fixture-captured "matches the current bash format
      exactly" test** — **capture the fixture from the real, currently-present bash-written epoch
      file BEFORE `vice-supervisor.sh` is deleted**, so "contract unchanged" has something concrete
      to diff against. This is order-dependent and irreversible if missed.
- [ ] **`host-scripts.test.ts`'s `EXPECTED_TRACKED_SHELL_SCRIPTS` → the single surviving entry**
      (RESEARCH §A6) — trivial once the deletion lands, must not be forgotten.
- [ ] **The `brokerHostPath()` / `hostLaunchInstructions()` naming-collision fix** (RESEARCH §A6) —
      five known call sites (`vice-proxy.ts:1397` + 3 message builders, `install-resources.ts:145`)
      plus their test assertions (4 hits in `vice-proxy.test.ts`, 5 in `repo-root.test.ts`). No fix
      exists yet. This is the "highest-blast-radius one-line change that appears in no source
      artifact" class the ROADMAP's Phase 01.6 criterion D already named once.
- [ ] **The container-guard / repo-root disposition decision itself** (RESEARCH §A7) — genuinely
      undecided, not merely unimplemented. `lib/repo-root.sh`'s logic must inline into the surviving
      launcher (not a free choice — the shell resolves the root before Node exists);
      `lib/container-guard.sh`'s destination is a real choice.

**Explicitly NOT a Wave 0 gap:** anything requiring a real host-side `x64sc` launch or a live agent
session's tool-surface observation. Both remain structurally unverifiable from this container, as
every prior phase in this milestone has already found.

| Behavioural equivalence of the reshaped broker under a real MCP session | E | **Not available in this phase.** The tool surface an agent sees is not reachable until Phase 01.4 lands | Deferred to Phase 01.4. Recorded here so a green suite is not mistaken for live proof |

> shape, and no live-session verification exists until 01.4. **This phase's green suite proves
> language and structural equivalence only.** Criterion E requires stating this explicitly rather
> than letting a green suite imply otherwise.
