# Phase 01.6.2 Plan 10: The Test Disposition Ledger and Function Disposition Table Summary

**Every one of `vice-broker.test.mjs`'s 61 tests now carries a named disposition (4 REPLACED, 31 RE-OBSERVED, 26 DELETED-with-reason) and every retiring bash function has a PORTED/DELETED/ABSORBED outcome — discharged by reading the retiring file's full 2,697 lines and both bash scripts' current committed function tables directly, which also surfaced a confirmed, previously-unknown gap: the new broker's acquire path never grants from its own warm-instance floor.**

## Accomplishments

- **The test disposition ledger** (Task 1): every one of `vice-broker.test.mjs`'s 61 top-level tests, counted by `grep -c '^test('` and confirmed by reading every test body in full across five sequential line-range passes covering the whole file — no test name was trusted without reading what its body actually asserts. 4 REPLACED (same property, new implementation, mechanism changed from subprocess-spawn to direct import/call), 31 RE-OBSERVED (same property, new in-memory or control-plane observation point), 26 DELETED (subject genuinely gone, reason from one of 14 named classes — the plan-time six plus eight this session's read surfaced and named rather than stretched onto an existing one).
- **The function disposition table** (Task 1): every function in `01.6.2-RESEARCH.md` §B's own table for both retiring bash scripts, checked against the CURRENT committed source and against what this phase's nine prior plans actually built (not what an earlier SUMMARY anticipated they would build). PORTED/DELETED/ABSORBED for every row, `vice-supervisor.sh`'s entire file absorbed wholesale into `broker-launch.mts`'s `superviseChild()` + `broker-epoch.mts`'s `writeEpochRecord()` per D-1.
- **The three anticipated positive findings, stated explicitly** rather than left as silent absences: the vanished start-time dead-record dropper (`drop_dead_instance_records()` — a fresh in-process broker starts empty by construction, so there is no stale record to drop), the dropped `broker-instances.json` projection (D-24: replaced outright by the control-plane `status` query), and the two non-porting CLI flags (`--once`/`--detach` — a long-lived process taking no per-invocation arguments has no equivalent shape for either).
- **A fourth finding, not anticipated at plan time, surfaced by this session's own full-body read and stated with equal explicitness**: `handleAcquire()` (`vice-broker.mts`) never consults `maintainWarmFloor()`'s warm-instance pool at all. Confirmed by reading `handleAcquire()`'s complete body and by grepping every `state.grants.set()` call site in the module (exactly one hit, always immediately following a freshly-spawned `acquirePortAndLaunch()` result, with no branch that promotes an existing `state.instances` entry in state `ready`). `maintainWarmFloor()` itself is correctly built and tested — it launches and promotes instances exactly as designed — but nothing ever consumes them; every acquisition is a fresh cold launch regardless of how many warm instances are sitting ready. Filed as Defect 5 against the existing `.planning/todos/pending/2026-08-01-vice-broker-spare-warming-and-stale-grant-defects.md` (already Phase 01.6.2.1 criterion M's tracking vehicle) and logged to `.planning/WINDOWS.md` (id 3, kind `deviation`). Not fixed here: wiring `handleAcquire()` onto the warm floor is a change to broker acquire logic, outside this plan's declared scope (test files + this validation artifact only), and is arguably an architectural decision rather than a mechanical port.
- **Every ledger claim made real** (Task 2): the two rows whose named replacement did not already exist — row 27 (the promotion log line's elapsed-ms figure) and row 35 (the container-guard exit-code contract against the real emitted broker artifact) — each got a genuine, asserting test written in this plan, not a ledger entry resting on a promise. Both pass; both were found by search in the file the ledger names, recorded row-by-row below.
- **Suite arithmetic reconciled, all three numbers measured live**: 430 tests (424 pass, 0 fail, 1 skipped, 5 todo) measured before this plan's own changes, matching `01.6.2-09-SUMMARY.md`'s recorded baseline exactly; +2 after this plan's own two additions (432/426/0/1/5); −61 when plan 11 deletes `vice-broker.test.mjs`, giving an **expected total of 371** for plan 11 to assert against.
