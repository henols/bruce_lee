## D5.3 — no FIFO fairness

**The developer answered the ordering-key question with free text**, which redirected the phase:

> *"if the server is restarted it shall start as normal and if a mcp is trying to contact a lost
> x64sc and dont get a responce the mcp proxy shall ask the broker to give it a new emulator.
> No file leger"*

Options that had been presented (broker-observed order seeded by mtime / the id's embedded
millisecond timestamp / file mtime alone) were all superseded — the answer rejected the premise that
ordering should be recoverable from disk at all.

A plain-text follow-up asked two things: what the broker does with request files already on disk at
startup, and whether the proxy-side re-ask (Defect 4) lands in this phase. The answer escalated
further — see the next section.

| Unit reproduction suffices; causal claim stays labelled | Keep "this is the mechanism behind random wave failures" marked inferred | |
| Require a live host reproduction first | Blocks on an intermittent event | |

**Notes:** the recommendation was to keep the causal claim labelled inferred; the developer chose
not to. The note (`vice-broker-lifecycle-decisions.md` § 5.3) already carries the "inferred"
