## Pattern Assignments

### `broker-state.mts` (model, in-memory CRUD)

**Analog:** `.claude/mcp/vice/vice-broker.mts` for the never-throw/plain-object idiom; `resources/vice-broker.sh` for the POLICY to preserve.

**Never-throw plain-object check** (`vice-broker.mts` lines 73-77):
```typescript
function isPlainObject(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
```
Reuse this exact predicate shape for any parsing this module still needs to do over protocol files it reads (leases, requests) — per RESEARCH §D2, `grants`/`spares` themselves become typed in-memory maps with NO JSON parsing at all, so this predicate is needed only where the module touches the protocol boundary (leases/requests), not for its own internal state.

**Policy to port exactly (not redesign), from `resources/vice-broker.sh`:**
- `count_launching()` (lines 842-852) → `.filter().length` over the in-memory grant/spare maps — this is THE single most load-bearing function; see `broker-launch.mts` below for the guard it feeds.
- `next_free_port()`/`port_is_blocked()`/`block_port()` (lines 692-739) → a method scanning the in-memory maps plus a `Set<number>` for `BLOCKED_PORTS` (module-level, process-scoped, not persisted — matches bash exactly).
- `count_ready()`/`count_total()` (lines 809-840) → simple `.filter().length` expressions; per RESEARCH §A1, port the CURRENT file-trusting-equivalent behavior (in-memory state's own recorded `state` field), do NOT implement Decision 5.2's "evaluate against probe-live instances" — that is explicitly declined for this phase.

### `broker-launch.mts` (service, event-driven, the concurrency guard)

**Analog:** `01.6.2-RESEARCH.md §C`'s own code block — copy verbatim, it was reasoned directly from the real bash mechanism this session:

```typescript
let launchInFlight = false;

async function tryLaunchOne(reason: "cold" | "spare", port: number): Promise<void> {
  if (launchInFlight) return; // synchronous check, no await since the last set
  launchInFlight = true; // synchronous set -- the pair cannot be interleaved
  try {
    await spawnOneInstance(port, reason);
  } finally {
    launchInFlight = false;
  }
}
```

**Required test (Group C, criterion C):** two concurrent launch requests against a STUBBED `spawn` (dependency-injected, never a real `child_process.spawn` in the test), asserting exactly one spawn occurs. This is a direct regression test for the 2026-08-01 triple-launch outage (§C) — treat as reproducing a real incident, not a hypothetical.

**Pitfall to avoid explicitly (Pitfall 3):** `maintain_spares()`'s bash loop `break`s after the FIRST successful launch per pass (serialised warming) — do NOT "improve" this into `Promise.all()` over several pending launches. Preserve the break-after-first-success shape; the single `launchInFlight` flag mechanically prevents concurrent spawns only if every launch call site (cold-launch AND warming) goes through the SAME guarded function.

**Ordering to preserve exactly** (`broker_once()`, bash lines 1870-1875): `process_requests()` → `sweep_grants()` → `maintain_spares()` → write/derive instances view, in that fixed order, every pass.

### `broker-kill.mts` (service, identity-verified kill/shutdown)

**Analog:** `01.6-RESEARCH.md §D1`'s `verifiedKill()`/`shutdown()` sketch — reuse directly, per Group D's own instruction ("identity-verified kill reused, not re-derived"). Confirmed byte-for-byte against `signal_recorded_pid()` (bash lines 1519-1547: `kill -0` liveness → `ps -o args=` identity → SIGTERM → poll 200ms up to `VICE_BROKER_KILL_WAIT_S` (default 5s) → SIGKILL) and `signal_vice_child_pid()` (lines 1574-1611, same discipline parameterised, returning a stage word `already_exited`/`identity_refused`/`sigterm`/`sigkill`).

**Required adaptation (Pitfall 2, §D3):** the identity-check expected substring changes from the supervisor script's own path to the `x64sc` binary path/name (`VICE_BIN`), recorded at spawn time — because this phase's broker spawns `x64sc` directly with no intermediate `vice-supervisor.sh` process to check identity against. Any lingering string literal containing `vice-supervisor` or `SUPERVISOR_SCRIPT` in the new kill-discipline code is a bug.

**Test analog:** `host-scripts.test.ts`'s SIGHUP test (lines 93-157) — spawn a real, killable stub process (`/bin/sleep`), assert it dies, using `waitFor()`'s poll-to-deadline idiom (lines 62-77), never a wall-clock `sleep`. Reuse `waitFor()` itself if it can be imported, or copy its exact shape.

### `broker-epoch.mts` (utility, D-04 atomic file writer)

**Analog:** `.claude/mcp/vice/vice-broker.mts`'s `writeBrokerRecord()` (lines 118-158) — copy the EXACT atomicity discipline (tmp-in-same-dir, `chmodSync(tmpPath, 0o600)` BEFORE content is written, then `writeFileSync`, then `renameSync`):

```typescript
const tmpPath = `${finalPath}.tmp-${process.pid}-${Date.now()}`;
writeFileSync(tmpPath, "");
chmodSync(tmpPath, 0o600);
writeFileSync(tmpPath, JSON.stringify(record, null, 2) + "\n");
renameSync(tmpPath, finalPath);
```

**Contract to preserve exactly (D-04, unchanged from bash `write_epoch()`, lines 289-306 of `vice-supervisor.sh`):** path `.vice-supervisor/<port>/epoch.json`; fields `epoch` (int, monotonic per-instance), `spawned_at` (ISO 8601), `pid` (the `x64sc` child's own pid — never the broker's own pid, per T-01.3-04), `vice_bin`, `vice_args`, `log`, `dry_run`. `supervisor_pid` — recommend dropping or repointing at the broker's own pid (RESEARCH §D1, Assumption A4: no current consumer reads it).

**Reader analog (do not change):** `.claude/mcp/vice/vice.ts`'s `readEpoch()` (lines 416-439) — already treats this file as untrusted, host-written input (`JSON.parse` in try/catch, `epoch` must decode to a finite integer, unknown fields ignored, never throws). The new writer must not drift from what this existing reader expects.

### `vice-broker.mts` (extended — the long-lived entry point)

**Analog:** itself, extended in place — do not replace `writeBrokerRecord()`, add to it.

**Pitfall to avoid explicitly (Pitfall 1):** the function's own header comment says "DO NOT add heartbeat_at" — that constraint is scoped to the TRACER (writes once, exits) and is WRONG for the real long-lived broker. The real broker MUST add `heartbeat_at`, refreshed every pass, mirroring bash's `write_broker_json()` (lines 924-947), or `readBrokerLiveness()`'s `alive`/`stale`/`never_started` classification (`vice-broker-client.ts` lines 417-430, unchanged) permanently reads a running broker as `never_started`.

**Field set to match/extend:** bash's `broker.json` carries `version`, `written_by`, `pid`, `started_at`, `heartbeat_at`, `spares_target`, `max_instances`, `ttl_seconds`, `poll_ms`, `dry_run`. Update `written_by` to name the TS broker (not `"vice-broker.sh"`, per §A2 — any reasonable new value is safe since no consumer parses that field for anything but a status message).

## Shared Patterns

### Never-throw JSON read
**Source:** `.claude/mcp/vice/vice-broker.mts` `readBrokerRecordMaybe()` (lines 84-97) and `.claude/mcp/vice/vice-broker-client.ts` `readJsonMaybe()` (lines 126-139) — identical two-nested-try/catch shape (one for the read, one for the parse), never throws, treats malformed/missing/non-object as "not there yet."
**Apply to:** every new module that reads a protocol-boundary file (leases, requests) — do not invent a fourth copy of this wrapper; import or structurally match one of these two.

### Atomic write (tmp-sibling → rename)
**Source:** `.claude/mcp/vice/vice-broker.mts` `writeBrokerRecord()` (lines 148-156) and `.claude/mcp/vice/vice-broker-client.ts` `writeJsonAtomic()` (lines 104-109).
**Apply to:** `broker-epoch.mts`'s new epoch-file writer, and any extension of `vice-broker.mts`'s own `broker.json` writer — one atomicity idiom for the whole broker.

### Request-id validation
**Source:** `.claude/mcp/vice/vice-broker-client.ts` line 44, `export const REQUEST_ID_PATTERN: RegExp = /^req-[0-9]+-[0-9]+-[0-9a-f]{8}$/;` and `isValidRequestId()` (line 50).
**Apply to:** the new broker's own request-processing code — `import { REQUEST_ID_PATTERN, isValidRequestId } from "./vice-broker-client.ts"`, never hand-write a new copy (C7's entire deliverable).

### Poll-to-deadline (never wall-clock sleep)
**Source:** `.claude/mcp/vice/host-scripts.test.ts` `waitFor()` (lines 62-77); `.claude/mcp/vice/vice-broker-client.ts` `pollGrant()`/`pollRecycleAck()` (lines 347-401) for the production-code equivalent shape.
**Apply to:** any new test needing to wait for an async condition (spare warming, kill completion) and any production polling logic.
