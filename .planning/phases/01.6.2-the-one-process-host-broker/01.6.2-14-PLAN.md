<objective>
Close both remaining ways a grant can outlive the connection that owns it: a queued acquire whose
client has already disconnected, and a replacement acquisition that overwrites its own grant slot
without releasing what was in it.

Purpose: the connection is the lease in this design, which makes an ownerless grant not merely a
resource leak but a hole in the control listener's authorization boundary — an instance nobody holds,
that nobody can release, occupying a port that can never be reallocated and a capacity slot that can
never be recovered. Both holes are reachable by completely ordinary client behaviour: a caller that
times out on a slow acquire and reconnects, and a session whose emulator stops answering. Neither
needs an adversary and neither is currently tested.

Output: a destroyed-socket check before the launch call rather than only after it, a late-arriving
grant released through the existing release path, a replacement acquisition that releases before it
adopts, and an end-to-end test against the spawned broker artifact that disconnects a genuinely
queued acquirer and counts the instances left behind.

Decisions this plan implements: **D-12** — the connection is the lease, open is the claim and close is
the release, kernel-enforced, which is both why a grant with no live connection has no releaser and
why the fresh-session replacement branch needs no explicit release; **D-13** — a lost machine costs
one acquisition rather than the session, which is only true if that one acquisition does not also
leak the grant it replaces; and **D-14** — broker death gets the same discipline and the same
vocabulary, which is why a failed release is handed to the existing broker-gone branch rather than
given a second failure vocabulary of its own.
</objective>

**Why WR-03 closes without a wire-format change, stated up front because the alternative was the
riskier design.** The code review's own fix sketch proposed a dedicated release-by-id or
recycle-shaped request. That would be a control-plane wire-format change, which this phase rated
one-way and gated behind a blocking decision checkpoint when criterion N introduced the format. It is
not needed: the leak is caused by the proxy overwriting its own single grant slot without releasing
what was in it, and the existing release request — which releases exactly the grant the connection
currently holds — releases precisely the right one, provided it is sent before the slot is
overwritten. Ordering one existing call correctly closes the leak with no new message and no new
door, so that is the design taken.

always-reachable leak: a client that disconnects while queued leaves its entry in the pending

response to be dropped, release the grant instead: invoke the existing release callback with the same
request id and then settle. Do not set the connection's current-grant variable on this path — the
connection is gone and there is nothing to release later. This half bounds the narrow race a pre-check
cannot close: a disconnect landing between the pre-check and the callback's completion. The existing
release callback already kills identity-verified and frees the port and the capacity slot, so nothing
new is needed here beyond calling it.

Write a comment stating plainly which half bounds which failure: the pre-check turns an
always-reachable leak into a bounded race, and the release-on-late-grant turns that bounded race from
