- Added `reapOrphanedInstances()`/`discoverBandProcesses()` (criterion I, D-15): runs on every broker start, before the control listener accepts and before anything is launched, unconditionally -- no marker file records whether the previous shutdown was clean, because a SIGKILLed broker never runs a shutdown path, making that question unanswerable by construction. ## Decisions Made

- **The expected-identity correction was already applied before this plan started.** `verifiedKill()`'s `expectedIdentity` parameter (never a module constant) was already in place from an earlier plan's tracer code, matching the bash original's PARAMETERISED sibling (`signal_vice_child_pid`) rather than its hardcoded one (`signal_recorded_pid`, matched against `$SUPERVISOR_SCRIPT`). This plan's Task 1 therefore focused on building the dedicated test file the plan requires (it did not exist before) rather than changing kill logic -- including the specific hazard test this plan's own `<plan_specific_hazard>` calls for: a deliberately-wrong identity string is asserted to leave the target genuinely alive, not merely checked via the returned stage word.
- **The default `exit` callback calls `process.exit()` only when wired to the real process global.** Discovered live: a long-lived broker's own timers keep it running forever after merely setting `process.exitCode`. Branching on `deps.proc === undefined` lets the real broker actually terminate on a signal while every unit test's injected fake `proc` never risks killing the actual test-runner process. See `RE-FINDINGS.md`'s new entry for the full reproduction.
- **The startup reap's port-band base is read via a small, locally-duplicated env-var reader** (`VICE_BROKER_BASE_PORT`, default 6600) rather than importing `broker-state.mts`'s own `resolveBasePort()`/`DEFAULT_BASE_PORT` -- `broker-kill.mts` is imported directly (unbuilt) by its own test file and by `broker-e2e.test.ts`, so it cannot VALUE-import a sibling `.mjs` specifier (the identical constraint plan 02 already documented for `broker-launch.mts`). The env var name and default are identical, so the two allocators can never disagree about which ports are the broker's.
- **The three task commits were reconstructed as independently-green checkpoints after full implementation and testing**, rather than committed incrementally during authoring -- each commit boundary was separately re-typechecked, rebuilt, and re-tested (not merely re-diffed from a final state) before being committed, so `git bisect` against any of the three lands on a working, self-consistent state.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A long-lived broker never actually exited on a signal -- `process.exitCode` alone is not enough when `setInterval` timers are running**
- **Found during:** Task 2, first live end-to-end signal test against a real spawned broker artifact
- **Issue:** `registerShutdownHandlers()`'s first working version only set `proc.exitCode = code` after killing every instance, mirroring this codebase's own established convention for `main()`'s synchronous argument-parsing error paths ("never `process.exit()`, always `process.exitCode`"). Against a real spawned broker (build the artifact, spawn under bare `node`, send a real `SIGTERM`), the stub children it launched were correctly killed, but the broker process itself never exited -- `child.exitCode`/`child.signalCode` stayed `null` past an 8-second poll deadline. Root cause: `vice-broker.mts`'s heartbeat and poll-pass `setInterval` timers keep the event loop alive for the process's entire life by design; setting `process.exitCode` only determines what code Node exits WITH once the loop naturally drains, and an interval-based server's loop never drains on its own.
- **Fix:** The default `exit` callback now calls the real `process.exit(code)` explicitly, but ONLY when `registerShutdownHandlers()` is wired to the real Node `process` global (`deps.proc` omitted, the real-broker wiring site). A test's injected fake `proc` (a plain `EventEmitter`) never takes that branch, so the unit tests remain safe.
- **Files modified:** `.claude/mcp/vice/broker-kill.mts`
- **Verification:** The three end-to-end signal tests (`SIGTERM`/`SIGINT`/`SIGHUP`) all pass: both stub children gone AND the broker itself exits with code 0, within deadline
- **Committed in:** `82134fe` (Task 2 commit)
- **Also logged:** `.planning/RE-FINDINGS.md`, dated 2026-08-04, HIGH confidence (reproduced live in this container)

**2. [Rule 3 - Blocking] `TS2322` type errors from an overly-strict `ProcessLike#once` listener parameter type**
- **Found during:** Task 2, first typecheck after adding the `EventEmitter`-based test stand-in
- **Issue:** `ProcessLike#once`'s listener parameter was initially typed `(...args: never[]) => void`, which is not assignable from `node:events`' own `EventEmitter#once` listener signature (`(...args: any[]) => void`) -- a real `EventEmitter` instance failed structural assignability to `ProcessLike` at every test call site.
- **Fix:** Widened `ProcessLike#once`'s listener parameter (and the internal `registrations` array's element type) to `(...args: any[]) => void`, matching `EventEmitter#once`'s own declared shape exactly, with a comment explaining why the looser type is deliberate here (compatibility with a real `EventEmitter`, not a general relaxation).
- **Files modified:** `.claude/mcp/vice/broker-kill.mts`
- **Verification:** `npm run typecheck` exits 0
- **Committed in:** `82134fe` (Task 2 commit)

**3. [Rule 1 - Bug] Two escalation-ladder unit tests initially asserted `identity_refused` instead of `sigkill` because the injected fake never passed the identity check**
- **Found during:** Task 1, first run of the injected-clock escalation tests
- **Issue:** The tests injected `isAlive: () => true` and a fake `sleepMs`, but did not override `readProcessArgs` -- so `verifiedKill()`'s REAL default `readProcessArgs` ran a genuine `ps -o args= -p 4242` against a pid that does not exist, returning an empty string, which failed the identity check (`args.includes(expectedIdentity)`) and returned `"identity_refused"` before the escalation logic was ever reached.
- **Fix:** Added `readProcessArgs: () => "x64sc"` to both tests' injected deps, so the identity check passes and the escalation ladder actually runs.
- **Files modified:** `.claude/mcp/vice/broker-kill.test.ts`
- **Verification:** Both tests pass, asserting the exact `["SIGTERM", "SIGKILL"]` kill sequence and `[200, 200, 200]` sleep sequence against the injected clock
- **Committed in:** `1a3ec1b` (Task 1 commit)
