# Phase 01.6.2 Plan 13: Split the Deliberate-Death Marker Into Recycle vs. Release Summary

**`vice_recycle` now respawns for real on the same port through the supervision loop plan 12 wired in, and `vice_release` provably does not — the two are now distinguished by a shared setter and a structural gate rather than by accident, proved end-to-end against the real spawned broker artifact.**

## Accomplishments

- Narrowed `InstanceRecord.deliberateKill` (`broker-state.mts`) to mean exactly "the broker ordered this death," and added a new, separate `respawnAfterKill` field answering "should a replacement follow" — the field name is kept unchanged per the plan's own directive (five rows of `01.6.2-VALIDATION.md`'s disposition ledger cite it by exact test name).
- `broker-launch.mts`'s `handleExit()` now splits its `deliberateKill` branch in two: a `respawnAfterKill: true` death relaunches on the SAME port through `launchSupervised()` **directly** — no crash accounting, no backoff wait, no doubling, and the pre-kill crash history/backoff carried forward unchanged — reporting a new `"recycled"` outcome word; a pre-kill `granted` state is restored on the fresh record so the warm floor's own ready-count numerator never mistakes a recycled session's own machine for an available spare. Absent or false behaves exactly as before.
- `vice-broker.mts` gains one shared setter, `markDeliberateDeath(instance, respawnAfterKill)` — the only place either field is ever written — called **before** the kill in both `handleRecycleForRealBroker()` (true) and `handleRelease()` (false). The recycle handler no longer needs to delete the grant or instance entry (it never did, in fact — that part of its behaviour is unchanged), and its header comment now describes the wired behaviour (marks and kills; the exit handler performs the actual relaunch) instead of disclaiming relaunching.
- The `vice_recycle` tool description (`vice-proxy.ts`) was checked clause by clause against the now-wired behaviour — killed, respawned, in place, same port, via the supervision loop, restart epoch changes — and found already accurate. No wording changed.
- A region-scoped structural gate in `broker-control.test.ts` holds the marker-before-kill ordering and the two opposite respawn answers permanently, following the same region-scoping technique the file's own pre-existing source-order structural tests use.
- Five new unit tests in `broker-launch.test.ts` cover the recycle branch's three deliberate differences from the crash path, the final-death branch, and the companion both-kinds invariant test the assumption-delta decision adopted.
- Two new end-to-end tests in `broker-e2e.test.ts` prove both directions against the real spawned broker artifact under bare `node` (`VICE_BIN` stubbed to `/bin/sleep`): a recycle over the real control plane respawns on the same port with the epoch advanced by exactly one and the ack's `epoch_before` field carrying the recorded integer; a release does not, across at least two configured evaluation passes.
- One dated entry appended to `.planning/RE-FINDINGS.md` at discovery, append-only, on the one-boolean-two-questions hazard this split closes.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Both new end-to-end tests initially found an unrelated auto-warmed spare colliding with their own port-count and pid-stability assertions**

- **Found during:** Task 3 (writing the "wired recycle" and "wired release" end-to-end tests)
- **Issue:** `maintainWarmFloor()`'s own "no mechanism -> warm zero" branch (`broker-launch.mts`) only fires when NEITHER `VICE_BROKER_PROBE_CMD` nor an HTTP mechanism is available -- and Node 24's global `fetch` is always available, so `resolveProbeMechanism()` resolves to `"http"`, never `"no_mechanism"`, by default. With the default warm floor (`VICE_BROKER_SPARES=3`) left unconfigured, the real broker auto-launched a speculative spare during both new tests' own wait windows: the recycle test observed two instance directories (`["6600","6601"]`) instead of one, and the release test observed the freed port 6600 reused by that auto-warmed spare, rewriting `epoch.json` at the same path with an unrelated pid and failing the "pid must not change after a release" assertion.
- **Fix:** Both `startBroker()` calls for the two new tests now set `VICE_BROKER_SPARES: "0"`, isolating each test's own acquire/recycle/release scenario from any auto-launched spare. Explained inline in both tests' own comments.
- **Files modified:** `.claude/mcp/vice/broker-e2e.test.ts`
- **Verification:** Both tests re-run individually and as part of the full `broker-e2e.test.ts` file (twice, to rule out flakiness) with the fix in place — all pass.
- **Committed in:** `1f5211c` (Task 3 commit)
