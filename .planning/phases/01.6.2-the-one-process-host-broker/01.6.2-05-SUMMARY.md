## Accomplishments

- Completed `broker-control.mts`'s message set: `recycle` resolves the requesting connection's OWN held grant only (a mismatched `target_id` answers `denied` without ever touching the kill discipline, so an injected signal recorder stays empty), reads the emulator child's pid from the in-memory instance record, kills it identity-verified through plan 04's `verifiedKill()`, and answers an acknowledgement field-for-field the same nine business fields the retiring bash writer emitted. `status` and `host_state` answer on demand from the in-memory `BrokerState` (D-24) -- neither response ever carries the capability token
- Added the arrival-ordered pending-acquire structure (`enqueueAcquire`/`drainPendingAcquires`): an acquire arriving while a launch is already in flight is queued and answered on the next evaluation pass instead of being refused, with `handleAcquire()` now answering a discriminated `AcquireOutcome` (`at_capacity` checked before the port allocator is ever touched; `no_free_port`/`launch_in_flight` passed through). The queue is a plain array (`splice` to snapshot, `push` to re-queue) with zero `sort()` calls anywhere in the file -- verified by a dedicated structural test
- Grew `broker.json` to its final fourteen-field set (D-27, criterion G): `spares_target`, `max_instances`, `base_port`, `poll_ms`, `dry_run` added; the bash original's `ttl_seconds` field is gone entirely, not renamed. `started_at` is fixed once, before the listener even attempts to bind, and threaded unchanged through every heartbeat refresh. A liveness round trip drives the UNCHANGED container-side `readBrokerLiveness()` over a real running broker's own record (alive) and a hand-built stale-heartbeat record (stale), proving the field this broker writes is the field that consumer reads
- Closed CR-01 (criterion K), an independently-verified blocker carried since Phase 01.2: the control listener now binds before the discovery record is written, making a well-known TCP port's kernel-enforced bind-once guarantee the actual singleton authority. On `EADDRINUSE`, `broker.json` arbitrates through a locally-duplicated liveness classifier and takes exactly one of two distinct paths -- a record classified `alive` exits quietly (status 0) as a second instance; `stale`/`never_started` fails loudly, naming the port and what to check. Both outcomes are proven against REAL listeners on ports discovered at runtime (collision-free), asserting the discovery record is byte-identical before and after
- **Removed, not merely extended**, the tracer/plan-04-era refuse-to-clobber pre-check (`readBrokerRecordMaybe` + `pidIsAlive` at the top of `run()`) -- it could never distinguish a live broker legitimately holding the port from an unrelated live process sharing a reused pid with a stale record, and it answered non-zero even for a genuinely live broker (the wrong outcome under criterion K's two-outcome requirement). Two of `vice-broker-launch.test.ts`'s own tests that exercised the OLD mechanism directly were replaced with tests proving the new one supersedes it (a pre-existing record naming this test's own live pid no longer blocks a restart by itself -- only a real bind conflict does)
- `startControlListener()` split into `bindControlListener()` (bind only, no protocol) and the protocol-wiring step, so a test can occupy a real port with something that never speaks this broker's wire format at all -- exactly the loud singleton path's own fixture
