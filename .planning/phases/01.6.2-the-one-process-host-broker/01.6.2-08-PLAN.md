<objective>
Make a lost machine cost one acquisition rather than the session, and tell the agent plainly. When a
granted emulator stops answering, acquire a replacement immediately but fail the triggering call
loudly, naming that the machine was replaced and that prior state is gone. Give broker death the same
discipline and the same vocabulary.

Purpose: a memory read served silently against a blank machine returns zeroed RAM as if it were real,
which is exactly the hazard the epoch check exists to catch — and a notice buried inside a successful
payload is easy to skim past. This is also the fix for the recorded defect where a proxy cached a dead
grant for the whole session with no re-request path. Broker death gets the same treatment as an
accepted, knowing regression: today it is survivable because the only remaining broker dependency
after a grant is a file write whose failure is a silent no-op; after this transport it is not.

Output: two new failure disciplines in the proxy, both riding the existing machine-restarted
vocabulary, both tested against a real listener.
</objective>

  <action>
Turn the granted-instance-unreachable path from a report-and-instruct into a replace-and-report.

When the pre-flight probe finds the session's granted instance unreachable, acquire a replacement
immediately over the control session the proxy already holds, using the same acquire and the same
grant containerizer the ordinary acquisition uses, and adopt it through the same adoption seam. One
code path for adopting an instance, no second one for replacements. Re-baseline the epoch before
returning, or the next call is refused by the drift guard against a baseline that is stale by
construction.

Then fail the triggering call. Not a result with a warning appended: an error. The reasoning is
already recorded and must be preserved in the message's own comment — a memory read served silently
against a blank machine returns zeroed RAM as if it were real, which is precisely the hazard the epoch
check exists to catch, and a notice buried in a successful payload is easy to skim past. Name three
things in the text: that the machine was replaced, that the replacement is a fresh emulator, and that
all prior state on the old one is gone. Then name what the agent should do, which is simply to make
the call again.

Reuse the existing voided-run vocabulary rather than paralleling it. The existing machine-restarted
error already carries the identities compared, where in the pipeline the check ran, and the last tool
call attempted, and the existing epoch-drift message already words a void in this project's own
idiom. Build the replaced-machine report from those, so a reader meeting it recognises the same
discipline rather than learning a second one. Do not introduce a second notion of a recoverable or
voided run.

Bound it: exactly one replacement attempt per triggering call. A replacement that itself fails
returns a report naming both the original unreachability and the failed replacement, and does not
retry — a retry loop against a broker that cannot grant is how a single failure becomes a hang.

Do not break the never-cache-a-negative-result invariant. No sticky flag saying the instance was
unreachable, no early return keyed off a previous failure. The next call re-probes from scratch,
because the call after a human fixes something must just work with no session restart. That invariant
has its own comment naming exactly the edit that would break it; read it before writing.

Update the affected tests in the proxy test file and add coverage for every behaviour above, driving a
real control listener that answers a second acquire with a different port. Assert the failure and the
following success as two separate facts in the same test, which is the only way to prove the cost was
one acquisition rather than the session.

Give broker death the same discipline as a dead emulator, and record what it costs.

When a forwarded call finds the control connection gone, attempt to open a fresh session. If one
opens, acquire a fresh instance, adopt it and re-baseline exactly as task 1's replacement path does —
reusing that path rather than writing a second one — and return the replaced-machine report, so the
agent learns the same three facts by the same words. If a fresh session cannot be opened, return a
report stating that the session must be restarted and naming the broker as the cause, and say plainly
that no further call in this session can succeed until the broker is running again.

Record in the source, where a later reader meets it, that this is an accepted knowing regression.
Today broker death is survivable: after the grant the proxy's only remaining broker dependency is a
file write whose failure is a silent no-op, and the emulator is a separate process under its own
supervisor. That property is given up deliberately, not overlooked — the tolerance decision was made
explicitly, and the compensation is that a session is told rather than left to produce quietly wrong
results.

Keep the broker-absent triple firing on its own paths. Those messages answer whether the broker is
reachable at all, before a session exists; broker death answers what happened to a session that had
one. Both need to keep saying what they say, and neither replaces the other. Say so in a comment, the
way the existing three message families already document their own boundaries.

Do not cache either report. A following call attempts a fresh session from scratch, so the call after
a human restarts the broker just works. This is the second path the never-cache invariant now governs
and it is the one most likely to attract a short-circuit later.
