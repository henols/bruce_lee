# Phase 01.6.2 Plan 14: Close Both Remaining Ways a Grant Can Outlive Its Connection Summary

**Two destroyed-socket checks close the broker-side disconnect-while-queued leak, a release-before-acquire ordering closes the proxy-side replacement leak, and a real Node.js event-loop starvation hazard discovered while proving the first fix live is closed with a targeted, minimal yield in the port allocator.**

## Accomplishments

- `broker-control.mts`'s `attemptAcquire()` gains two destroyed-socket checks, each closing a DIFFERENT failure and named as such in the source comment: a pre-check BEFORE `onAcquire()` is ever called (closes the always-reachable leak — a client that disconnects while queued no longer causes the next drain pass to perform a real, ownerless launch), and a release-on-late-grant branch on the success path (a grant that settles after its own socket is gone is released through the existing `onRelease()` callback rather than silently dropped, bounding — never claimed as eliminating — the narrower race between the pre-check and `onAcquire()`'s own completion).
- `vice-proxy.ts`'s `handleGrantedInstanceUnreachable()` now sends `session.release()` before `session.acquire()` on the same-session replacement attempt, clearing the module-level `grantId` slot in between — closing the leak where a replacement acquisition abandoned the grant it was about to overwrite (the proxy's own grant slot is a single value). No new control-plane message: the existing release request already releases exactly the grant the connection currently holds. Because `session.release()` closes the underlying connection (D-12), the same-session acquire that follows always finds it already gone and falls through the EXISTING broker-gone (D-14) branch — accepted deliberately, per this plan's own acceptance criteria.
- A new end-to-end test (`broker-e2e.test.ts`) proves the disconnect-while-queued fix against the real spawned broker artifact: a contiguous run of loopback listeners pre-occupies the port allocator's own scan-band base, making the queueing window wide by construction; the test asserts its own precondition explicitly (one connection served, the other queued with no response) and fails with a diagnostic rather than passing silently when it does not reproduce.
- **Deviation, recorded live:** building that end-to-end test exposed a real, test-independent liveness gap in `broker-state.mts`'s `nextFreePort()` — a scan against many in-use candidates starves the control listener's ability to service ANY other connection (not merely a competing acquire) for the scan's entire duration, because Node drains its microtask/nextTick queue fully after every I/O callback and the shipped `EADDRINUSE` probe never yields to the poll/check phase. Fixed with a periodic `await new Promise(setImmediate)` yield, covered by a new targeted unit test, verified against the full existing `broker-state.test.ts` suite before and after.
- Two region-scoped structural tests in `vice-proxy.test.ts` hold the release-before-acquire ordering and the fresh-session branch's own stated reason for needing no release, permanently.
- One pre-existing test (`vice-proxy.test.ts`) whose mock could only reach the same-session "broker refuses the replacement" branch — now unreachable by this fix's own construction — was updated to exercise the actually-reachable fresh-session failure instead.
- Two dated entries appended to `.planning/RE-FINDINGS.md` at discovery: the make-the-window-wide-by-construction technique, and the EADDRINUSE-starves-the-event-loop hazard plus its fix.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical Functionality] `nextFreePort()`'s scan starved the control listener's ability to service ANY other connection for the scan's entire duration**

- **Found during:** Task 2 (writing the "wired disconnect-while-queued" end-to-end test)
- **Issue:** The literal "widen the port scan" technique did not reproduce a queued second connection at all, at any candidate count tried (60, 80, then 500 in an isolated repro). Root-caused with three minimal, isolated Node.js repros varying one thing at a time: `net.Server.listen()`'s `EADDRINUSE` failure settles its Promise without ever yielding to libuv's poll/check phase, and Node drains the microtask/`nextTick` queue completely after every I/O callback before considering the next ready file descriptor — so a `for` loop of `await`s that all resolve this way runs to completion as one unbroken unit with respect to every OTHER socket on the process, including an already-established, already-warmed connection with no data-delivery jitter of its own. This is a genuine, test-independent liveness gap: during a contended scan, a release/recycle/status request over an UNRELATED connection would be held up for as long as the scan takes, not merely a competing acquire.
- **Fix:** `nextFreePort()` (`broker-state.mts`) now yields via `await new Promise((r) => setImmediate(r))` every few scan candidates — negligible added cost against the real bind-and-release round trip each candidate already pays. Confirmed to fix the end-to-end test's own precondition reproduction (verified by toggling the fix on and off against the same test) and covered by a new, narrowly-scoped unit test in `broker-state.test.ts`.
- **Files modified:** `.claude/mcp/vice/broker-state.mts`, `.claude/mcp/vice/broker-state.test.ts`, `.claude/mcp/vice/resources/broker-state.mjs`
- **Verification:** Full existing `broker-state.test.ts` suite (11 pre-existing tests) re-run and confirmed passing both before and after the fix; the new unit test passes; the end-to-end test's own precondition reproduces reliably across repeated runs with the fix in place, and was confirmed to fail (both the precondition check AND, when Task 1's own pre-check is additionally reverted in a scratch copy, the instance-count assertion) without it.
- **Committed in:** `9f0a5d7` (Task 2 commit)

**2. [Rule 1 - Test correction] Updated a pre-existing test whose mock could only reach a branch Task 3's own design makes unreachable**

- **Found during:** Task 3 (writing the release-before-acquire ordering and its structural tests)
- **Issue:** `vice-proxy.test.ts`'s pre-existing "D-13: a replacement acquire the broker itself refuses..." test mocked the fake broker to refuse the SAME-SESSION replacement acquire with `at_capacity`. Since `session.release()` now runs before `session.acquire()` on that same session, and `release()` closes the connection (D-12), the same-session acquire that follows ALWAYS finds the connection gone (`broker_gone`) and never reaches the fake broker a second time over that session — this specific mocked scenario is unreachable by this fix's own construction, exactly as anticipated by this plan's own acceptance criteria ("the existing broker-gone branch still handles a dead connection").
