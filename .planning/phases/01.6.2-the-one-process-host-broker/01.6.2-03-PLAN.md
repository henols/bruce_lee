<objective>
Absorb the per-instance supervisor wholesale: the epoch-file writer with its contract held to the
frozen bash fixture, the crash-respawn loop with its backoff and its crash-loop give-up, and the
per-instance boot and crash logs a human still reads.

Purpose: criterion B keeps the epoch file as one of exactly two on-disk survivors, with its format,
location and semantics unchanged and only its writer moved. That file's whole value is a liveness
check costing zero emulator traffic, and the container-side reader is not changing — so a drift in
the writer silently stops every session seeing valid epochs. D-23 keeps the log artifacts because
their inputs are still read by a human: the 2026-08-01 outage's three-way outcome table came
straight out of one of them.

Output: `broker-epoch.mts` complete with a fixture-diff test, and the launch module grown into a
real per-child supervisor with respawn, backoff, give-up and logging.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| broker → epoch file → container | The broker writes a record the container reads as untrusted, possibly half-written input on its own schedule |
| emulator child → broker | Child exit status and output cross into the broker's respawn decision and its log files |
| operator configuration → spawn | Binary path, argument string, backoff and crash-window values are operator-supplied |
