<objective>
Make `vice_recycle` do what its own tool description promises: kill this session's emulator and bring
it back on the same port, through the supervision loop plan 12 wired in. Make release keep doing the
opposite, and make the difference explicit rather than accidental.

Purpose: the recycle handler kills and returns. Its own header comment says relaunching is the
per-child supervisor's concern — a defensible sentence only while a per-child supervisor is actually
wired in, which until plan 12 it was not. Meanwhile neither the recycle nor the release path sets the
deliberate-death marker before signalling, which was harmless only because no supervisor existed to
misread it: with plan 12 landed, every release would now be read as a crash and respawned, breaking
kill-never-recycle for the whole broker. So the marker work and the recycle work cannot be separated,
and the two paths want opposite answers to the question the marker currently conflates.

Output: one broker-ordered-death marker meaning exactly what its name says, one separate field
answering whether a replacement follows, a recycle that respawns on the same port without spending
the crash budget, a release that stays gone, and end-to-end proof of both against the spawned broker
artifact.

Decisions this plan implements: **D-04** — the recycle's respawn advances the per-instance epoch
record by one under its unchanged contract, which is what the existing container-side epoch guard
turns into a machine-restarted signal for the session that asked for the recycle; and **D-23** — the
respawned instance keeps writing its boot and crash log at the same per-instance path, so a recycle
leaves the forensic trail a human reads intact rather than starting a new one somewhere else.
</objective>

The recycle relaunch differs from the crash relaunch in three specific ways, each for a stated
reason, and each must be observable in a test:

- **No crash accounting.** Pass the pre-kill record's crash history forward unchanged rather than

  make the floor under-warm and would present a session's own machine as an available spare.
