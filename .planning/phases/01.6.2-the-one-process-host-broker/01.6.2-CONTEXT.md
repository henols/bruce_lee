<domain>
## Phase Boundary

One TypeScript process, running on the host, owns broker coordination, per-instance supervision and
the warm pool. It holds its coordination state in memory, speaks to the container over **one TCP
control connection per session whose lifetime is the lease**, and leaves exactly one shell script in
the repo.

**Five lifecycle-policy defects are fixed as part of it**, not translated forward. **Phase 01.5's
defect scope folds in. Phase 01.7's transport change folds in.** The file-messaging protocol
(`requests/`, `grants/`, `leases/`, `denials/`, `recycle-acks/`, `spares/`,
`broker-instances.json`) **ceases to exist** — two files survive: `broker.json` as the bootstrap
record and the per-instance `epoch.json`.

**Out of scope, explicitly:** cross-project brokering (D-16); the tool-surface work and live-session
verification that Phase 01.4 owns; the Bruce Lee reconstruction itself, which this subsystem only
carries.

### The five lifecycle-policy changes

- **D-05 (D5.2 — probe-live floor, the proven defect): the floor is evaluated over probe-live instances, never over a recorded `ready` state.**
  The probe is an **in-process TCP connect** to
  the instance's monitor port with a short timeout — not the bash `VICE_BROKER_PROBE_CMD` external
  command, which **retires**. Retiring it also dissolves the note's "pair of indistinguishable
  states": a deliberate zero-warm-floor config and a broken host with no `curl` no longer look
  identical. A failed probe **drops the record AND attempts an identity-verified kill** of the
  recorded pid (criterion D's discipline, so a recycled pid is never the victim) — because a failed
  probe does not prove the process is gone, and a wedged `x64sc` still holds a GPU context, an audio
  handle and a port. Probed on **every floor evaluation, no cache**.
  **Permitted-route note, stated explicitly because the project rule demands it:** the probe is
  **host-side broker code**. `mcp__vice__*`-only governs *container-side* code reaching the emulator;
  the broker is the process that owns the emulator's lifecycle and already probes today via
  `probe_ready()`. **No test may open a real connection — every probe, launch and kill test is
  stubbed and no `x64sc` runs.**

- **D-06 (D3 — warm floor 3 → 1): the default becomes 1; the knob still honours any N.** The
  `start [N]` argument and the env knob keep working, so the 2026-08-02 host-validation path stays
  reproducible without a code change. Evidence: waves arrive as a millisecond burst so spares 2..N
  buy nothing; `x64sc` is not headless (GTK3 window + OpenGL 4.6 context + PulseAudio handle each);
  a machine is never shared, so a spare is only ever a latency optimisation — and boot was
  **measured sub-second on 2026-08-02 (~0.65 s upper bound)**.

- **D-07 (D5.1 — launch priority): priority is layered on the lock and is NON-PREEMPTIVE.** An
  in-flight boot **always completes** — never killed, never abandoned — and when it reaches ready, a
  waiting request takes it **regardless of which reason booted it**. Priority governs only which
  reason wins the launch slot when it frees: request-driven before warming.
  **The single `in_flight` owner must not weaken** (criterion C; RESEARCH Pitfall 3; the 2026-08-01
  three-simultaneous-`x64sc` SEGV). Preemption was considered and rejected precisely because a
  kill/relaunch overlap re-creates the concurrent-spawn window that outage came from.
  — **Reversibility:** reversible.

- **D-08 (D5.3 — FIFO fairness): arrival order is order of receipt on the control connection.**
  The original defect — glob-lexical iteration over `req-<pid>-<ms>-<hex>` filenames — **cannot
  exist** once requests are messages rather than files. The broker keeps an in-memory arrival-ordered
  queue. **No file ledger, and no reconstruction of queue order from disk** (developer, 2026-08-03).
  The FIFO guarantee is scoped to one broker lifetime; a restarted broker starts clean and recovery
  is pull-driven from the container (D-13).

- **D-09 (supersedes PD-05): the shutdown-deletion question is dissolved, not answered.**
  PD-05 decided that `requests/`, `leases/`, `denials/` and `recycle-acks/` survive shutdown as
  container-owned protocol state. Under D-01 **those directories never exist**. Nothing to delete,
  nothing to reconcile. Recorded so a reader meeting PD-05 in the agenda knows why it no longer
  applies.

- **D-10 (D6 — rename): the ready pool becomes the `warm floor`; the knob becomes `VICE_BROKER_WARM_FLOOR`.**
  `spares` denoted the entire ready pool while reading as "extras beyond
  what is in use," and misread as such during a live outage. The rename reaches **everything that
  survives** — the knob, internal function and type names, and every log line. `spares/` the
  directory dissolves on its own under in-process state.
  **`VICE_BROKER_SPARES` breaks cleanly — no alias, no deprecation shim.** An unknown env var is
  simply ignored. *(The developer was shown the failure mode — an operator with it set in a shell
  profile silently gets the default — and chose the clean break.)*
  — **Reversibility:** costly — operator-facing name, and the break is the point.

- **D-11: D-06 and D-10 land in SEPARATE commits.** The behaviour change ships while the identifier
  still reads `VICE_BROKER_SPARES`; the rename is its own commit. A bisect over a later regression
  attributes to one or the other, never both.

### Transport — the merged Phase 01.7

- **D-12: all six file-lease mechanisms retire together.** `startHeartbeat()`, the
  mtime-as-heartbeat convention, `file_mtime_epoch()`, `lease_is_stale()`, `sweep_grants()` and the
  180 s TTL. The connection **is** the lease: open is the claim, close is the release, enforced by
  the kernel — including on SIGKILL and including container death. Keeping any one of the six means
  two competing authorities on "is this lease alive."
  — **Reversibility:** one-way — the file protocol and its client are deleted, not disabled.

- **D-13: a dead emulator fails the triggering call loudly, with the replacement already in place.**
  When a proxy's granted emulator stops answering, the proxy acquires a fresh instance from the
  broker **immediately** — but the call that hit the dead emulator returns an **explicit error**
  naming that the machine was replaced, that this is a fresh emulator, and that all prior state is
  gone. The next call runs on the new instance and succeeds.
  **Why not auto-succeed:** a `vice_memory_read` served silently against a blank machine returns
  zeroed RAM as if it were real. That is the exact hazard the epoch check exists to catch, and a
  notice buried in a successful payload is easy to skim past. This is the fix for **Defect 4**
  (*"proxy caches a dead grant for the session's life"*), which folds in with Phase 01.5 per D-02.
  Reuse the existing `MachineRestartedError` / `assertSameMachine()` path (`.claude/mcp/vice/vice.ts`);
  do not invent a second vocabulary for the same situation.

- **D-14: broker death gets the same discipline as a dead emulator.** 01.7's criterion 5 is an
  accepted, knowing regression — today broker death is survivable (after the grant the proxy's only
  broker dependency is `touchLease`, whose failure is a silent no-op); after this it is not. The
  proxy reports the session must be restarted, or acquires a fresh instance where possible, using
  the same fresh-machine signal as D-13.

- **D-15: reap-on-startup is unconditional and bumps every epoch.** A restarted broker sees zero
  connections and would otherwise conclude every emulator is free and hand a live one to a second
  proxy. Unconditional because a SIGKILLed broker never runs a shutdown path, so "was the last
  shutdown clean" is unanswerable — a marker file would itself be the class of file-based liveness
  claim this phase retires. The void rides the existing epoch mechanism into `MachineRestartedError`.

- **D-16: cross-project brokering is OUT OF SCOPE — do not even check.** 01.7's criterion 7 was
  marked explicitly optional by the developer on 2026-08-02; on 2026-08-03 they took it out
  entirely. `.planning/todos/pending/2026-08-01-make-the-broker-cross-project-via-shared-home-dir-state.md`
  stays in the backlog, untouched.

- **D-17: CR-01 closes here — the `EADDRINUSE` singleton guard.** `01.2-REVIEW.md`'s CR-01 is an
  independently-verified blocker carried since Phase 01.2: two concurrent brokers race in
  `grant_from_spare()` and can hand the same ready spare to two sessions. A well-known listen port
  cannot be bound twice, so the guard is kernel-enforced for the cost of binding it.
  **Verify it actually holds rather than assuming it** — two brokers on different ports are still two
  brokers, so `broker.json` must be the arbiter of which port is the broker's.

### Ports

- **D-18: three distinct bands, and the control port is load-bearing.**

  | Band | Use | Notes |
  |---|---|---|
  | Control plane | The broker's own TCP listener | **Fixed default, well clear of both other bands**, overridable by env for a genuinely colliding host. `broker.json` records the port actually bound so a proxy always finds the right broker. |
  | 6510–6599 | **Reserved by convention for an `x64sc` a human launches for their own work** | The reported problem: the broker must not squat a port a human wants. Also sidesteps the previously-recorded VS Code `127.0.0.1:6511` collision. |
  | 6600+ | Broker-allocated emulator instances | `VICE_BROKER_BASE_PORT` moves from **6510 → 6600**. A clearly separate band so the two uses cannot be confused and the human range has room to grow. Costs: every existing log line, doc string and test fixture naming 6510 must be re-checked. |

  **The singleton guarantee holds only while the control port keeps its default.** Two brokers
  deliberately configured onto different ports are two brokers and no code can prevent that — state
  this in the plan rather than implying the guard is unconditional.

  **On `EADDRINUSE`, `broker.json` arbitrates and there are two distinct messages:** if it names a
  live broker (pid alive, heartbeat fresh) → exit quietly as a second instance, the guard working as
  designed. If it says `never_started` or `stale` → the port is held by something that is not a
  broker → **fail loudly**, naming the port and what to check. Conflating these lets a squatted port
  masquerade as a healthy singleton, permanently and silently.
  — **Reversibility:** costly — the emulator band appears in fixtures, logs and operator docs.

- **D-19: equivalence is dropped as the frame; verification is against specification.** With the

  **The genuinely-unchanged set is named separately and held to real equivalence:** the emulator data
  plane (the proxy still dials the granted port directly — 01.7 criterion 3), the `epoch.json`

  moves), and the agent-facing tool surface.
  **Criterion E's wording must be replaced, not merely annotated** — a reader must not meet a
  sentence claiming structural equivalence for a deliverable that replaced the protocol.

- **D-20: no blanket fails-against-old test requirement.** PD-06's original bar (*every change needs
  a test that fails against the OLD behaviour*) is dropped as a general rule — it is incoherent
  where no old behaviour exists to run (the transport, D-08, D-17) and follows naturally from D-19.
  **What survives from PD-06, unchanged: each of the five changes still lands as its own
  explicitly-labeled task with its own test, never blended into a generic "convert
  `vice-broker.sh`" line item.** And two specific tests were chosen on their merits during this
  discussion and stand as chosen:
  - **D-06's proof:** an idle-state test against a stubbed spawn asserting exactly one warm instance,

  - **D-05's proof:** a stale-record replacement test — seed a `ready` record whose process does not

  - **D-08's proof:** a direct FIFO assertion — inject N acquires in a known order, assert grants
    come back in that order.
  - **D-07's proof:** criterion C's race test (two concurrent launches, stubbed spawn, exactly one
    spawn) and the priority test are **two separate tests in separate waves**, C green before the

### Operational surface

- **D-23: the supervisor's log artifacts survive; its scripts do not.** Decision 1 of the design note
  named an open question it refused to answer — `vice-supervisor.sh` has a standalone non-MCP
  recovery pipeline over its crash logs and epoch files. **Answer:** the pipeline's scripts are
  already gone (D-02 in `01.6-CONTEXT.md` deleted `vice-pool.mjs`/`vice-session.mjs` behind a
  zero-consumers gate), but its **inputs are still read by a human** — the developer had
  `.vice-supervisor/6510/logs/x64sc-20260803-171513.log` open in the editor during this discussion.
  The broker keeps writing **per-instance boot/crash logs under `.vice-supervisor/<port>/logs/` and
  `epoch.json`, same paths, same format**. The 2026-08-01 outage's three-way SEGV/exit-1/exit-0 table
  came straight out of one of those files; that forensic trail is not given up.

- **D-24 (OQ-1): `broker-instances.json` is dropped; status becomes a control-plane query.** It was a
  pure projection with no confirmed consumer. With state in-process and a control plane in place,
  "what instances exist" is a message the broker answers on demand — strictly better than a file that
  can go stale. Delete the file and its tests; add the status query to the control-plane message set.

- **D-25 (OQ-3): detaching stays the operator's job; the broker warns loudly at start.** No
  `--detach`, no setsid recursion dance — the launcher stays thin per Decision 2 and C6, and running
  detached is the operator's own `nohup`/`setsid`/systemd choice. **A mandatory start-time banner
  names exactly what a Ctrl-C or a closed terminal will destroy.** On 2026-08-02 a `^C` produced
  `reap saw 4 recorded instance(s), terminated 4` and killed a live session; after D-14 broker death
  is fatal to every session, so the warning matters more than it did. The incident was not caused by
  missing machinery — it was caused by nobody being told.

- **D-26 (OQ-4): `broker.json`'s `written_by` stops claiming `"vice-broker.sh"`.** No consumer parses
  it beyond a status message (`readBrokerLiveness()` reads only `pid` and `heartbeat_at`), so any
  reasonable value is safe — but the current one is false. Exact string is the planner's to pick.

- **D-27: `broker.json` gains the control port and keeps its full field set.** It is the discovery
  record (01.7 criterion 2), read once, so `ECONNREFUSED` is never ambiguous.
  **The single most important thing to get right, and the easiest to carry forward wrong:** the
  Phase 01.6 tracer `vice-broker.mts` **deliberately omits `heartbeat_at`**, with its own comment
  explaining why — correct for a tracer that writes once and exits, **actively wrong** for a
  long-lived broker. The real broker MUST refresh `heartbeat_at` every pass, or
  `readBrokerLiveness()` classifies a running broker as `never_started` forever. `node_version` must
  survive into the real broker — it is literally criterion C1's deliverable, and it is what clears
  the 01.6 / 01.6.1 unsealed-on-a-host-side-truth blocker.
