<objective>
Turn the single-pass broker into a real daemon, and make its teardown path singular.

Purpose: the sweeper is mandatory but rarely exercised — the proxy is SIGKILLed ~490ms into every
graceful teardown, and container or host death runs nothing in-process at all. A sweeper that is a
second code branch rots untested and then fails on the day it matters. Making graceful release and
TTL sweep converge on identical code means the rare path *is* the common path.

Output: a `start`/`stop`/`status` daemon with a backoff loop and a clean signal trap, one
`teardown()` reached from two triggers, a TTL sweeper with logged staleness, kill-never-recycle
enforced by a test, and a request-id pattern that cannot drift between the two languages.
</objective>

    All driven from `vice-broker.test.mjs` via `--once --dry-run` against a temp directory, so no
    real `x64sc` and no live host are involved:

    - A grant whose lease file is absent is torn down: the grant file is removed and the pass logs a
      reason naming the released trigger.
    - A grant whose lease file exists with a fresh mtime survives the pass untouched.
    - A grant whose lease file exists but is older than `VICE_BROKER_TTL_S` is swept: the broker
      removes the lease itself, then tears the grant down, and logs the observed staleness in
      seconds alongside the configured TTL.
    - The released case and the swept case leave **identical** resulting directory state — same files
      present, same files absent — differing only in the logged reason. This is the assertion that
      makes "exactly one teardown path" checkable rather than asserted.
    - A grant recording a supervisor pid whose `ps` output does not name the supervisor script is not
      signalled: the pass logs a refusal naming the pid and the mismatching argument string, and the
      grant is still removed so the protocol does not wedge on an unkillable stale entry.
    - A lease refreshed to `now` between two passes is never swept, no matter how many passes run.
    - `stop` with no `broker.json` present exits 0 with a message rather than failing.
    - `status` with two recorded instances prints one line per instance naming its port and state.
  </behavior>
  <action>
    Generalise plan 01's single teardown branch into the two-trigger, one-implementation shape, and
    give the script its real daemon lifecycle.

    Extract `teardown(id, reason)` as the single function that: reads the grant's recorded supervisor
    pid once; verifies `ps -o args= -p "$pid"` names `$SUPERVISOR_SCRIPT` and signals with
    `kill -TERM` only on a match, logging a refusal naming the pid and the observed argument string
    on a mismatch; removes `grants/<id>.json`; drops the instance's entry from
    `broker-instances.json`; and logs a single line carrying the id, the port and `reason`. Removing
    the grant happens on both the matched and the refused path — a stale entry that cannot be killed
    must not wedge the protocol, and a refusal is already logged loudly.

    Add `lease_is_stale(lease_path, ttl_seconds)` comparing the lease's mtime against now. Use
    `stat -c %Y` with a `stat -f %m` fallback so the check works on both GNU and BSD `stat`, since
    the broker runs on the host rather than in this container. In the loop body, iterate the granted
    ids and branch exactly as RESEARCH Pattern 2's pseudocode does: lease absent → `teardown "$id"
    "released"`; lease present but stale → `rm -f` the lease first, then `teardown "$id" "swept
    (stale ${age}s, ttl ${VICE_BROKER_TTL_S}s)"`. The sweep branch converting stale-but-present into
    missing before calling `teardown` is what makes the two triggers converge; do not give the sweep
    its own kill or its own grant removal.

    Add the daemon lifecycle. `cmd_start` validates `[N]` as an integer 1..16 (default from
    `VICE_BROKER_SPARES`, itself defaulting to 3), records `broker.json` once with `pid`,
    `started_at`, `spares_target`, `max_instances`, `ttl_seconds` and `dry_run`, then enters
    `broker_loop`: a `while true` that refreshes `broker.json`'s `heartbeat_at` through the atomic
    helper, runs one `broker_once` pass, and sleeps `VICE_BROKER_POLL_MS` — with the same
    consecutive-failure backoff shape `vice-supervisor.sh` already uses, so a transient filesystem
    error slows the loop rather than killing it. Register `trap cleanup INT TERM` where `cleanup`
    removes `broker.json` and exits 0, leaving granted instances alone: the broker stopping is not
    the same event as a session ending, and killing live sessions' emulators on operator Ctrl-C would
    be a surprise. `--once` short-circuits `broker_loop` to a single pass and returns, which is what
    every test drives.

    Add `cmd_stop`, which reads `broker.json`, verifies the recorded pid's `ps` output names this
    script before signalling it, and reports plainly when there is no `broker.json` to act on. Add
    `cmd_status`, printing the broker's own liveness line (pid, heartbeat age) followed by one line
    per `broker-instances.json` entry naming its port, state and lease id — the reporting shape
    `vice-pool.sh`'s own `cmd_status` uses.

    State the file-permission precondition rather than inheriting it (D-1.2-D). The existing
    `registry.json` is mode `0600`, which works only because the container's `vscode` and the host's
    own user are both uid 1000 on a real ext4 bind mount — so either side can create and unlink the
    other's files. Keep that posture for the broker's own protocol files rather than widening it
    defensively for a multi-user scenario that does not exist here, and record uid-parity in the
    script header as an explicit, named precondition of the whole design, with the consequence if it
    is ever violated (the broker running as a different host user cannot read the proxy's leases, and
    every acquisition silently times out). A precondition that is written down is checkable; one that
    is merely true today is a trap.

    Add `write_instances()` and a `read_instance_field()` reader following the
    grep-and-sed-against-known-shape idiom `read_registry_ports`/`read_registry_pids` already use, so
    `broker-instances.json` needs no `jq` either. **The broker writes `broker-instances.json` and
    must never write `registry.json`** — that file is `vice-pool.sh`'s, read by `vice-pool.mjs`'s
    `acquire()` on behalf of the standalone recovery pipeline, and a second writer would hand
    recovery-pipeline callers broker-owned instances, breaking kill-never-recycle and reintroducing
    exactly the cross-session contamination this phase exists to remove.

    Close C8 and complete C2's validation half.

    In `vice-broker.sh`, make the kill-never-recycle rule structural rather than incidental. When
    `teardown` removes an instance entry it must not leave that entry in any state a later grant can
    select; the only way an instance becomes grantable is by being launched and then proven ready. Add
    a short comment at the removal site recording why: on-demand beat the fixed pool because a newly
    launched emulator is a known-clean power-on state, a warm spare keeps that property only while it
    has never been used, and recycling a released instance rebuilds the fixed pool while keeping none
    of the benefit. State that this is the one rule not to relax for efficiency, and that the test
    named in the acceptance criteria fails if it is.

    Harden the request scan. Skip any request whose id fails the allow-list pattern before that id
    reaches any path construction, logging a refusal that names the offending id in a quoted form.
    Skip any request whose JSON body does not yield the fields the grant needs, logging its path and
    the missing field, and continue the pass — the queue must survive one bad entry. Neither case
    writes a denial file, because a denial is keyed by id and an id that failed validation is not
    safe to build a path from.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared bind mount → host broker | Request files and lease mtimes are untrusted input driving process kills and launches |
| host broker → host process table | The broker signals pids it recorded earlier, which may have been recycled |
| broker state → non-MCP pool callers | `registry.json` is read by `vice-pool.mjs` on behalf of the recovery pipeline |
