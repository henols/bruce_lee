# Phase 01.2 Plan 01: On-Demand Broker Tracer Summary

**A host-side one-shot bash broker plus a container-side protocol client wire vice-proxy.mjs to acquire a VICE instance on the first forwarded tools/call and release it on all five session-ending paths, proven end-to-end against an in-process stand-in with no host emulator involved.**

## Performance

- **Duration:** ~100 min
- **Completed:** 2026-07-31
- **Tasks:** 2 (Task 1 tracer; Task 2 TDD comprehensive coverage)
- **Files modified:** 8 (4 created, 4 modified)

## Accomplishments

- `resources/vice-broker.sh`: a host-only, bash, one-shot broker (`--once`) that reads pending `requests/*.json`, allocates the next free port, writes an atomic `grants/<id>.json` (or spawns a real supervised instance outside `--dry-run`), and tears down any grant whose `leases/<id>` has gone missing -- identity-verified via `ps -o args=` before signalling, exactly like `vice-pool.sh`'s own `cmd_stop`.
- `vice-broker-client.mjs`: the container-side protocol client -- request-id generation/validation (`req-<pid>-<ts>-<hex8>`), atomic tmp+rename writers for requests and leases, `touchLease()`/idempotent `releaseLease()`, a poll-to-deadline `pollGrant()` that never throws on a malformed or truncated grant/denial file, three-way `readBrokerLiveness()` classification, and an unref'd heartbeat timer.
- `vice-proxy.mjs`: `ensureBrokerLease()` acquires on the first forwarded `tools/call` only (never `initialize`/`tools/list`), redirects `vice.mjs`'s transport seam via `useInstance()` on a grant, and re-baselines the epoch check against the granted instance. The shutdown block is replaced by an idempotent `onTeardown()` wired to both measured ladders (SIGINT first on the graceful path; stdin `end`/`close` on the abrupt path), removing the file's only `process.exit()` call.
- 44 tests across three files (14 isolated client-unit tests, 1 broker-script integration test, 29 proxy tests including 11 new for this plan) plus the 18 pre-existing proxy tests all pass with zero host emulator involvement.

## Decisions Made

- **`releaseLease()` swallows a missing lease file.** Task 2's own behavior spec ("a silent no-op") required this; Task 1's "one unlinkSync and nothing else" constraint is about async-safety (no promise/timer/subprocess), not about forbidding a synchronous try/catch. Discovered via a genuine RED test (`releaseLease(): a silent no-op on a missing lease file` failed with an uncaught ENOENT against the Task-1 implementation), closed in the GREEN commit.
- **Every proxy test's cleanup `kill()` became `kill("SIGKILL")`.** Registering `process.on("SIGTERM", ...)` (required by this plan) suppresses Node's default SIGTERM-terminates behaviour; a bare `kill()` in a test's `finally` block no longer ends the child, leaving a dangling stdio pipe that hangs the whole test file. Verified directly: a standalone script confirmed a registered SIGTERM handler leaves the process alive after `kill -TERM`. This is a non-assertion change (documented inline in the test file) required by this plan's own teardown redesign, not a pre-existing bug.
- **`vice-pool.test.mjs`'s `RESOURCES_DIR` entry list updated.** A hardcoded assertion enumerating every file under `resources/` broke the instant `vice-broker.sh` was added there -- a direct, in-scope consequence of this plan's own change, fixed rather than left red.
- **N (the `start [N]` positional) validated but not yet wired to `VICE_BROKER_SPARES`.** Kept as CLI-shape parity with `vice-pool.sh`'s own `start N` for plan 02's future warm-spares loop; the env var `VICE_BROKER_SPARES` is read independently (and can legitimately be `0` in this task, since no spares logic exists yet).
- **Argument-shape validation (including `N`'s range check) moved BEFORE the container guard** in `vice-broker.sh`, deliberately deviating from `vice-pool.sh`'s own ordering, so a usage error (`start 17`) is reported without requiring `VICE_SUPERVISOR_ALLOW_CONTAINER=1` -- confirmed against this plan's own acceptance criteria, which test `start 1`/`start 17` with no escape hatch set.

## Issues Encountered

- **`vice-broker.sh`'s marker-comment collision.** The `TEARDOWN-REGION-END` source marker in `vice-proxy.mjs` was initially also mentioned in prose inside the `BEGIN` marker's own explanatory comment, so `indexOf("TEARDOWN-REGION-END")` found the wrong (earlier) occurrence and the test-side region slice was ~100 characters instead of the whole handler. Reworded the prose to avoid repeating the literal marker string; confirmed fixed by inspecting the sliced region directly before re-running the test.
- **CONTAINER_WORKSPACE_PATH resolves outside this worktree.** `repoRoot()`'s documented precedence (`CONTAINER_WORKSPACE_PATH` first, when `from` resolves inside it) means any `.mjs` entry point run from *inside* a git worktree under `.claude/worktrees/<id>/` still resolves the repo root to the shared devcontainer mount's main checkout (`/workspaces/bruce_lee`), not the worktree — a pre-existing, documented behavior (see `vice-mcp-selector-docs.test.mjs`'s own comment on this exact hazard), not something this plan changes or needs to fix. One stray `tools/vice-broker.sh` deployed into the main checkout during manual CLI testing was removed by hand; a second copy deployed into this worktree's own `tools/` during automated test runs is correctly gitignored (verified via `git status`) and was left in place as harmless, disposable output.
