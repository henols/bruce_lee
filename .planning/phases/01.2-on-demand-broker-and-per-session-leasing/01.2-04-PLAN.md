<objective>
Hide cold start behind N boot-fresh, never-used spares, without ever handing out a machine that has
not proven itself usable.

Purpose: a TCP accept can happen before the C64 finishes booting. Advertising a spare on
`port_in_use()` alone presents as a flaky emulator rather than as a race, which in this project is
the expensive kind of bug — a half-ready machine corrupts a capture and every provenance verdict
downstream of it. Warm spares are a latency optimisation, not a correctness requirement, so the
right answer when readiness cannot be proven is to warm nothing, not to guess.

Output: an explicit `launching` → `ready` state machine, one function owning both the spare target
and the instance ceiling, readiness proven by a real MCP round-trip with an injectable probe seam,
denials that distinguish "not yet" from "never", and churn visible in the log.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host broker → spawned `x64sc` | Instance launch passes arguments into a spawned emulator process |
| broker → readiness probe | An operator-supplied executable path decides whether a machine is handed to a session |
| broker state → grant selection | Instance state in a file on the bind mount decides which port a session reaches |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.2-05 | Denial of Service | `maintain_spares` | medium | mitigate | The `MAX` ceiling and the `ready_spares == N` target are both read and enforced inside one function, so the bound cannot drift away from the target it bounds; `VICE_BROKER_MAX` is range-validated 1..16 at start |
| T-01.2-07 | Elevation of Privilege | `launch_instance`'s spawn | medium | transfer | The spawn reuses `vice-supervisor.sh` unchanged, which already documents and mitigates `VICE_ARGS` handling as its own recorded threat; the broker adds no second spawn path |
| T-01.2-10 | Tampering | grant selection | high | mitigate | Only entries in state `ready` are selectable, and `teardown` removes rather than resets an entry, so a released instance has no route back to grantable |
| T-01.2-15 | Tampering | `VICE_BROKER_PROBE_CMD` | low | accept | The value is invoked as an executable with the port as its only positional argument, never evaluated as a shell string, so there is no injection surface. The remaining risk is an operator pointing it at a program that always reports ready, which is the operator's own machine and trust domain — documented as a test seam rather than defended against |
| T-01.2-16 | Spoofing | advertising an unproven instance as ready | high | mitigate | Readiness requires a real MCP round-trip; a TCP accept is explicitly rejected as sufficient, and when no probe is available the broker warms zero spares rather than guessing |
| T-01.2-SC | Tampering | package-manager installs | high | accept | Zero installs in this plan; all code is bash coreutils plus `curl`, which is not a package-manager dependency added by this phase |
</threat_model>
