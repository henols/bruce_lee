**Launch primitive, reused unchanged** (`vice-pool.sh:369-381`, cited directly in RESEARCH.md):
```bash
resolved_args="-mcpserver -mcpserverhost $VICE_POOL_MCP_HOST -mcpserverport $port"
```

**Atomic tmp+rename JSON write** (`tools/vice-supervisor.sh:289-306` `write_epoch()`, and
`vice-pool.sh:319-343` `write_registry()` — same idiom, apply to `grants/<id>.json`,
`denials/<id>.json`, `broker.json`):
```bash
write_epoch() {
  local tmp
  tmp="$(mktemp "$VICE_SUPERVISOR_DIR/.epoch.XXXXXX")"
  { printf '{...}'; } >"$tmp"
  mv "$tmp" "$EPOCH_FILE"   # mv within one filesystem is atomic; a direct > redirect is not
}
```
No `jq` assumed — hand-rolled `json_escape()`/`json_string_array()` helpers
(`vice-supervisor.sh:246-262`) are the copy-source for any string escaping the broker needs.

**Identity-verified kill, never a name/pid-only match** (`vice-pool.sh:444-461` `cmd_stop`):
```bash
args="$(ps -o args= -p "$pid" 2>/dev/null || true)"
case "$args" in
  *"$SUPERVISOR_SCRIPT"*)
    kill -TERM "$pid" 2>/dev/null || true
    ;;
  *)
    echo "refusing to signal pid $pid ... possible pid reuse" >&2
    ;;
esac
```
This is the exact shape `teardown(id)` (RESEARCH Pattern 2) must use before killing a granted
instance's `x64sc`/supervisor pid.

**Registry read without jq** (`vice-pool.sh:417-422` `read_registry_ports`/`read_registry_pids`) —
copy this grep/sed-against-known-shape idiom for reading `requests/*.json` in the broker's scan
loop; do not introduce `jq`.

**Single-teardown-path loop shape** (RESEARCH.md Pattern 2, pseudocode already written — implement
literally):
```bash
for id in "${GRANTED_IDS[@]}"; do
  lease="$LEASES_DIR/$id"
  if [ ! -e "$lease" ]; then
    teardown "$id" "released"
  elif lease_is_stale "$lease" "$TTL_S"; then
    rm -f "$lease"
    teardown "$id" "swept (stale ${TTL_S}s)"
  fi
done
```

**Signal trap for the daemon's own clean shutdown** (`vice-supervisor.sh:328-339`):
```bash
child_pid=""
cleanup() {
  if [ -n "$child_pid" ] && kill -0 "$child_pid" 2>/dev/null; then
    kill -TERM "$child_pid" 2>/dev/null || true
    wait "$child_pid" 2>/dev/null || true
  fi
  exit 0
}
trap cleanup INT TERM
```

**Atomic tmp+rename write for a request file** (mirror `tryAcquirePort`'s tmp-then-`linkSync`
idiom, lines 400-401, adapted to a plain write+rename since requests are not exclusive-lock files
the way leases are):
```js
const tmp = join(leasesDir(dir), `.tmp-${process.pid}-${token}`);
writeFileSync(tmp, JSON.stringify(record, null, 2) + "\n");
```
and `refreshLease()`'s tmp+`renameSync` pattern (lines 479-492) for `touchLease()`:
```js
export function refreshLease(leasePath, token, ttlMs) {
  let rec;
  try { rec = JSON.parse(readFileSync(leasePath, "utf8")); } catch { return false; }
  if (rec.token !== token) return false;
  const updated = { ...rec, expires_at: new Date(Date.now() + ttlMs).toISOString() };
  const tmp = `${leasePath}.tmp-${process.pid}-${randomUUID()}`;
  writeFileSync(tmp, JSON.stringify(updated, null, 2) + "\n");
  renameSync(tmp, leasePath);
  return true;
}
```

**Grant-polling loop** (`acquire()`, lines 666-717 — the exact shape for `pollGrant()`): poll on an
interval up to a deadline, throw a descriptive error assembled from per-candidate rejection reasons
once the deadline passes, never hang silently:
```js
const deadline = Date.now() + timeoutMs;
while (true) {
  // check for a grant/denial file matching this request id
  if (Date.now() >= deadline) {
    throw new Error(`acquire: no free instance within ${timeoutMs}ms -- ...`);
  }
  await sleepMs(Math.max(0, Math.min(pollMs, deadline - Date.now())));
}
```

**Redirect seam — no new API needed** (`vice.mjs:84-101`, cited directly in RESEARCH.md):
```js
export function useInstance({ port, url, epochFile, pooled = false } = {}) {
  // resets the handshake, redirects rpc()'s POST target, readEpoch()'s default path, etc.
}
```
Call `useInstance({ port, url, epochFile, pooled: true })` once a grant is read — identical to how
`vice-pool.mjs`'s own callers already use it.

**Error handling / never-throw posture:** every JSON read of a broker-written file (grant, denial,
`broker.json`) must be wrapped exactly like `vice-pool.mjs`'s `readRegistry()`/`isReclaimable()`
treat `registry.json`/lease files — try/catch around both read and parse, treat malformed shape as
absent, never propagate a raw parse exception up to the MCP handler.

**Crash-safety net pattern** (`vice-pool.mjs:494-520`, `pendingLeases`/`ensureExitHandlers()`) — if
the broker-client needs its own best-effort cleanup-on-process-exit, mirror this registered-once
`Set` + single exit-handler-registration guard shape rather than adding a new listener per lease.

### `.claude/mcp/vice/vice-proxy.mjs` (controller, extended — no analog needed, extend in place)

**Current shutdown code to REPLACE** (lines 820-834 — confirmed via direct read, matches
RESEARCH.md Pitfall 1 exactly):
```js
function shutdown() {
  process.exit(0);
}
process.stdin.on("end", shutdown);
process.stdin.on("close", shutdown);
```
The header comment at lines 40-42 and the inline comment at lines 820-822 both assert the
pre-spike, now-disproven termination ladder ("stdin EOF -> SIGTERM -> SIGKILL") — correct this
prose in the same change.

**New shutdown code** (verbatim from RESEARCH.md's Code Examples / the spike-findings skill):
```js
let teardownRan = false;

function releaseLease(trigger) {
  if (!leaseFile) return;
  try { unlinkSync(leaseFile); }
  catch (err) { console.error(`vice-proxy: lease_unlink_failed trigger=${trigger}: ${err.message}`); }
}

function onTeardown(trigger) {
  if (teardownRan) return;
  teardownRan = true;
  releaseLease(trigger);
}

process.stdin.on("end",   () => onTeardown("stdin_end"));
process.stdin.on("close", () => onTeardown("stdin_close"));
for (const sig of ["SIGTERM", "SIGINT", "SIGHUP"]) {
  process.on(sig, () => onTeardown(sig));
}
```
Note: this removes the file's ONLY `process.exit(` call. The test suite's source-assertion
convention (see below) currently expects exactly one occurrence "on the stdin end/close path" —
that assertion must be updated in the same change to match the new invariant (zero explicit
`process.exit(` calls, since SIGKILL/natural-stdin-exit now handle both paths).

**Never-throw handlers to preserve unchanged** (lines 43-48 — do not touch, only add code around
them):
```js
process.on("uncaughtException", (err) => {
  console.error(`vice-proxy: uncaughtException (ignored, staying alive): ${err && err.stack ? err.stack : err}`);
});
process.on("unhandledRejection", (reason) => {
  console.error(`vice-proxy: unhandledRejection (ignored, staying alive): ${reason && reason.stack ? reason.stack : reason}`);
});
```

**Acquisition call site to redirect** (deferred to first `tools/call`, per locked decision):
the existing `ensureViceSession()`-shaped call path (forwards to `activeInstance()`/`useInstance()`)
must gain a new `ensureBrokerLease()` step ahead of the first forwarded `tools/call` — model its
control flow on `vice-pool.mjs`'s `acquire()` (see broker-client section above) rather than
inventing new control flow inside `vice-proxy.mjs` itself; keep the acquisition logic in the new
`vice-broker-client.mjs` module and have the proxy call into it.

**Three-state broker-absent diagnostics** — extend the existing pattern (already built in 01.1 for
the analogous "host unreachable" diagnosis); read the current implementation before writing new
prose so wording stays consistent (never started / dead-or-hung / alive-but-launch-failed, each
quoting the absolute host path via `hostPath()`).

## Shared Patterns

### Atomic tmp+rename writes (applies to `vice-broker.sh` AND `vice-broker-client.mjs`)
**Source:** `tools/vice-supervisor.sh:289-306` (`write_epoch`), `tools/vice-pool.sh:319-343`
(`write_registry`), `.claude/mcp/vice/vice-pool.mjs:479-492` (`refreshLease`)
**Apply to:** every new protocol file (`requests/<id>.json`, `grants/<id>.json`,
`denials/<id>.json`, `broker.json`) on both the bash and Node sides. Never a direct `>` redirect or
plain `writeFileSync` to the final path.

### Identity-verified process kill, never name/pid-only
**Source:** `tools/vice-pool.sh:444-461` (`cmd_stop`)
**Apply to:** `vice-broker.sh`'s `teardown(id)` — verify `ps -o args= -p "$pid"` contains the known
supervisor script path before signalling.

### Container guard, sourced not forked
**Source:** `tools/lib/container-guard.sh`, `tools/lib/repo-root.sh` (both existing, unchanged)
**Apply to:** `vice-broker.sh` sources both verbatim, exactly as `vice-supervisor.sh` and
`vice-pool.sh` already do — this codebase has documented history (both files' own header
comments) of a second copy drifting out of sync (the removed mountinfo signal). Do not fork.

### Never-throw / never-cache-a-negative-result
**Source:** `.claude/mcp/vice/vice-proxy.mjs:43-48` (uncaughtException/unhandledRejection),
`.claude/mcp/vice/vice-pool.mjs`'s try/catch-around-JSON-parse posture throughout
**Apply to:** `vice-proxy.mjs`'s extended shutdown/acquisition code and the new
`vice-broker-client.mjs` module — every read of a broker-written file is untrusted input from the
container's point of view; parse failures become "treat as absent," never an uncaught throw.

### CLI flags evaluated before the container guard
**Source:** `tools/vice-pool.sh:156-193`, `tools/vice-supervisor.sh:125-162`
**Apply to:** `vice-broker.sh`'s `--help`/`--check-container`/`--print-paths`/`--once` — all must
be checked and able to exit before `container_guard_enforce` runs, exactly like the two existing
scripts, so diagnosing a wrongly-refusing guard never itself requires bypassing the guard.
