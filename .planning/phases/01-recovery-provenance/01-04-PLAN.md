## Phase Goal

See `01-01-PLAN.md` § Phase Goal. ROADMAP's Phase 1 Goal line is not in user-story form and no story was invented; per MVP mode this is surfaced rather than fabricated — run `/gsd mvp-phase 01` if a user story is wanted for the phase.

This plan is an **expansion slice** inside an established phase, not a tracer. Plan 01-01 was this phase's tracer and shipped; SKELETON.md's capability is already proven. The vertical slice this plan adds is narrow and complete: detector armed on evidence, play driven, hits attributed, dumps captured, claim written down with what looked for it.

<objective>
Prove the dumps are complete by looking for on-demand loading with mechanical detectors, and record the result as a claim with its evidence attached — including when the result is zero.

Purpose: a dump that misses a region the game loads later is the exact failure mode that makes every downstream provenance verdict and every Phase 4 round-trip diff quietly wrong. Success criterion 2 does not accept silence: "zero found" only counts if the armed set and the coverage reached are stated alongside it. Absence of evidence is only evidence of absence when you can show what looked — and when you can show the machine was running while it looked.

This is a rewrite of a plan that was executed and then reverted (`bb0b1f7`). The design of the original was largely sound and is kept. Three things it got wrong, and this rewrite fixes each with a mechanical gate rather than a caution: it ran on the pre-01.2 fixed instance pool that hung mid-run; it armed a loader range (`$08F5`-`$08F7`) that was permanent game code, inherited from prose rather than verified live, which logged 113 false hits from ordinary idling; and it counted never-populated-range hits without attributing them, when those ranges are structurally guaranteed to fire the first time real gameplay runs.

Output: `tools/lib/vice-acquire.mjs`, `tools/watch-loads.mjs`, their unit tests, `recovery/LOADING.md`, and a committed supplementary dump for every attributed load event found.
</objective>

<assumption_delta_decision>
The scope of this rewrite introduces a second way to reach an emulator instance where there was one, so the identity question is re-asked rather than assumed.

- **Primary noun:** *the granted instance* — the emulator this session already holds, identified by its container-side coordinates.
- **Decision:** `promote`. A single acquisition seam (`tools/lib/vice-acquire.mjs`) becomes the primary representation and the fixed instance pool is demoted to one historical variant of it, rather than adding a broker path alongside a still-required pool path. Adding a route alongside would leave two live acquisition mechanisms in a repository whose own tooling philosophy is that a second case arrives as data or as one generalised seam, never as a branch — the same rule `check-parameterisation` already enforces for release identity.
- **Rationale:** the concrete failure this closes is the reverted run's `disarm` bug, where `arm` and `disarm` each acquired independently and addressed different instances, leaving 174 checkpoints armed. One seam makes that class of bug unreachable rather than merely discouraged.
- **Invariant worth encoding:** every live verb in the recovery pipeline reaches the emulator through exactly one acquisition function, provable by grep — see Task 2's acceptance criteria.
</assumption_delta_decision>
