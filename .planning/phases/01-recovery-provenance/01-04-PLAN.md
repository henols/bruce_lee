## Phase Goal

See `01-01-PLAN.md` § Phase Goal. ROADMAP's Phase 1 Goal line is not in user-story form and no story was invented.

<objective>
Prove the dumps are complete by looking for on-demand loading with mechanical detectors, and record the result as a claim with its evidence attached — including when the result is zero.

Purpose: a dump that misses a region the game loads later is the exact failure mode that makes every downstream provenance verdict and every Phase 4 round-trip diff quietly wrong. Success criterion 2 does not accept silence: "zero found" only counts if the armed set and the coverage reached are stated alongside it. Absence of evidence is only evidence of absence when you can show what looked.

Output: `tools/watch-loads.mjs`, its unit tests, `recovery/LOADING.md`, and a committed supplementary dump for every load event found.
</objective>

  <action>
Write `tools/watch-loads.mjs` following the established repository CLI conventions and taking the same injectable `call` as the other tools so the pure logic is testable without the emulator. Verbs `arm`, `disarm`, `report` and `attribute`; flags `--release` and `--json`.

`WATCH_SET` is built per release from the registry and the release's range manifest, never hardcoded. It contains three kinds of sentinel, and D-10 is explicit that these are the detector while play is merely what drives them:

1. **Loader re-entry exec checkpoints.** `vice_checkpoint_add({start, end, exec:true, stop:true})` spanning the release's already-defeated loader code range. Per D-10 this must never fire again after the dump point; if it does, that is itself first-class evidence of a second load pass and is exactly what the plan is looking for.
2. **Drive and serial-bus watches.** `vice_watch_add({address:"$DD00", size:1, type:"both"})`. CIA2 port A carries both the VIC bank select bits and the serial-bus CLK, DATA and ATN lines that a KERNAL-bypassing fastloader bit-bangs directly. Because these disks' loaders bypass the KERNAL entirely there is no `$FFD5`-style vector activity to watch instead, so this register is the primary sentinel rather than a supplementary one. Note in the tool's own documentation that VIC bank changes will also trip it, which is why hits carry attribution and a reason rather than being counted blindly.
3. **Never-populated-range write watches.** One `vice_watch_add({type:"write"})` per range the capture's manifest classified `unused`. A write into a range that was empty at dump time is the signature of content arriving later.

Implement `attributeAddress(addr)` as pure logic over the declared ranges: exactly one owner per address, abutting ranges stay separate, an out-of-range address returns an explicit unmatched result rather than the nearest neighbour. Implement `reportHits` to sort by emulated cycle ascending then address ascending, so two hits in the same cycle have a defined order and the report is reproducible; take the cycle from `vice_cycles_stopwatch` reads taken at each stop, used purely as a *label* on the hit and never as a gate.

`disarmAll` is the counterpart of the missing bulk-clear tool: enumerate with `vice_checkpoint_list` and delete each returned id individually with `vice_checkpoint_delete`. `armWatchSet` must call `disarmAll` on any failure partway through, so the shared instance is never left holding half an armed set for the next session.

Record the resolved `WATCH_SET` for each release into `recovery/RELEASES.json` in a form that can be re-armed verbatim — the address ranges, the types, and the reason each is armed. Plan 02-02 re-arms this exact set during Phase 2's mandatory exhaustive all-chambers trace, which is how D-11 gets breadth without paying for the expensive play-through twice.

Write `tools/watch-loads.test.mjs` with `node:test` covering every behaviour above using a stub `call`.

Note that this machine is PAL at roughly 50.125 Hz while the joystick tools' own docstrings quote milliseconds per frame at 60 Hz, so any millisecond figure derived from a docstring is wrong here; use frame counts and checkpoints only.
