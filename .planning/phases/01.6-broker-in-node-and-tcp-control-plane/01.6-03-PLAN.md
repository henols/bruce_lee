**What this plan is: the contract between what is built and what is deployed.** Three separate
landmines, all of which fire during a file move and none of which any source artifact before
2026-08-02 recorded:

1. **`install-resources.mjs` has no delete path at all** (RESEARCH § Runtime State Inventory,
   confirmed by full source read). `tools/` in this very container currently holds all three stale
   `.sh` copies. Once the deployed set changes shape, a missing prune leaves retired executables on
   the host — and criterion E says either add one or record its absence as accepted. It is added.
2. **`.gitignore` names deployed files individually**, lines 99–103, because `tools/` is mixed. When
   the deployed set changes, the ignore list must change with it, and nothing enforces that today.
3. **C6's own phrasing is wrong.** `01.6-VALIDATION.md` proposes `find . -name "*.sh"` "excluding
   gitignored `tools/`". `tools/` is not gitignored — five individual paths inside it are, alongside
   tracked reverse-engineering tooling. Directory exclusion is the wrong predicate and would pass a
   check that should fail. `git ls-files` is the right one: it enumerates tracked files, so deployed
   copies and the untracked `.claude/worktrees/` copies are excluded structurally rather than by a
   hand-maintained exclusion list. Measured 2026-08-02: exactly seven tracked shell scripts repo-wide,
   five under `resources/` and two under `.devcontainer/`.

**Why the C10 guard lands here rather than with the conversion.** 01.6.1 owns C10 proper and its
widening to the transitive path. But the moment an agent is most likely to perform the cleanup that
comment forbids is the moment it is editing that very file — which is this plan. The guard is authored
now, against the `.mjs` sources, so it is green today and 01.6.1 widens data rather than inventing
logic.

**Scope boundary held.** No `.mjs` module is converted here. `vice-proxy.mjs`, `vice.mjs`,
`vice-broker-client.mjs` and the rest stay exactly as they are — 01.6.1's work. The only source module
this plan edits is `install-resources.mjs`, and only to add a prune path.

## Trust Boundaries

| Boundary | Description |
|---|---|
| installer → the host's `tools/` directory | A mixed directory: gitignored deployment output beside tracked reverse-engineering tooling. Anything with delete authority here can destroy work. |
| `tools/.vice-deployed.json` → the prune | The manifest is the prune's only input, and it lives on the same shared mount both sides write to — untrusted input by construction. |
| `.mcp.json` → the agent session | Read once at session start. A wrong value here is not degraded service, it is no emulator access at all. |
