## The verification hazard this phase cannot engineer away

**State this before any table is read.** This phase runs **first** in v1.1, before Phase 01.4. There
is **no live-session verification available**. The only proof of equivalence is the test suite — and
Phase 01.4's central finding is that this exact suite was **268/268 green while three tools were
uncallable from a real session**.

Therefore: a green suite here proves **language and structural equivalence only**. The claim *"the
tool surface a session sees is unchanged"* must be carried forward to Phase 01.4 as **explicitly
unverified**. Adding more tests of the same shape is the wrong answer and must not be proposed as
closing this gap.

## Sampling Rate

- **After every task commit:** run that file's own test directly — `node --test <path>/<file>.test.ts`. Fast, container-only.
- **After every plan wave:** full suite — `node --test <src-dir>/`.
- **Before `/gsd-verify-work`:** full suite green, **plus** the written unverified-claim statement above.
- **Max feedback latency:** target < 30s for the per-file loop; set the real number once Wave 0 measures the suite.

## Wave 0 Requirements

- [ ] `tsconfig.json` + `package.json` (container-only `typescript` devDependency) — neither exists in the repo today.
- [ ] Bundling toolchain for D-01, so `@mastra/core`'s ~59 MB / 33-dep tree ships as emitted JS and the host still needs only `node` (criterion 3 is **not** relaxed).
- [ ] The §F sync test — `resources/` matches a fresh build of the committed TS source.
- [ ] The §E TDZ-hazard regression test — **static** source-text check; a runtime test does not catch this categorically (live-reproduced: the crash fires only on a top-level synchronous call).
- [ ] The §D2 single-`in_flight`-owner race test — two concurrent launch requests against a stubbed spawn, assert exactly one spawn. This is the 2026-08-01 triple-launch defect's regression test.
- [ ] Structural "exactly one `.sh` survives" test (C6).
- [ ] `vice-broker.test.mjs`'s replacement suite — **the single largest gap.** 2,685 lines / 61 tests that verify the bash daemon by spawning it as a real subprocess and inspecting on-disk `grants/`/`spares/`. Once state moves in-process, that mechanism stops existing. Size this as **redesign, not port**, in its own task.
- [ ] Baseline measurement: current suite wall time, so the latency target above is a number rather than a guess.

**Explicitly NOT a Wave 0 gap:** live-session verification of the tool surface. No test infrastructure
this phase could add closes it. See the hazard note at the top.
