# Phase 01.6 Plan 03: The Prune, Parity, and Load-Order Contract Summary

**Manifest-scoped `pruneResources()` closing install-resources.mjs's delete gap, a two-way `.gitignore`-vs-deployed-set parity gate, a `git ls-files`-based replacement for C6's broken directory-exclusion phrasing, and a statement-anchored static guard (with cycle allowlist) proving the Criterion-10 TDZ cycle stays exactly as documented — all four landmines defused with live, reverted demonstrations of each failure mode.**

## Performance

- **Duration:** ~1h10m
- **Tasks:** 3, each producing one atomic commit
- **Files created:** 1 (`load-order.test.mjs`)
- **Files modified:** 4 (`install-resources.mjs`, `install-resources.test.mjs`, `host-scripts.test.mjs`, `vice-mcp-selector-docs.test.mjs`, `.gitignore`)

## Accomplishments

- `install-resources.mjs` now has a delete path for the first time in this repo's history: `pruneResources()` removes a deployed file this installer previously placed under `tools/` once that file no longer exists in `resources/`, and its candidate set is *exactly* the on-disk manifest (`tools/.vice-deployed.json`) minus current `resourceEntries()` — never a directory walk of `tools/`, which also holds tracked reverse-engineering tooling. Proven with 8 new tests covering malformed-manifest safety, round-trip convergence, retired-entry removal, untracked-file protection, and both escape-refusal shapes (parent-directory hop, absolute path).
- `.gitignore` and the deployed set are now in **enforced two-way parity** — a missing ignore line and a stale one are both caught, live-demonstrated by temporarily deleting `/tools/vice-launcher.sh`'s line and observing the exact expected failure message before reverting.
- The one-shell-script structural check now uses `git ls-files` instead of C6's broken "exclude gitignored `tools/`" directory predicate — `tools/` is a *mixed* directory (gitignored deployment output alongside tracked RE tooling), so a directory exclusion could never have told those apart correctly. Independently confirmed via `git ls-files -- '*.sh'`: exactly 8 tracked paths (6 in the new `EXPECTED_TRACKED_SHELL_SCRIPTS` allowlist + 2 under `.devcontainer/`).
- The Criterion-10 load-order guard is a statement-anchored static source-text check, not a runtime-crash test (per RESEARCH.md §E's live-reproduced nuance that a lazily-called reintroduction does not crash today). It correctly rejects a plain import, a `import type` import, and a named `{ type repoRoot }` import from `install-resources.mjs` into `repo-root.mjs` — and, critically, never fires on `install-resources.mjs`'s own header comment, which quotes that exact forbidden import verbatim in prose. Both the direct guard and the accompanying cycle-allowlist scaffold were live-demonstrated against injected violations and reverted cleanly.
- `.mcp.json`'s vice entry now asserts its resolved file's *basename* is the proxy entry point (not merely "some file that exists"), with a failure message naming the actual stakes: this path is hardcoded, read once at session start, and a silent repoint costs the agent all emulator access at the next session start. Live-demonstrated by repointing at `vice.mjs`.
- Suite rose from the wave-2 baseline of 309 to **323** — exactly the 14 new tests this plan's own arithmetic predicts (8 + 2 + 4).

## Decisions Made

See frontmatter `key-decisions` for full reasoning. Summarized:

1. Manifest shape is `{ "entries": [...] }`, not a bare array, matching the plan's must-have wording for what counts as "malformed".
2. `pruneResources()`'s own `skipped`/`failed` stay separate from `installResources()`'s copy-loop arrays (different semantic domains); only `pruned` is added to `installResources()`'s returned object, per the plan's literal wording.
3. The manifest write inside `installResources()` is independently wrapped in try/catch to preserve the pre-existing "never throws on unwritable root" guarantee — not explicit in the plan's prose, but required by the existing test that guarantee already covers.
4. The cycle-graph builder's specifier-extraction regex needed the identical statement-anchoring fix as the direct guard — an unanchored version produced a phantom edge from `install-resources.mjs`'s own header-comment prose, caught by the cycle test itself failing unexpectedly before this was committed.
5. `EXPECTED_TRACKED_SHELL_SCRIPTS` includes `vice-pool.sh` today (6 entries) since this plan's scope fence forbids deleting it — that is plan 04's job.

## Deviations from Plan

None requiring an executor deviation rule beyond the empirical fixes already anticipated by the plan's own text (RESEARCH.md §E explicitly calls out that the naive extension-group and unanchored-pattern traps would need discovering and fixing during this task, and the cycle-extraction regex bug was the same trap recurring in the graph-builder half — caught and fixed within Task 3, before its commit, via the test itself failing).

## Issues Encountered

- The cycle-allowlist test's specifier-extraction helper initially used an unanchored `from\s+["'](\.[^"']+)["']` search (mirroring an earlier draft of the direct guard before its own anchoring fix was applied). Running the test surfaced a phantom `install-resources.mjs -> repo-root.mjs` edge sourced entirely from `install-resources.mjs`'s header comment, which quotes that exact import verbatim in prose. Fixed by anchoring the extractor to a real statement start (`^[ \t]*(?:import|export)...`), identical reasoning to the direct guard's own anchoring. Resolved within Task 3, before its commit — not a deviation requiring a rule, since RESEARCH.md §E already named exactly this class of trap as something to expect and fix during this work.
