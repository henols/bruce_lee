# Phase 01.6.1: Code Review Report

**Reviewed:** 2026-08-03T16:13:51Z
**Depth:** standard
**Files Reviewed:** 26
**Status:** issues_found (Info only — no Critical or Warning findings)

## Summary

This phase converts the entire `.claude/mcp/vice/` implementation from `.mjs` to TypeScript.
Reviewed at standard depth: every source and test file was read in full, cross-referenced
against imports/exports, and — because the stated intent was a **port, not a rewrite** —
spot-checked against the actual `git show` diffs for the highest-risk conversions
(`vice.mjs→vice.ts`, `vice-proxy.mjs→vice-proxy.ts`, the `repo-root`/`install-resources`/
`hostpath` cycle-break) to distinguish genuine behavior changes from mechanical type
annotation.

**Assessment: this is an unusually faithful and carefully-verified port.** Every diff
inspected line-by-line showed the same pattern: an added type annotation, an `isPlainObject()`
narrowing in place of an implicit `object` check, or an `(e as Error)` cast at a catch site —
never a changed conditional, a dropped branch, or a narrowed default that silently drops a
case. The two intentionally-documented behavior changes (`incident-record.ts`'s mode
restriction, `refresh-manifest.ts`'s atomic write + exported `main()`) are both correctly
implemented and covered by dedicated tests (`incident-record.test.ts`'s T-01.6.1-08 mode
assertions; `refresh-manifest.test.ts`'s tmp-sibling/mode/entry-point-guard tests).

Checked and clear:
- **`erasableSyntaxOnly` compliance**: no `enum`, `namespace`, or constructor parameter
  property slipped into any reviewed `.ts` file.
- **The hard "no direct VICE connection" rule**: every network call in this tree lives inside
  `vice.ts`'s `rpc()`/`call()` seam, `vice-probe.ts`'s deliberately-separate single-shot probe
  (both are the sanctioned `mcp__vice__*` implementation itself, not a bypass — documented and
  unchanged from before this phase), or `vice-proxy.ts`'s forwarding through `call()`. No
  reviewed module reads broker state to find a port for its own connection, or imports a
  transport module as a library to reach the emulator directly.
- **No hardcoded secrets, `eval`, or shell/process injection** anywhere in the reviewed set.
- **`vice-broker.test.mjs`** correctly updated its `PROXY_PATH` constant to point at the
  renamed `vice-proxy.ts` (verified byte-identical join target against `vice-proxy.test.ts`'s
  own constant) — not flagged for remaining `.mjs`, per this review's scope.

No Critical or Warning findings. The four Info items below are all either genuinely
pre-existing (verified via `git show` against the pre-conversion `.mjs`) or negligible in
practical impact, and are recorded for a future hardening pass rather than as defects in this
phase's own work.

## Info

### IN-01: `vice-broker-client.ts`'s atomic write skips the mode-restriction step its three siblings now apply

**File:** `.claude/mcp/vice/vice-broker-client.ts:104-109`
**Issue:** `writeJsonAtomic()` (used for `requests/*.json`, `leases/*`, and the recycle-request
records) writes the tmp file's content directly and renames — it never calls `chmodSync(tmp,
0o600)` before content lands. This phase deliberately tightened exactly that pattern in three
sibling modules in the same directory: `incident-record.ts`'s `writeAtomic()`,
`install-resources.ts`'s `writeDeployManifest()`, and `refresh-manifest.ts`'s
`writeManifestAtomic()` all now create the tmp file empty, `chmodSync` it to `0o600`, *then*
write content. `vice-broker-client.ts`'s own `writeJsonAtomic()` was left as it was before the
conversion (confirmed via `git show cdb566a^:.claude/mcp/vice/vice-broker-client.mjs` — the
pre-conversion source has the identical unrestricted sequence), so this is not something the
TypeScript port introduced or made worse. It is flagged here because the request/lease records
this function writes carry `session_id`/`client_pid` metadata and briefly sit at the process's
default umask between write and rename, which is exactly the exposure window the sibling
modules' own T-01.6.1-08-style hardening exists to close — the inconsistency across four
atomic-write call sites in one directory is worth closing in a follow-up rather than only in
three of the four.
**Fix:** Apply the same empty-file → `chmodSync(tmp, 0o600)` → write-content → rename sequence
inside `writeJsonAtomic()`.

### IN-02: `bytesFromMemoryReadResult()`'s hex decode silently drops a trailing odd nibble

**File:** `.claude/mcp/vice/vice-proxy.ts:805-818`
**Issue:** The `"hex"` decode branch loops `for (let i = 0; i + 1 < clean.length; i += 2)`, so
an odd-length cleaned hex string silently loses its last nibble instead of raising or reporting
a decode problem. Pre-existing (identical in the pre-conversion `.mjs`, confirmed by the
`git show fc515df`/`07a83e9` diffs, which touch only types here) — carried over unchanged by
this port. Practical impact is low: every call site reads a fixed, even byte count ($01/1 byte,
vector pairs/2 bytes), so an odd-length response would itself already be a symptom of a
malformed host reply, not something this project's own call sites can trigger.
**Fix:** If ever revisited, treat an odd-length cleaned hex string as a decode failure (`{
available: false, reason }` via the existing `captureStep()` wrapper) rather than truncating
silently.

### IN-03: `vice-proxy.ts` is a single ~2,680-line module carrying many independently-testable concerns

**File:** `.claude/mcp/vice/vice-proxy.ts` (whole file)
**Issue:** JSON-RPC dispatch, epoch/session tracking, the `vice_recycle` protocol, the
`vice_diagnose` cycle-bracket/checkpoint-trap logic, path rewriting/translation, output
chunking, and the seam-hazard annotation table all live in one file. This predates the
TypeScript conversion (the `.mjs` original was already this size and shape — the `07a83e9`
diff is purely additive type annotations/interfaces, no restructuring), so it is not a defect
introduced by this phase. Noted because the file's own size is now large enough that a future
functional change risks touching more than intended; the existing test suite
(`vice-proxy.test.ts`, ~4,470 lines) already mitigates this by exercising the file thoroughly,
including several structural/source-text assertions that pin exact declaration text.
**Fix:** No action required by this phase. Worth considering a follow-up split (e.g. recycle/
diagnose evidence-gathering into their own module) once a phase specifically targets
`vice-proxy.ts`'s maintainability rather than its language.

### IN-04: Non-null assertions (`!`) in `vice-proxy.ts`'s checkpoint-trap report render

**File:** `.claude/mcp/vice/vice-proxy.ts:972,974`
**Issue:** `trapCheckpoint!.checkpoint_num` is used twice inside `renderCheckpointTrapReport()`.
Both are safe in practice — `trapReason === "pc"` / `"handler"` can only be set alongside a
non-null `trapCheckpoint` in `gatherCheckpointTrapEvidence()` — but the assertion papers over
that invariant rather than the type checker proving it, so a future edit that changes how
`trapReason`/`trapCheckpoint` are derived could silently reintroduce a crash here with no
compiler signal. Introduced by this port (the `.mjs` original had no such marker at all, since
untyped JS doesn't need one) but behavior-neutral — TypeScript would have flagged a genuine null
risk here as an error, not silently accepted a wrong one.
**Fix:** Optional: narrow via a discriminated union on `trapReason` (`{ trapReason: "pc";
trapCheckpoint: CheckpointInfo } | { trapReason: "handler"; trapCheckpoint: CheckpointInfo } |
{ trapReason: null; trapCheckpoint: null }`) so the two fields' correlation is enforced by the
type system instead of asserted.
