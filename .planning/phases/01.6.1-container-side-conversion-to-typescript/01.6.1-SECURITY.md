## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| agent session → `.mcp.json` → proxy entry point | Read once, at session start. A wrong path costs all emulator access, and the session that made the change cannot observe it. | Process spawn specifier |
| proxy → host VICE | Every forwarded call crosses this; the deny-list, the epoch re-check and the path rewriting all live at this seam. | Tool calls, tool results, paths |
| stdin JSON-RPC → the proxy's handlers | Untrusted message shapes arrive on stdin; the proxy must narrow before reading fields. | Untrusted JSON |
| host MCP server's advertised tool list → the vice library's discovery filter | The deny-list is applied at this choke point and again at the proxy's read time. Losing either re-exposes a tool with three layers of defence against it. | Tool descriptors |
| manifest file → the proxy's offline tools-list handler | Read with no host I/O. A truncated or clobbered manifest is a wrong tool surface for a whole session. | Cached tool manifest |
| host broker's concurrently-written state files → the broker client's readers | The broker writes grant/request/lease files while the client reads them; a half-written record is routine, not exceptional. | Broker state JSON |
| environment → path translation | `CONTAINER_WORKSPACE_PATH` / `HOST_WORKSPACE_PATH` feed a translation that hands paths to a host process. A silently wrong root yields a plausible-looking wrong host path. | Filesystem paths |
| host path string → container path string | `containerpath` is the inverse seam; a hardcoded absolute host path in its source would be silently wrong on any other machine. | Filesystem paths |
| incident record → filesystem | Records are written into the workspace; a world-readable temp file or a partially-written record are real outcomes of wrong write ordering. | Diagnostic records |
| host reply → agent-visible output | The output ceiling chunks rather than truncates, so a large reply is never silently cut. | Tool result payloads |
| module graph → process start | A TDZ crash at module-load time means the proxy process never starts, so every tool call fails. Availability-shaped. | Module initialization order |
| static safety check → the module tree it polices | A check enumerating by hardcoded extension stops matching after a rename and reports green while enforcing nothing. | Guard coverage |
| static guard → the module it polices | The direct guard's subject is renamed in the same plan the guard is renamed in. | Guard coverage |
| container/host language boundary | The request-id rule exists twice, in two languages. This phase makes the container copy importable; 01.6.2 deletes the shell copy. | Request identifiers |
| test process → the emulator | **Forbidden.** `mcp__vice__*` is the only permitted route; no test may open its own connection or discover a broker port. | (must not cross) |
| the test suite → the claim of equivalence | The suite is the only equivalence proof available *in this phase*, and Phase 01.4 showed a green suite coexisting with three tools uncallable from a real session. The central hazard of this phase. | Verification confidence |
| this phase → Phase 01.6.3 | The proxy suite is the coverage 01.6.3 relies on when it swaps the transport seam. An assertion weakened for the type checker removes coverage a later phase counts on. | Test coverage |
