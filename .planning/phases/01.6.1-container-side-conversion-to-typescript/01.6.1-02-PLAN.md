## The measurement that makes Option B cheap — verified live at plan time (2026-08-03)

RESEARCH's Assumption **A2** worried that Option B would force a `workspaceRoot` parameter
through roughly nine bare `hostPath(p)` call sites in `containerpath.test` and
`vice-proxy.test`. **It does not, and the reason is measurable:**

`.devcontainer/devcontainer.json` lines 48-49 export **both** `HOST_WORKSPACE_PATH` and
`CONTAINER_WORKSPACE_PATH` into `containerEnv`. Read live in this container:
`CONTAINER_WORKSPACE_PATH=/workspaces/bruce_lee`. So today's
`const CONTAINER_WS = process.env.CONTAINER_WORKSPACE_PATH || WORKSPACE_ROOT` **already
resolves from the environment variable**, and `WORKSPACE_ROOT` — the `repoRoot` call that
keeps the whole cycle alive — is a fallback that is never taken here.

Consequence: an env-first, parameter-optional design preserves current behaviour byte for
byte at every existing call site, including every bare `hostPath(p)` in the two large test
files. Threading the parameter through the four production callers is still correct (it
restores portability for an environment where the variable is absent), but it is **not**
load-bearing for keeping the suite green — which removes A2 as a cost and as a risk.

## Where the top-level call sites actually are — measured live at plan time

`repoRoot(` appears at seven production call sites. Only **two** are module-scope; the rest
are inside function bodies and are lazy and safe:

| Call site | Scope | Guarded? |
|---|---|---|
| `hostpath.mjs:47` | module scope | yes (`{ from: HERE }`) — **removed by this plan** |
| `containerpath.mjs:53` | module scope | yes (`{ from: HERE }`) — the guard's live subject after this plan |
| `incident-record.mjs:36` | inside `incidentsDir()` | bare, lazy, safe |
| `repo-root.mjs:137` | inside `supervisorDir()` | passes `opts`, lazy, safe |
| `repo-root.mjs:156` | inside the bottom-of-module `try` block | bare, and its position is load-bearing per that file's own comment |
| `vice-proxy.mjs:1161,1217,1228,1596,1799` | all inside function bodies | bare, lazy, safe |

This is why the guard must be scoped to **module-scope** calls rather than to "any call in a
cycle member": with the allowlist empty there are no cycle members left, so a
member-scoped guard would be vacuous on the day it lands — the exact failure this phase
exists to eliminate. A module-scope guard has a real subject today (`containerpath`) and
acquires a new at-risk subject the moment Option B gives `vice-sync` its `repo-root` import.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| module graph → process start | A TDZ crash at module-load time means the MCP proxy process never starts, so every tool call fails. Availability-shaped, and this plan is the one place in the whole conversion where the hazard's own files are being edited. |
| environment → path translation | `CONTAINER_WORKSPACE_PATH` / `HOST_WORKSPACE_PATH` are the inputs to a translation that hands paths to a host process. A silently wrong root produces a plausible-looking wrong host path. |
