## The One Real TypeScript Precedent — `vice-broker.mts`

Every one of the 11 conversions in this phase should copy these conventions verbatim. Read from
`/workspaces/bruce_lee/.claude/mcp/vice/vice-broker.mts` (190 lines).

### Extension choice: `.mts`, not `.ts`, for anything host-bound; `.ts` for everything else in this phase

`vice-broker.mts` uses `.mts` specifically because it is **host-bound** — `tsconfig.build.json`'s
literal one-element `include: ["vice-broker.mts"]` compiles it to `resources/vice-broker.mjs`
(explicit `.mjs` output, because `<repo>/tools/` — where `install-resources.mjs` deploys it — has
no `package.json`, so a bare `.js` there would resolve as CommonJS and break the ESM import at
runtime; RESEARCH.md's orientation block states this plainly). **None of the 11 files this phase
converts are host-bound** (RESEARCH §Standard Stack: "all 11 source files this phase converts are
container-only... the only host-bound artifact remains `vice-broker.mts`"). Convert all 11 to
plain `.ts`, not `.mts` — there is no `outDir`/build step for any of them, they run directly under
`node --test` and are typechecked only by the `noEmit: true` project (`tsconfig.json`), whose
`include: ["**/*.ts", "**/*.mts"]` already covers a bare `.ts` file with zero tsconfig edits.

Test files follow `vice-broker-launch.test.ts`'s own stated convention (its header comment,
verbatim): *"This is a `.ts` file (not `.mts`): it tests emitted OUTPUT and authored TypeScript,
never imports a `.mjs` module itself... the convention this group establishes."* Since every
source file this phase converts also becomes `.ts`, every one of its test files becomes
`<name>.test.ts` importing `./<name>.ts` — same-extension pairing throughout, no mixed-extension
import specifiers anywhere once a slice completes.

### Type declarations under `erasableSyntaxOnly`

`enum`, `namespace`, and constructor parameter properties are all banned (confirmed live, RESEARCH
§4). `vice-broker.mts` never needs any of them; its type vocabulary is entirely:

```typescript
export interface ParsedArgs {
  repoRoot: string;
  stateDir: string;
}

export interface BrokerRecord {
  pid: number;
  started_at: string;
  node_version: string;
}

export type WriteResult =
  | { ok: true; path: string; record: BrokerRecord }
  | { ok: false; reason: string };
```
(`vice-broker.mts` lines 32-35, 67-71, 111-113)

**Copy this exactly for every converted file:** plain `interface`/`type` declarations for shapes
(broker records, parsed CLI args, manifest shapes, probe results), discriminated union `type`s for
result values instead of throwing (`WriteResult`'s `{ ok: true, ... } | { ok: false, reason }`
shape is the idiom to reuse anywhere a converted function currently returns `null`-or-a-reason via
convention rather than a typed union — e.g. `install-resources.mjs`'s manifest writer, `vice.mjs`'s
`serverInfo()` failure path). No `class` with parameter-property constructors anywhere in this
codebase's converted files; none of the 11 source files currently use `class` at all (confirmed:
none of the excerpts read this session show one), so this constraint costs nothing in practice.

### Narrowing `unknown`, not casting

```typescript
function isPlainObject(value: unknown): value is Record<string, unknown> {
  return typeof value === "object" && value !== null && !Array.isArray(value);
}
```
(`vice-broker.mts` lines 74-77) — a type predicate, used to narrow the result of `JSON.parse`
(which returns `any` in practice but should be typed as `unknown` at the boundary) before touching
its fields. Apply this to every converted `readJsonMaybe`-shaped helper (`vice-broker-client.mjs`,
`incident-record.mjs`, `install-resources.mjs`'s manifest reader, `vice.mjs`'s manifest/deny-list
handling) — none of them should cast a parsed JSON value with `as SomeInterface` without first
running it through a predicate like this one.

### Never-throw file read — the discipline that must survive unchanged

```typescript
export function readBrokerRecordMaybe(path: string): Record<string, unknown> | null {
  let raw: string;
  try {
    raw = readFileSync(path, "utf8");
  } catch {
    return null;
  }
  try {
    const parsed: unknown = JSON.parse(raw);
    return isPlainObject(parsed) ? parsed : null;
  } catch {
    return null;
  }
}
```
(`vice-broker.mts` lines 84-96) — explicitly documented in its own doc comment as matching
`vice-broker-client.mjs`'s `readJsonMaybe()` posture "exactly." This is the **typed** version of
the exact untyped pattern already in `vice-broker-client.mjs`, `incident-record.mjs`, and
`install-resources.mjs`'s manifest reader. **This is the single highest-value excerpt in this whole
document** — every one of those three files' converted equivalent should look like this, two
separate `try`/`catch` layers preserved (file-read failure vs. parse failure), never collapsed into
one, never replaced by a thrown error. (Same discipline the parent `01.6-PATTERNS.md`'s "Shared
Pattern: Never Throw on Untrusted File Read" already names — this is its typed form, now with a
real in-repo TS excerpt instead of only the JS one.)

### Atomic write — the choke-point discipline, typed

```typescript
const tmpPath = `${finalPath}.tmp-${process.pid}-${Date.now()}`;
writeFileSync(tmpPath, "");
chmodSync(tmpPath, 0o600);
writeFileSync(tmpPath, JSON.stringify(record, null, 2) + "\n");
renameSync(tmpPath, finalPath);
```
(`vice-broker.mts` lines 94-98, inside `writeBrokerRecord`) — tmp sibling created empty, `chmod
600` before content ever lands, content written, then renamed. Copy this shape verbatim wherever a
converted file writes JSON state: `incident-record.mjs`'s `writeIncidentRecord`,
`install-resources.mjs`'s manifest writer, `refresh-manifest.mjs`'s manifest write (currently a
bare `writeFileSync(path, ...)` with **no** tmp/chmod/rename — see §Gaps below, this is a real gap
the port should either preserve as-is with a comment or tighten to match this idiom; RESEARCH.md
does not mandate closing it, but flag it in the plan rather than silently porting the weaker
version and calling it "faithful").

### CLI entry-point guard, `process.exitCode` not `process.exit()`

```typescript
export function main(argv: string[] = process.argv.slice(2)): void {
  let args: ParsedArgs;
  try {
    args = parseArgs(argv);
  } catch (e) {
    process.stderr.write(`${(e as Error).message}\n`);
    process.exitCode = 1;
    return;
  }
  // ...
  process.exitCode = 0;
}

if (process.argv[1] && resolvePath(process.argv[1]) === fileURLToPath(import.meta.url)) {
  main();
}
```
(`vice-broker.mts` lines 158-190) — `process.exitCode`, never `process.exit()`, "so any pending
I/O flushes first" (the file's own comment). **Copy this exactly for `refresh-manifest.mjs`**,
whose current JS form (`main().catch(...)`, `process.exitCode = 1`) already follows the
exit-code-not-exit() half of this discipline — the TS conversion's job is only to type `main`'s
signature and the caught error (`(e as Error).message`, matching the excerpt above) and keep the
"is this the entry point" guard idiom identical.

### Doc-comment density and "why," not "what"

Every function in `vice-broker.mts` carries a doc comment stating why a design choice was made,
often citing a specific past incident or measurement (e.g. "Zero-signal liveness probe... EPERM...
still means the pid IS alive"). This matches the existing `.mjs` files' own convention exactly
(`hostpath.mjs`, `install-resources.mjs`, `repo-root.mjs`, `vice-probe.mjs` all do this heavily
already, as the excerpts below show) — **the conversion should port these comments verbatim,
never summarize or trim them for brevity.** This is the single most repeated instruction across
both this phase's RESEARCH.md and the parent's PATTERNS.md: comments encoding a hazard are load-
bearing, not decorative.

## Pattern: The Criterion-B Cycle Break (Option B, §3.4) — `hostpath.mjs` Follows `install-resources.mjs`'s Own Template

`install-resources.mjs`'s header comment (already quoted in the parent `01.6-PATTERNS.md`, still
accurate) is the canonical template `hostpath.mjs` must now follow, verbatim in shape:

```javascript
// HOSTING CHOICE (D-3): this check lives in a DEDICATED module, triggered
// from repo-root.mjs, for two reasons. First, repo-root.mjs is a pure path
// resolver, and inlining filesystem-writing side effects into it would make
// every importer of a path function also a file writer. Second and decisive:
// this module needs the repo root, and repo-root.mjs is where the repo root
// is computed -- hosting this logic INSIDE repo-root.mjs and importing it
// back from there would be a module cycle. In that cycle, this module would
// evaluate while repo-root.mjs's `const HERE` is still in its temporal dead
// zone, and every entry point would die with
// "Cannot access 'HERE' before initialization".
//
// THE CYCLE IS AVOIDED STRUCTURALLY: this module takes the repo root as an
// ARGUMENT and imports NOTHING from repo-root.mjs. Do not "clean this up" by
// adding `import { repoRoot } from "./repo-root.mjs"` here -- that importable
// convenience is exactly the cycle described above.
```
(`.claude/mcp/vice/install-resources.mjs` lines 6-19)

`hostpath.mjs` today violates exactly this shape — it imports `repoRoot` and calls it at its own
top level:

```javascript
import { repoRoot } from "./repo-root.mjs";
// ...
const WORKSPACE_ROOT = repoRoot({ from: HERE });
const CONTAINER_WS = process.env.CONTAINER_WORKSPACE_PATH || WORKSPACE_ROOT;
```
(`hostpath.mjs` lines 34, 47-48)

**Concrete conversion shape for `hostpath.ts`** (per RESEARCH §3.4, Option B):
1. Delete the `import { repoRoot } from "./repo-root.mjs"` line and the top-level `const
   WORKSPACE_ROOT = repoRoot(...)` call entirely.
2. Change the exported function that consumes `WORKSPACE_ROOT` (`hostPathCandidates`, per
   RESEARCH) to accept the root as a parameter: `hostPathCandidates(containerPath: string,
   opts: { workspaceRoot?: string } = {})`, falling back to `process.env.CONTAINER_WORKSPACE_PATH`
   alone when `workspaceRoot` is not supplied, and throwing a clearly-named error if neither is
   available — matching this project's "loud failure over silent wrong answer" ethos (RESEARCH
   §3.4 step 1, verbatim).
3. Add a header comment to `hostpath.ts` copying `install-resources.mjs`'s shape above nearly
   word-for-word, substituting "hostpath.ts" for the module name and "an unguarded `repoRoot()`
   call" for the specific mechanism — the pattern being copied is the STRUCTURE of the comment
   (why a dedicated-argument-taking design avoids a cycle) more than its exact prose.
4. Thread the parameter through the three known production callers (per RESEARCH §3.4 step 2):
   `install-resources.mjs`'s `hostLaunchInstructions(root)` (already has `root` in scope — pass
   it through), `containerpath.mjs` and `vice-proxy.mjs` (already import `repoRoot` directly —
   pass it through), and `vice-sync.mjs` (does not currently import `repo-root.mjs` — needs a new,
   non-cyclic import, since `vice-sync.mjs` is not itself a member of the cycle).
5. Update `containerpath.test.mjs`/`.ts` and `vice-proxy.test.mjs`/`.ts`'s own direct calls to
   `hostPath()` to pass the same `workspaceRoot` parameter (RESEARCH A2, flagged as not
   independently verified against every call site — check each one, don't assume uniformity).

**Then land Option A's call-site guard as a permanent regression test regardless** (RESEARCH §3.5):
reword `load-order.test.mjs`'s planned Part 3 to assert `ALLOWED_CYCLES_THROUGH_REPO_ROOT` is `[]`
AND that no cycle member calls `repoRoot()` unguarded — the exact test text is already given in
RESEARCH §3.3 and needs only the array literal updated to empty per this section's step 3 above.

## Shared Patterns

### Never-throw / two-layer try-catch on untrusted reads
**Source:** `vice-broker.mts`'s `readBrokerRecordMaybe` (typed) + `vice-broker-client.mjs`'s
`readJsonMaybe`-shaped helper (untyped original, parent PATTERNS.md lines 349-367).
**Apply to:** `vice-broker-client.ts`, `incident-record.ts`, `install-resources.ts`'s manifest
reader, `vice.ts`'s manifest/deny-list handling, any new `refresh-manifest.ts` read of an existing
manifest before deciding not to overwrite it on failure.
**Failure mode to reject in review:** collapsing the two try/catch layers into one, or replacing a
`return null` with a thrown `Error` "because TypeScript likes explicit errors" — this is a designed
degrade-gracefully path, not an oversight (RESEARCH §Security Domain names this explicitly under
Denial-of-Service).

### Atomic write (tmp → chmod 600 → content → rename)
**Source:** `vice-broker.mts` lines 94-98 (excerpt above).
**Apply to:** `incident-record.ts`'s `writeIncidentRecord`, `install-resources.ts`'s manifest
writer. **Flag, don't silently fix:** `refresh-manifest.mjs`'s current write is a bare
`writeFileSync(path, ...)` with no tmp/chmod/rename step — note this gap in the plan rather than
either silently tightening it (a behavior change beyond "port") or silently porting the weaker
version without comment.

### Repo-root-as-argument (breaks/avoids the TDZ cycle)
**Source:** `install-resources.mjs` header comment (verbatim above), now also the template for
`hostpath.ts`'s Option-B conversion.
**Apply to:** `hostpath.ts` (this phase, Slice 2) — the only file this phase touches that currently
violates the pattern.

### Extension-agnostic static-check regexes
**Source:** `load-order.test.mjs`'s own `(?:\.[cm]?[jt]s)?` suffix group.
**Apply to:** `vice-mcp-selector-docs.test.mjs`'s `importsHostpath()`, before any consumer renames.

### `type` import erasure is not automatically "safe" against the TDZ hazard
**Source:** parent `01.6-PATTERNS.md`'s own already-identified risk — `import type { repoRoot }
from "./repo-root.ts"` is fully erased at compile/strip time, so a static check must reject the
cyclic import regardless of the `type` keyword's presence. `load-order.test.mjs`'s Part 1 guard
(anchored to `import` + optional `type` modifier, per its own comment read this session) already
handles this correctly — preserve that anchoring exactly when the guard's file-name literal is
updated for the rename (see §Extension-Hardcoded Static Checks above); do not simplify the regex
while touching it.
