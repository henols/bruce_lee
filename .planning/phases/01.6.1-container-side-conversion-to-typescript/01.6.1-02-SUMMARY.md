## Accomplishments

- Broke the `repo-root.mjs` -> `install-resources.mjs` -> `hostpath.mjs` -> `repo-root.mjs` cycle structurally: `hostpath.mjs` now takes the workspace root as an optional `workspaceRoot` argument on every exported function, falling back to `CONTAINER_WORKSPACE_PATH` and throwing a named error only when neither is available (resolved lazily, so the mountinfo-fallback path is untouched).
- Threaded the root through all four production callers: `install-resources.mjs`'s `hostLaunchInstructions(root)`, `containerpath.mjs`'s `hostRootCandidates()` (its own `WORKSPACE_ROOT`), `vice-proxy.mjs`'s three `hostPath()` call sites, and `vice-sync.mjs`'s `screenshot()` (a new, lazy, function-body `repo-root` import — the exact fresh route the new guard now polices).
- Left `containerpath.test.mjs` and `vice-proxy.test.mjs` completely untouched — confirmed via `git diff --name-only HEAD` printing nothing for either file both before and after — proving the change is behaviour-preserving through the `CONTAINER_WORKSPACE_PATH` env-first fallback (RESEARCH's own live measurement).
- Emptied `ALLOWED_CYCLES_THROUGH_REPO_ROOT` to `[]` and landed a new Part 3 module-scope call-site guard in `load-order.test.mjs`, following a genuine RED (predicate undefined, both new tests failed with `ReferenceError`) then GREEN (predicate implemented, 6/6 pass) cycle.
- Proved, live, that both guards actually discriminate: in a scratch copy of the flat tree (outside the repo, never mutating the tracked tree), reintroducing the cycle failed the allowlist assertion, dropping the `from:` override on `containerpath.mjs`'s call failed the call-site assertion naming that file, and combining both regressions unguarded reproduced the exact `Cannot access 'HERE' before initialization` crash RESEARCH §3.2 first found.
- Full suite: 247 -> 249 (247 + 2, the two new Part 3 tests). Typecheck clean throughout every task.

## Task 3 — Verbatim Discriminating-Power Evidence

Per this plan's own `<output>` requirement: the guard was proven to discriminate, not merely shown to exist. All three regressions were applied to a scratch copy of the flat module tree outside the repository (`/tmp/.../scratchpad/01.6.1-02-task3-cycle-repro/`), one at a time, each restored before the next; the tracked tree's `git status --porcelain` was empty before, during, and after, and the scratch directory was deleted at the end.

**Baseline (healthy scratch copy, before any regression):** `load-order.test.mjs` run against the scratch tree reported 6/6 pass — matching the real tree exactly.

**Regression 1 (graph half — cycle reintroduced in scratch `hostpath.mjs`, WITH an explicit `from:` override):**

```
AssertionError [ERR_ASSERTION]: the set of cycles through repo-root.mjs changed -- expected exactly [], got [["hostpath.mjs","install-resources.mjs","repo-root.mjs"]]. A NEW cycle through repo-root.mjs must be justified by amending ALLOWED_CYCLES_THROUGH_REPO_ROOT in this test, not silently allowed through on the same luck that keeps today's recorded cycle from crashing (a lazy call site, not a structural guarantee). Widening this allowlist to TypeScript sources, and deciding whether to break the cycle outright, belong to Phase 01.6.1 criterion B and are not settled here.
```

Result: 5 pass, 1 fail (the cycle assertion) — exactly the expected FAIL. `hostpath.mjs` restored to healthy before the next regression.

**Regression 2 (call-site half — scratch `containerpath.mjs`'s module-scope call loses its `from:` override; `hostpath.mjs` healthy):**

```
AssertionError [ERR_ASSERTION]: containerpath.mjs: module-scope call `const WORKSPACE_ROOT = repoRoot();` does not pass an explicit `from:` override. An unguarded module-scope repoRoot() call falls through to repo-root.mjs's own still-possibly-uninitialised `HERE` binding -- 01.6.1-RESEARCH.md §3.2 reproduced this LIVE, crashing with exactly "Cannot access 'HERE' before initialization". The cycle allowlist above being empty does not make this check redundant: 01.6.1-02's own cycle-break (Task 1) gave vice-sync.mjs a repo-root import it did not have before, which is a fresh route to the same hazard this guard exists to police.
```

Result: 5 pass, 1 fail (the call-site assertion), naming `containerpath.mjs` exactly. `containerpath.mjs` restored to healthy before the next regression.

**Regression 3 (the crash itself — both regressions combined in scratch `hostpath.mjs`, with NO `from:` override this time; `containerpath.mjs` healthy):**

```
CRASH: ReferenceError: Cannot access 'HERE' before initialization
```

Produced by dynamically importing the scratch copy of `repo-root.mjs` in a fresh Node process (`import('.../repo-root.mjs')`), which cascades through `install-resources.mjs` -> the regressed `hostpath.mjs`, whose bare `repoRoot()` call reads `repo-root.mjs`'s own not-yet-initialized `HERE` default parameter mid-cycle — the identical crash text 01.6-RESEARCH.md §E and 01.6.1-RESEARCH.md §3.2 both reproduced against the pre-Plan-02 tree.

**After all three:** the real, tracked `load-order.test.mjs` reported 6/6 against the real tree; `git status --porcelain` printed nothing; the scratch directory was deleted; full suite 249/249, typecheck exit 0.
