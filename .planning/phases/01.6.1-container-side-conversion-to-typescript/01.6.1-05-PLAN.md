<objective>
Convert RESEARCH §2's Slices 5 and 6 — the broker-protocol client and the transport library
— and deliver this phase's half of **criterion C7**.

Purpose: C7 in full reads *"the duplicated request-id regex is deleted, not merely kept in
sync."* Two copies exist today, and they are duplicated **across the container/host language
boundary**, not within the container: one is a JavaScript regular expression in the broker
client, the other is a shell pattern inside `resources/vice-broker.sh`. The shell copy does
not retire until Phase 01.6.2 folds that script into the one-process broker. **This phase's
contribution to C7 is therefore not a deletion** — it is making the container-side copy a
real, typed, named export so 01.6.2's in-process broker can import the one definition rather
than re-state the rule a third time in yet another shape.

The parity test that stops the two copies drifting lives in `vice-broker.test.mjs`, which is
**explicitly out of this phase's scope** — its methodology changes when the bash daemon it
spawns disappears, and converting its syntax before its methodology would produce TypeScript
that still spawns a daemon 01.6.2 is about to delete. It stays `.mjs`. But it imports the
module this plan renames, so it needs **exactly one line changed and nothing else**.

Output: four `.ts` files, one line touched in an out-of-scope file, and the specifiers in
every consumer of both modules repointed.

**Inherited decisions:** none of D-01…D-06 is owned here. D-05 already deleted the vice
module's CLI in Phase 01.6, which is why the file this plan converts is 555 lines of library
rather than 818 lines of library plus CLI — do not look for a command-line block, and do not
add one.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host broker's concurrently-written state files → the broker client's readers | The broker writes grant/request/lease files while the client reads them; a half-written record is routine, not exceptional. |
| host MCP server's advertised tool list → the vice library's discovery filter | The deny-list is applied at this choke point and again at the proxy's read time. Losing either application re-exposes a tool this project has three layers of defence against. |
| container/host language boundary | The request-id rule exists twice, in two languages. This phase makes the container copy importable; 01.6.2 deletes the shell copy. |
