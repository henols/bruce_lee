## Decisions Made

- **`vice-proxy.test.mjs`'s network-call scan widened, file itself untouched.** The check is out of this phase's scope by RESEARCH's own ownership table (Slice 9, its own later plan), but its file-enumeration predicate was hardcoded to `.mjs` and broke the moment `vice-probe.mjs` renamed. Widening only the predicate (not renaming the file, not touching its other content) keeps the deferred-plan boundary intact while keeping the suite green now.
- **`@ts-expect-error` over a `declare module` shim for `host-scripts.test.ts`'s untyped import.** `install-resources.mjs` stays `.mjs` this wave; a `declare module "./install-resources.mjs" { ... }` ambient shim was tried first and rejected by `tsc` itself (TS2665 -- a relative specifier that resolves to a real file is not eligible for shorthand ambient augmentation). The scoped `@ts-expect-error` is self-cancelling: the moment Plan 03 converts `install-resources.mjs` to `.ts`, this directive itself becomes a loud `TS2578` ("unused directive") error, which is the correct signal to remove it.
- **`npm ci` run in `.claude/mcp/vice/` before any test/typecheck.** The worktree checkout had no `node_modules` at all (gitignored, never installed here). `package.json`/`package-lock.json` already pin `typescript@7.0.2`/`@types/node@24.13.3`, human-approved in Phase 01.6 plan 01 -- this is environment setup reproducing an already-approved lockfile, not a new package-legitimacy decision.
