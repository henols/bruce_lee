### Auto-fixed Issues

**1. [Rule 3 - Blocking] `TEST_FILE_PATH`'s own self-reference broke after the rename**
- **Found during:** Task 1, fixing `vice-proxy.test.ts`'s typecheck errors
- **Issue:** `const TEST_FILE_PATH = join(HERE, "vice-proxy.test.mjs");` still named the pre-rename filename. This is read via `readFileSync(TEST_FILE_PATH, "utf8")` inside a self-referential structural test (every `SEAM_HAZARDS` id must be named "by at least one test in vice-proxy.test.mjs") -- would have thrown `ENOENT` at test run time now that the file no longer exists under that name.
- **Fix:** Changed the one line to `"vice-proxy.test.ts"`, matching the `PROXY_PATH` precedent Plan 07 already established for this exact file.
- **Files modified:** `.claude/mcp/vice/vice-proxy.test.ts`
- **Verification:** `node --test vice-proxy.test.ts` -- the structural test that reads `TEST_FILE_PATH` passes; 85/85 overall.
- **Committed in:** `ee34423` (Task 1's commit)

**2. [Rule 2 - Missing Critical] Five `.find()` results flowed into `join()`/`readFileSync()` with no existence check**
- **Found during:** Task 1, fixing TypeScript's `string | undefined` errors
- **Issue:** `readdirSync(dir).find((f) => f.endsWith(".md"))` returns `string | undefined`; five call sites passed the result straight into `join()`/`readFileSync()` with no check, which is both a latent runtime hazard (a silent `undefined` filename) and, mechanically, what TypeScript's strict mode flagged.
- **Fix:** Added `assert.ok(incidentFile, "an incident record must have been written")` (four sites) / `assert.ok(secondFile, "a second, distinct incident file must exist")` (one site) immediately before use, matching the pattern one sibling test in the same file already used. No existing assertion was touched; each addition is a new, independent check.
- **Files modified:** `.claude/mcp/vice/vice-proxy.test.ts`
- **Verification:** `npx tsc --noEmit -p tsconfig.json` exits 0; `node --test vice-proxy.test.ts` -- all five affected tests still pass, 85/85 overall.
- **Committed in:** `ee34423` (Task 1's commit)

**3. [Rule 1 - Bug] `load-order.test.ts`'s cycle-allowlist test had gone vacuous after Plan 03's rename**
- **Found during:** Task 2 step B, the mandatory end-of-phase re-proof of the criterion-B guards
- **Issue:** `findCyclesThroughNode(graph, "repo-root.mjs")` used a literal string as the DFS start node. Plan 03 renamed `repo-root.mjs` to `repo-root.ts`, so this literal named a node that no longer existed in the import graph -- the function returned `[]` unconditionally, and since `ALLOWED_CYCLES_THROUGH_REPO_ROOT` is also `[]`, the assertion passed on an empty-vs-empty match that gave no signal the check had stopped running at all. Confirmed live: injecting Plan 02's own guarded-cycle regression into a scratch copy did NOT fail this test before the fix.
- **Fix:** Changed the argument to `resolveModuleByStem("repo-root")`, matching the by-stem idiom already established two tests earlier in the same file (Plan 03's own precedent, which this specific literal had been missed by).
- **Files modified:** `.claude/mcp/vice/load-order.test.ts`
- **Verification:** Re-injected the identical regression against the fix: correctly fails, quoting `the set of cycles through repo-root.mjs changed -- expected exactly [], got [["hostpath.ts","install-resources.ts","repo-root.ts"]]`. Real tree: `node --test load-order.test.ts` 7/7 pass; full suite 275/270/5/0; typecheck exit 0.
- **Committed in:** `e63320f` (Task 2's commit)
