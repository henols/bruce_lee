Two disciplines are load-bearing and must come through unchanged:

  - **The atomic write.** Wherever this module writes a record, the sequence is: create an
    empty tmp sibling, restrict its mode before any content lands, write the content, then
    rename over the destination. Do not collapse it to a single write because the types
    would be simpler. The ordering exists so a reader can never observe a partially-written
    record and can never observe a world-readable one.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted on-disk incident record → reader | A corrupt or half-written record must degrade, never crash the proxy that is mid-way through capturing evidence about a failing emulator. |
| incident record → filesystem | Records are written into the workspace; a world-readable temp file or a partially-written record observable by a concurrent reader are both real outcomes of getting the write ordering wrong. |
| host path string → container path string | `containerpath` is the inverse translation seam; a hardcoded absolute host path written into its source would make it silently wrong on any other machine. |
