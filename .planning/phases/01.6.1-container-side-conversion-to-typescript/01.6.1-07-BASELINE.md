**One difference found, not silently passed over.** `isPlainObject` is a new top-level
function -- the type-narrowing predicate this plan's own typing guidance requires ("Narrow
every value that arrives from stdin or from a parsed host reply through a type predicate before
touching its fields... Casting a parsed message straight to a request interface would let a
malformed message through with no runtime check"), copied verbatim in shape from
`vice-broker.mts`'s own `isPlainObject()` and from the same-named predicate every other
converted file in this phase already introduced (`vice-broker-client.ts`, `vice.ts`,
`install-resources.ts`). It replaces what the untyped original did ad hoc and inconsistently at
each call site (`params && params.protocolVersion`, `result && result.hex`, etc.) with one
named, reused check. It is called at every JSON-RPC/host-reply boundary the file has
(`handleInitialize`, `readManifestTools`, `handleToolsList`, `bytesFromMemoryReadResult`,
`gatherCheckpointTrapEvidence`, `cyclesFromStopwatchResult`, `pathArgsFor`, `handleMessage`,
`handleToolsCall`) and returns a boolean with no side effect and no behavior change of its own
-- it narrows before a read, it does not change what is read. **Resolution: kept.** The
alternative (inlining the same three-clause check at every one of those ~10 call sites to avoid
adding a name) would have made the port *less* faithful to this phase's own established idiom
and strictly worse to read, for the sake of a literal headcount rather than the invariant the
headcount exists to protect (no logic silently dropped, renamed, or duplicated with drift). No
other name was added, removed, or renamed: all 93 baseline names are present, unchanged, in the
post-rename file.

**A related, load-bearing note for Plan 08:** four declarations were kept as textually
UNANNOTATED as before -- `handleRecycle`, `runCycleBracket`, `DIAGNOSE_VERDICTS`,
`SEAM_HAZARDS`, and `CHECKPOINT_ARMING_TOOLS` -- because `vice-proxy.test.mjs`'s own structural
tests scan the source for their EXACT pre-conversion declaration text (e.g.
`src.indexOf("async function handleRecycle(args)")`,
`src.match(/^async function runCycleBracket\(\)\s*\{/gm)`,
`src.match(/const DIAGNOSE_VERDICTS = Object\.freeze\(\[([^\]]+)\]\)/)`,
`src.indexOf("const SEAM_HAZARDS = [")`, and `extractSetLiteral()`'s
`` `const ${constName} = new Set(\[([^\]]*)\])` `` pattern for `CHECKPOINT_ARMING_TOOLS`). Adding
an inline parameter or return-type annotation to any of these breaks the oracle test LOUDLY
(confirmed live, this session -- see RE-FINDINGS.md). Each is still fully typed: `args` on
`handleRecycle` is typed via a contextually-typed `const handleRecycle: (args: Record<string,
unknown>) => Promise<ToolCallResult> = async function handleRecycle(args) {` (the function
EXPRESSION's parameter is contextually typed from the variable's own annotation, with zero text
change to the substring the oracle scans for); `runCycleBracket`'s return type is left to plain
inference (its body's own shape already gives it a concrete, checked type); `DIAGNOSE_VERDICTS`
and `CHECKPOINT_ARMING_TOOLS` are left unannotated `const`s (their `Object.freeze([...])` /
`new Set([...])` initializers already infer a concrete, checked type); `SEAM_HAZARDS`'s single
production entry is cast `as SeamHazardEntry` at the object-literal level (inside the array,
after the entry's own closing brace) rather than annotating the array declaration itself, so the
array's own inferred element type becomes `SeamHazardEntry` without touching the declaration
line the oracle's `indexOf("const SEAM_HAZARDS = [")` anchors to.
