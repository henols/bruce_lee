## Two decisions this plan takes, recorded rather than made silently

**Decision 1 — the manifest write is tightened to the atomic idiom, deliberately.**
`refresh-manifest`'s current write is a bare single-shot write with no tmp sibling, no mode
restriction and no rename. PATTERNS flags this as a real gap and instructs the plan to
*"flag it rather than either silently tightening it (a behaviour change beyond 'port') or
silently porting the weaker version without comment."* Flagged, and closed — for a specific
reason: the module's **own doc comment already promises** that *"a partial or empty manifest
is never written over a good one on failure."* Today that promise holds only for the
handshake-failure path; a crash or a full disk mid-write breaks it, and the file the proxy's
offline tools-list handler reads is the casualty. The atomic idiom is already in this repo
(`vice-broker.mts`), so closing the gap costs one already-written shape and makes an existing
documented guarantee true. Rated `reversible`. Surfaced for the developer at the end-of-phase
human check in Plan 08.

**Decision 2 — `refresh-manifest` gains an exported entry function and an entry-point guard.**
It currently calls its main function at module load, which makes it untestable without
spawning a process. PATTERNS names `vice-broker.mts`'s exported-`main`-plus-guard shape as
the template for exactly this file. This is the minimum structural change that makes first
coverage possible, and it is the shape the one authored-TypeScript precedent in the repo
already uses. Rated `reversible`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host MCP handshake → the manifest refresher | An operator-run CLI trusts whatever the host advertises; the deny-list filter it inherits from the transport library is what keeps a denied tool out of the snapshot the proxy later serves offline. |
| manifest file → the proxy's offline tools-list handler | The proxy reads this file with no host I/O. A truncated or clobbered manifest is a tool surface that is wrong for the whole of a session. |
| test process → the emulator | Forbidden. `mcp__vice__*` is the only permitted route, and no test may open its own connection or discover a broker port. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01.6.1-14 | Tampering | the manifest write | high | mitigate | Task 1 replaces the single-shot write with the tmp-sibling → restrict-mode → content → rename sequence, and asserts no leftover temporary sibling and a restricted mode. A partial manifest is a wrong tool surface for a whole session, and the file's own doc comment already claimed this could not happen. |
| T-01.6.1-11 | Information Disclosure | the deny-list filter inherited by the manifest snapshot | high | mitigate | Task 1 changes nothing about where the filter is applied; the transport library still strips denied names before returning, and the proxy applies the same filter again at read time. Acceptance drives the entry function against a stub whose advertised tool list is compared to what lands on disk, so a lost filter would surface as a content mismatch. |
| T-01.6.1-15 | Spoofing | a fabricated stub standing in for the emulator | high | mitigate | Task 2 forbids building a stub for the checkpoint primitives and asserts the absence of a server in that test file. A stub that answers plausibly would convert a recorded gap into an unrecorded false pass, in the one area this project grades most strictly. The gap is recorded as machine-visible todos instead. |
| T-01.6.1-16 | Denial of Service | a test leaving a non-zero exit code or a redirected environment variable set | medium | mitigate | Task 1's helper restores both in a `finally` block, copied from the existing template. | T-01.6.1-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this phase. See Plan 01's register. |
