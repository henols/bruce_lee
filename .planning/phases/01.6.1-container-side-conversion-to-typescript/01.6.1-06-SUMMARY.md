## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `withTempManifestPath()`'s `finally` block restored the redirected env var before the async callback's real work had finished**
- **Found during:** Task 1, while running the newly-converted `refresh-manifest.test.ts` for the first time -- 6 of 7 tests failed with `ENOENT` reading the tmpdir path, and console output showed `main()` writing to the REAL `tools-manifest.json` instead of the redirected tmpdir path.
- **Issue:** The test helper's outer function was not `async`, and its `try { return fn(path); } finally { restore env var }` ran the `finally` block the instant `fn(path)` returned a `Promise` object -- not once that promise settled. `VICE_TOOLS_MANIFEST` was deleted/restored before `main()`'s own `await serverInfo()` resolved, so `manifestPath()` read the env var late, found it already gone, and fell through to the real default path -- briefly overwriting the tracked, committed `tools-manifest.json` with test fixture data.
- **Fix:** Made the helper `async` and changed `return fn(path)` to `return await fn(path)`, so the `finally` block genuinely waits for the inner async work.
- **Files modified:** `.claude/mcp/vice/refresh-manifest.test.ts`. The real `tools-manifest.json` was restored via `git checkout -- .claude/mcp/vice/tools-manifest.json` before staging any commit -- confirmed clean via `git diff` immediately after.
- **Verification:** Re-ran the full test file: 7/7 pass, and the dedicated "real tools-manifest.json is untouched" snapshot test (added specifically to catch a regression of this exact class) passes. Logged to `.planning/RE-FINDINGS.md` at discovery per CLAUDE.md's rule.
- **Committed in:** `e3fc740` (Task 1's GREEN commit)

**2. [Rule 1 - Bug] `vice-sync.test.ts`'s own explanatory comment defeated its acceptance criterion's literal grep check**
- **Found during:** Task 2, while verifying the plan's own acceptance criterion `grep -rn "createServer" .claude/mcp/vice/vice-sync.test.ts` returns nothing -- the first draft's comment explaining the absence of a stub server literally contained the string `"createServer"` (quoting it to say it wasn't there), which the grep matched anyway.
- **Issue:** A self-referential comment ("no stub VICE server exists ... grep for `createServer` finds nothing") is true in spirit but defeats a literal string-match acceptance check the moment it names the very string being checked for.
- **Fix:** Reworded the comment to describe the absence without naming the literal function ("No stub HTTP listener of any kind exists anywhere in this file").
- **Files modified:** `.claude/mcp/vice/vice-sync.test.ts`
- **Verification:** `grep -rn "createServer" .claude/mcp/vice/vice-sync.test.ts` returns nothing; full suite re-run confirms 275/275 accounted for (270 pass + 5 todo), 0 fail.
- **Committed in:** `0010585` (Task 2's GREEN commit)
