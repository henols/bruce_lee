**Recommended order: leaves first (bottom-up), hub last.** `vice-proxy.mjs` imports from 7 of the other 10 source files; converting it before its dependencies exist as `.ts` would mean it imports a mix of `.mjs` and `.ts` siblings mid-conversion (which Node's native resolution handles fine at runtime, since specifiers are extension-exact either way — but it maximizes the number of files touched by a single commit's import-specifier updates, which is exactly the kind of avoidable churn the "suite green continuously" criterion exists to minimize). Converting leaves first means each slice's "update every consumer's import specifier" step touches only files already converted in an earlier slice, never a file still to come.

### The mechanical rule every slice follows

Node's native module resolution matches import specifiers by **exact extension** — `import { x } from "./foo.mjs"` and `import { x } from "./foo.ts"` are different specifiers that happen to resolve to files with the same basename. **Renaming a file from `.mjs` to `.ts` requires updating every consumer's import specifier in the same commit**, or the consumer breaks immediately (module not found) rather than silently — this is a loud failure, not a hazard, but it means "convert `foo.mjs`" is never a one-file change; it is "convert `foo.mjs` to `foo.ts`, and update every file that imports `./foo.mjs`, including test files that stay `.mjs`." §5 gives a concrete example (the request-id-pattern parity test inside the out-of-scope `vice-broker.test.mjs`, which will need a one-line specifier update even though that file itself never converts in this phase).

### 3.2 What actually keeps the cycle from crashing today — and it is NOT what the load-order.test.mjs comment implies

`load-order.test.mjs`'s own header comment (lines 1–15) frames the survival story entirely around `hostPath()`'s laziness. That is true but incomplete: `hostpath.mjs` **also** calls `repoRoot({ from: HERE })` at its own top level (line 47, `const WORKSPACE_ROOT = repoRoot({ from: HERE })`) — a **top-level, synchronous** call to a function from the very module that is mid-cycle. This call does not crash **only because it passes `HERE` explicitly** (`hostpath.mjs`'s own `HERE`, already initialized by that point in its own evaluation) — so `repoRoot`'s default parameter (`from = HERE`, referring to `repo-root.mjs`'s own, still-uninitialized `HERE`) is never evaluated. `repoRoot` itself (a function declaration) is always callable mid-cycle by ECMAScript's module-linking semantics; the hazard is specifically about what its *body* reads if the call omits the override.

**This was proven live, not reasoned about.** In a scratch copy of the three cycle files, changing exactly one line —

```diff
- const WORKSPACE_ROOT = repoRoot({ from: HERE });
+ const WORKSPACE_ROOT = repoRoot();
```

— and then `import("./repo-root.mjs")` produces:

```
CRASH: Cannot access 'HERE' before initialization
```

**The real `load-order.test.mjs`, run against this exact regressed tree, reports 4/4 tests still passing.** Neither the direct-import guard (Part 1 — it only inspects `install-resources.mjs`'s own text) nor the cycle-allowlist (Part 2 — it only tracks *which* modules import *which*, not how the imported bindings are called) notices anything changed, because nothing about the import graph changed. This is precisely the gap the phase description names: **the check is import-graph-shaped; the hazard is call-site-shaped.** **Evidence: live reproduction and live test run, this session, in `/tmp/.../scratchpad/cycle-repro/`. Confidence: HIGH.**

### 3.3 Option A — Widen: a call-site guard, tested and working

Add a fourth check to `load-order.test.mjs` asserting every `repoRoot(` call site in a cycle member's source passes an explicit `from:` key. Tested live against both the real file and the regressed copy:

```javascript
// New Part 3 for load-order.test.mjs: every repoRoot(...) call inside a
// module that participates in the repo-root cycle must pass an explicit
// `from:` override, so it can never fall through to repo-root.mjs's own
// (possibly still-TDZ'd) HERE. This is the call-site half of the hazard
// the cycle-allowlist above does not see, because the import graph itself
// never changes when this regression is introduced.
const CYCLE_MEMBERS_CALLING_REPO_ROOT = ["hostpath.mjs"]; // extend if a future cycle member also calls repoRoot()

test("call-site guard: every repoRoot() call inside a cycle member passes an explicit `from:`", () => {
  for (const file of CYCLE_MEMBERS_CALLING_REPO_ROOT) {
    const src = readFileSync(join(HERE, file), "utf8");
    const totalCalls = (src.match(/\brepoRoot\(/g) || []).length;
    const guardedCalls = (src.match(/\brepoRoot\(\s*\{[^)]*?\bfrom\s*:/g) || []).length;
    assert.equal(
      guardedCalls,
      totalCalls,
      `${file} calls repoRoot() ${totalCalls} time(s) but only ${guardedCalls} pass an explicit ` +
        "'from:' override -- an unguarded call defaults to repo-root.mjs's own HERE, which is " +
        "exactly the TDZ hazard this cycle survives only by avoiding (01.6.1-RESEARCH.md §3)."
    );
  }
});
```

Live-verified against the two states:

| Tree state | `totalCalls` | `guardedCalls` | Test result |
|---|---|---|---|
| Real `hostpath.mjs` today | 1 | 1 | ✔ pass |
| Regressed (`from: HERE` removed) | 1 | 0 | ✘ fails — exactly the regression from §3.2 |

**Cost:** a conservative check — it forbids *any* unguarded `repoRoot()` call anywhere in a listed cycle member, even one that would in fact be safe (e.g., inside a function called lazily after the cycle has fully resolved). Given the file's own established convention is "always pass `from` explicitly" (the existing call already does this, and there is no functional reason not to), this cost is close to zero in practice. **Effort: one new test, ~15 lines, no production code touched. Confidence: HIGH — tested against both the passing and failing case live.**

### 3.4 Option B — Break the cycle: remove `hostpath.mjs`'s dependency on `repo-root.mjs` entirely

`hostpath.mjs` only needs `repoRoot()` to compute `WORKSPACE_ROOT` (used to build `CONTAINER_WS` for `hostPathCandidates()`'s `HOST_WORKSPACE_PATH`-relative branch). This is exactly the shape `install-resources.mjs` already solved for itself (D-3's own stated philosophy: "this module takes the repo root as an ARGUMENT and imports NOTHING from repo-root.mjs"). Applying the identical pattern to `hostpath.mjs`:

1. `hostpath.mjs`: delete `import { repoRoot } from "./repo-root.mjs"` and the top-level `const WORKSPACE_ROOT = repoRoot({ from: HERE })`. Change `hostPathCandidates(containerPath, { workspaceRoot } = {})` to accept the root as a parameter, falling back to `process.env.CONTAINER_WORKSPACE_PATH` alone when not supplied (matching the module's own existing environment-driven design) and throwing a clear, named error if neither is available — consistent with this project's established "loud failure over silent wrong answer" ethos.
2. Update the (small) caller set. All are already known and traced by `vice-mcp-selector-docs.test.mjs`'s own `HOSTPATH_ALLOW_LIST` (four production consumers): `install-resources.mjs`'s `hostLaunchInstructions(root)` **already has `root` in scope** — trivial, pass it through. `containerpath.mjs` and `vice-proxy.mjs` **already import `repoRoot` directly** — trivial, pass it through. `vice-sync.mjs` does not currently import `repo-root.mjs` — this is the one caller needing a new (non-cyclic — `vice-sync.mjs` is not itself imported by any cycle member) import line.
3. Result: `hostpath.mjs` no longer imports `repo-root.mjs` at all. The three-module cycle collapses to **zero** cycles through `repo-root.mjs`; `ALLOWED_CYCLES_THROUGH_REPO_ROOT` becomes `[]`. The entire hazard class — not just this one call site — is eliminated structurally, matching the project's own already-stated preference (the header comment's "the cycle is avoided STRUCTURALLY" framing) rather than defended by an ongoing test.

**Cost:** touches 4–5 files instead of 0 production files (Option A adds a test only); a handful of call sites in test files (`containerpath.test.mjs`, `vice-proxy.test.mjs` both call `hostPath()` directly today and would need the same `workspaceRoot` parameter threaded through). **Effort: small but real, on the order of the other mechanical port work this phase already does — and `hostpath.mjs` is already being edited this phase regardless (it converts to TypeScript in Slice 2), so the marginal cost of adding one parameter while already touching the file's signature is genuinely low.**

### 3.5 Recommendation

**Do both, in this order: Option B first (break the cycle while `hostpath.mjs` is open for conversion anyway, in Slice 2), Option A's guard second as a permanent regression test even after the cycle is gone** — reworded slightly to assert the ALLOWED_CYCLES list is empty AND that no cycle member calls `repoRoot()` unguarded, so a future re-introduction of the dependency is caught by both the graph check and the call-site check simultaneously. **Confidence: MEDIUM-HIGH.** Reasoning: Option B is cheap specifically *because* this phase already opens `hostpath.mjs` for editing (zero marginal touch-cost argument does not apply to a hypothetical future phase, which is why "now" is the right time); Option A alone is real but leaves a hazard class alive, defended only by vigilance; Option B alone without Option A's guard leaves nothing stopping a *future* contributor from reintroducing the exact same shape by a different route (e.g., `vice-sync.mjs` growing a new top-level call after picking up the `repoRoot` import Option B adds to it). The two are complementary, not alternatives, and doing both costs little beyond what §2's Slice 2 already touches. **If the developer prefers minimal-diff conservatism, Option A alone is a completely defensible fallback** — it is tested, it works, and it costs one new test file section with zero production-code risk.

## Architecture Patterns

Inherited from `01.6-PATTERNS.md` without change for the mechanical-port files (§File Classification table there is still accurate for containerpath/hostpath/incident-record/refresh-manifest/repo-root/vice-broker-client/vice-probe/vice-sync/vice.mjs — read it directly rather than re-deriving here). Two patterns are genuinely new, both surfaced by this delta pass:

### Pattern: Extension-hardcoded static checks go silently vacuous across a rename

`load-order.test.mjs`'s direct guard (`IMPORT_REPO_ROOT_PATTERN`'s target-file read) is hardcoded: `readFileSync(join(HERE, "install-resources.mjs"), "utf8")`. When this file becomes `install-resources.ts` in §2's Slice 2, this line must be updated in the same commit, or the test either throws (file not found — loud, safe) or, worse, if both files transiently coexist mid-slice, silently checks the STALE `.mjs` copy while the real, converted `.ts` file goes unchecked. **The pattern's own extraction regex (`IMPORT_REPO_ROOT_PATTERN` itself) is already extension-agnostic** (`(?:\.[cm]?[jt]s)?`) — only the hardcoded filename read needs updating, not the pattern.

A second, separately-discovered instance of the identical class: `vice-mcp-selector-docs.test.mjs`'s `importsHostpath()` (the criterion-9 caller-side closure check) matches specifiers via `specifier === "./hostpath.mjs" || specifier.endsWith("/hostpath.mjs")` — **hardcoded to `.mjs`, not extension-agnostic at all.** Once `hostpath.mjs` and its consumers convert to `.ts` in §2 Slices 2–6, every real consumer's specifier becomes `"./hostpath.ts"`, which this check does not match — the test would then report **zero consumers**, passing vacuously while enforcing nothing, which is precisely the failure class this file's own header comment (line 273–274) already names as the thing to avoid. **This must be widened (e.g., a shared `[cm]?[jt]s` suffix check, mirroring `load-order.test.mjs`'s own already-correct pattern) as part of §2's Slice 0 or Slice 2 — before, not after, any consumer actually renames**, so the check never has a window where it silently stops working. **Evidence: direct read of both check implementations, live this session. Confidence: HIGH.**

**Warning sign for any future static check in this tree:** a hardcoded `.mjs` string literal anywhere in a test asserting something about *this specific module tree*, since every file in it is mid-migration to `.ts` this phase.

### Pattern: A cycle allowlist recorded by filename must be updated in the same commit as the rename it allowlists

`ALLOWED_CYCLES_THROUGH_REPO_ROOT = [["hostpath.mjs", "install-resources.mjs", "repo-root.mjs"]]` records basenames with their current extension. If §3's Option B is taken (breaking the cycle), this becomes `[]` in the same commit `hostpath.mjs`'s import is removed. If Option A alone is taken (cycle survives, guarded), this array's three entries must be renamed to `.ts` in the same commit as Slice 2's conversion — `listModuleFiles()` already re-derives the actual graph from whatever extensions exist on disk, so the array is the only hand-maintained piece, and it is deliberately hand-maintained (per the file's own comment) so a *new*, unreviewed cycle cannot slip through silently.
